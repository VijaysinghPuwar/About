36 Frequently Asked Questions

Why does spoonstill need FFmpeg? All decoding, filtering, encoding, muxing and joining is done by FFmpeg. spoonstill decides what to ask for and checks the result.

Why isn't FFmpeg bundled? The FFmpeg most people install with Homebrew is a GPL build that cannot be redistributed with a proprietary product. Bundling needs a separate LGPL build, which is milestone M5 work (D-062). Meanwhile still doctor --install and the window's Install button run the platform package manager.

Why Rust? The documents do not argue the language choice at length; what the code shows is the benefits it uses: a compiler that enforces crate boundaries and thread safety (Send/Sync), no garbage-collection pauses during long renders, unsafe forbidden for the project's own code, small native binaries for macOS and Windows, and Tauri for the window. (Inference from the code; not a recorded decision.)

Why multiple crates? To make boundaries the compiler enforces: a pure core with no I/O, one process boundary, logic shared by both surfaces (Chapter 4).

Why both a CLI and a desktop app? The CLI is the complete, scriptable, testable control surface; the window is for people who prefer clicking.

Does the GUI duplicate CLI logic? No. Both call the same spoonstill_app functions. The window translates clicks into calls and results into views; a contract test checks the seam.

Why does narration determine scene duration? Because the scene should last exactly as long as what is said over it. Duration is measured from the normalized audio and rounded up to whole frames, so speech is never cut (D-021, D-022).

Why use software encoding by default? libx264 gives the same pixels on every machine (good for caching and comparison) and better quality on slow gradients; measured hardware speed-ups were 1.2x to 1.7x. Hardware is available with --encoder auto.

What happens if narration is longer than expected? The scene simply gets longer; nothing is trimmed. Only a scene over one hour is refused, and a text that could not fit in an hour of speech is refused before it is spoken.

What happens if FFmpeg crashes? The scene fails with MediaError::Exit and the tail of FFmpeg's stderr; its temporary file is deleted; other scenes continue and every failure is reported together; finished segments stay cached for the next run.

Can spoonstill process hundreds of scenes? Yes; 500 is the design point. The project measured 500 scenes cold in about 2.5 minutes at 1080p on the development Mac, and real runs of 431 scenes (D-154, D-195).

Why forbid unsafe Rust? So the project's own code cannot contain memory-unsafe operations. It does not cover dependencies or FFmpeg (Chapter 22).

Where are temporary files stored? Beside their final destinations, with hidden .name.partial-<pid>-<n>.ext names, so the final rename is atomic on the same filesystem.

Can it overwrite my original photos? No. Files are copied in, never moved; ingest never overwrites; removed scenes go to removed/; the renderer never writes your inputs or project.yaml. It will replace an existing output film, but only after the new one passes every check.

Does TTS require the internet? Yes, speaking a new line does. Cached lines, recordings and silent scenes do not; a fully cached project renders offline.

How is Windows different from macOS? Where tools are found, path prefixes, quoting, console windows, file-name rules, the title bar, drag coordinates, and the hardware encoders available (Chapter 24).

Is there a database? No. Planned state.db was never built; the content-addressed cache already provides resume (D-154).

What is removed/? Where still remove and picture replacement put files. spoonstill never deletes your media.
