About This Book

This book teaches one codebase: spoonstill, the batch renderer in the repository https://github.com/VijaysinghPuwar/spoonstill. It is written for a reader who can program but who may be new to Rust, to FFmpeg, to video, or to the engineering habits this project uses. Each topic starts in plain English, then goes deeper, then points at the exact file where the behaviour lives.

How the repository was synchronised

The local clone at ~/Desktop/Projects/vidio was on master at 0dd74eb (v0.1.18), two commits behind origin/master. It also held uncommitted edits to README.md, decisions.md, arrange.rs and picture.rs, and the two incoming commits also changed README.md and decisions.md. A fast-forward pull would therefore have refused to run, and any stash, reset or merge would have put that in-progress work at risk. So nothing in the working tree was touched. Instead the newest remote state was checked out into a separate, temporary git worktree (git worktree add --detach <scratch>/repo origin/master), and everything in this book was read, built, tested and run there. Appendix A gives the full record.

How to read the evidence labels

The project's own documents are very detailed, but documents drift. This book treats the current source code and runtime behaviour as the final authority. Where it matters, a claim carries one of these labels:

  • Verified from source: read in the code at the commit above.
  • Verified by test: a named test asserts it, and the test suite passed on the analysis machine.
  • Verified by runtime experiment: a command was actually run for this book and its output inspected.
  • Documented intention: a design document says it; the code may not yet do it.
  • Historical decision: recorded in decisions.md; may have been amended later.
  • Inference: reasoning from the evidence, not directly shown.
  • Not independently verified: reported elsewhere and not re-checked here.

Verified by runtime experiment. A six-scene fixture project was rendered twice on the analysis machine. The first run encoded six segments; the second reused all six and finished in under a second.

Docs and code disagree. Boxes like this mark a place where a document says one thing and the code does another. The code wins.

How the book is organised

  • Part I, The Product explains what spoonstill is for and teaches the video and audio vocabulary you need.
  • Part II, Architecture walks through the seven components one at a time.
  • Part III, How It Works traces real operations end to end, including the long chapter "What Happens When I Press Render?".
  • Part IV, Engineering covers Rust concepts, errors, security, performance, platforms, tests, CI and releases, dependencies, decisions and tradeoffs.
  • Part V, Working With the Code is practical: debugging, safe modification, limitations, a file map and a reading order.
  • Part VI, Study Aids has the glossary, the FAQ, a 30-question knowledge check, and a 15-video curriculum.
  • The appendices record how this report was verified and give the exercise answers.

A note on style: this book uses no em dashes anywhere, including inside quoted code comments, where the repository's own long dashes have been replaced with a comma or a hyphen. Code excerpts are otherwise quoted as they appear, sometimes shortened with // ....
