7 spoonstill-tts: Turning Text Into Speech

7.1 Why it exists

When a scene has a written line instead of a recording, something must speak it. spoonstill-tts defines the contract for a speech provider and contains the one provider that exists today: Edge, which uses Microsoft Edge's "Read Aloud" neural voices through the open-source edge-tts Python command line tool.

It owns: the Provider trait, the Edge implementation, retries, error classification, long-text splitting, and a process-wide rate limiter. It does not own: caching (the app computes cache keys), the final audio format (media normalizes it), or the scene's duration (measured with ffprobe afterwards).

7.2 The Provider trait

// crates/spoonstill-tts/src/lib.rs:226-304 (abridged)
pub trait Provider: Send + Sync {
    fn id(&self) -> &str;
    fn availability(&self) -> Availability;          // Ready | Missing(Remedy)
    fn voices(&self) -> Result<Vec<Voice>, TtsError>;
    fn default_voice(&self) -> &str { "" }
    fn install(&self) -> Result<String, TtsError> { /* "cannot install itself" */ }
    fn speak(&self, request: &Request<'_>, destination: &Path, cancel: &Cancel)
        -> Result<Spoken, TtsError>;
}

Send + Sync means one provider value can be shared by many threads, because the audio pool speaks several lines at once. Request<'a> borrows its text, voice and settings, so it is Copy and asking for 500 lines clones nothing. Spoken reports the bytes written, the command line with the text removed, and the voice that actually spoke (if the request said default, this is the resolved name).

providers() returns vec![Box::new(edge::Edge::from_env())], and provider(id) finds one by name, case-insensitively, or returns TtsError::NoSuchProvider listing what exists. There is no ElevenLabs provider (Verified from source; a test asserts provider("elevenlabs") is an error).

7.3 How Edge speaks a line

The exact command (Verified by runtime experiment, from the project log):

/opt/homebrew/bin/edge-tts --voice en-GB-RyanNeural --rate '+0%' --volume '+0%'
    --pitch +0Hz
    --file .../.spoonstill/cache/audio/.spoken-75a6acdb77d4f3b7.txt.partial-16618-1.txt
    --write-media .../.spoonstill/cache/audio/.spoken-75a6acdb77d4f3b7.spoken.partial-16618-0.spoken

The text goes in a file (--file), never on the command line (D-081). Three reasons, in rising importance: command lines have length limits; every process on the machine can read another's command line (ps); and spoonstill logs every command line, and the logs go into diagnostics bundles that people send to others. The operator's script does not belong there. The temporary script file is deleted after the attempt whether or not it worked.

The speak flow (edge.rs:1362-1487):

  1. Empty text is a BadRequest.
  2. Voice: empty or default means default_voice_for(text), which looks at the script the line is written in. Latin text gives en-US-AvaNeural; Devanagari gives hi-IN-MadhurNeural; there are 21 such defaults (D-158). A named voice is always obeyed.
  3. Length: a line longer than one hour of speech at 17.3 characters per second (62 280 characters) is refused before any request is made.
  4. Rate, volume and pitch settings are validated (+N%, +NHz).
  5. The line is split into pieces of at most CHUNK_CHARS = 9 000 characters, at paragraph, then sentence, then word boundaries, and packed so an hour is a handful of requests.
  6. Each piece is spoken with retries (below). Several pieces are joined by concatenating the MP3 bytes, which is valid because MP3 is a stream of self-contained frames.
  7. The result is checked: zero bytes is a failure (the tool sometimes exits 0 having written nothing), and the first bytes must look like audio (an HTML error page is rejected).
  8. The file is renamed into its final place.

A Scratch drop guard holds every temporary path and deletes them however the function exits (D-123).

7.4 Retries and classification

The network fails in many ways. edge-tts prints a Python exception on the last line of stderr, and classify() reads that line and matches exception class names, not prose:

  • Permanent (do not retry): NoAudioReceived, ValueError, TypeError, usage errors, No such file or directory, Permission denied, ModuleNotFoundError, and anything unrecognised. An unknown failure is more likely a wrong argument than a flaky network.
  • Transient (retry): WebSocketError, aiohttp, ClientConnector..., ServerDisconnected, ConnectionResetError, ConnectionRefusedError, TimeoutError, socket.gaierror, SSL errors, DNS failures, HTTP 429 and 503.

Retry::default() makes 3 attempts with pauses of 0, 0.5 s and 1.5 s. The retry loop persevere takes both the attempt and the sleep as closures, so tests can run retries instantly without a network.

NoAudioReceived has a special rule since D-195: if the line is short (200 characters or fewer), contains real letters, and is in a script the voice can read, it is retried, because the author's logs showed twelve such lines that all spoke on the next try. A line of only punctuation, or a Hindi line sent to an English voice, is a permanent error with a sentence saying why and which voice to use instead (wrong_script).

When retries run out, network_hint turns the technical reason into advice: "check your internet connection, then any VPN or firewall" for DNS failures, "wait a while" when the service stopped accepting connections, and so on, never inventing a cause it cannot see.

7.5 The pace gate: a rate limiter you can read

In a real 431-scene render, the service accepted 335 lines in three and a half minutes (eight at a time) and then refused every connection for about 54 minutes. pace.rs exists so that does not happen again (D-195). Three rules:

  • at most 2 requests in flight;
  • starts at least 1.2 s apart (at most 50 per minute);
  • after a refused connection, everyone waits a cool-down of 15 s, doubling for each consecutive refusal up to 120 s, reset when a line is spoken.

The arithmetic lives in a plain struct that takes "now" as a parameter, so it is tested without sleeping:

// crates/spoonstill-tts/src/pace.rs:95-111
pub fn try_start(&mut self, pace: Pace, now: Instant) -> Result<(), Duration> {
    let earliest = [self.next_start, self.cool_until].into_iter().flatten().max();
    if let Some(earliest) = earliest
        && earliest > now
    {
        return Err(earliest - now);
    }
    if self.in_flight >= pace.in_flight {
        return Err(Duration::from_millis(100));
    }
    self.in_flight += 1;
    self.next_start = Some(now + pace.gap);
    Ok(())
}

Around it, a Gate holds the schedule in a Mutex with a Condvar, created once per process with OnceLock so every render and every voice audition in the process shares it. enter() waits (in steps of at most 100 ms, so Stop is obeyed even during a two-minute cool-down) and returns a Slot guard whose Drop frees the place however the request ended. A DNS failure is deliberately not a refusal: an offline machine should be told so in seconds, not after cool-downs.

7.6 Whose code is whose

Layer Owner Role
spoonstill_tts::edge, pace spoonstill (Rust) arguments, script file, pacing, retries, classification, validation, joining, rename
spoonstill_media::command spoonstill (Rust) spawning, timeout, cancellation, stderr
edge-tts third party (Python, installed with pipx, brew or pip) opens a websocket to Microsoft and writes MP3
speech.platform.bing.com Microsoft the neural voice service; unofficial and reverse-engineered by edge-tts

spoonstill's Rust code contains no network client. Every byte of speech traffic comes from the edge-tts child process. Speech therefore needs the internet; recordings and silent scenes do not, and a fully cached project renders offline because the pre-flight check only asks for providers whose lines are not cached.

7.7 Installing edge-tts

install() tries, in order: pipx install edge-tts, brew install edge-tts (macOS), and python -m pip install --user --upgrade edge-tts (with python3 and Windows' py -3 variants). It locates each installer with locate, never a bare name, and only claims success after re-locating edge-tts and checking it runs. No version is pinned.

7.8 Tests

72 test functions. tests/edge_retry.rs (Unix only) replaces edge-tts with a small shell script that fails a chosen number of times and then writes fake MP3 bytes, proving retries, permanent failures, chunk joining, cancellation and the cool-down through the real process boundary, offline. tests/edge_live.rs talks to Microsoft for real and is #[ignore]d; make tts-live runs it, and it exists to notice when an edge-tts upgrade changes the error text the classifier depends on.

Docs and code disagree. crates/spoonstill-tts/src/lib.rs (lines 7-11) says ElevenLabs is the default in a sold build and keys come from keyring-rs. Neither exists. The crate's Cargo.toml description is accurate ("ElevenLabs is not written yet").

A code-reading observation (not executed). If Stop is pressed while the last retry attempt is in flight, interpret() maps MediaError::Cancelled to a transient failure, so the user sees "the voice service could not be reached" instead of a clean cancellation (edge.rs:956, 1195). The test a_request_already_in_flight_is_stopped uses one attempt and accepts either outcome, so it does not pin this.
