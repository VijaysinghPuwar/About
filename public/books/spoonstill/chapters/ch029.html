24 Cross-Platform Design: macOS and Windows

Decision D-071 put both macOS and Windows in scope from the first milestone. Linux is not a release target, though the code compiles there and one session ran the gates on it (D-198).

24.1 The approach

The code is cross-platform by construction: paths are Path/OsStr, not strings; processes are stopped by writing q to stdin, not by signals; Ctrl-C uses the ctrlc crate, which also covers Windows console events; platform differences are isolated behind #[cfg]. Where a Windows-only function exists, it usually compiles on every platform so its tests run on the Mac too (D-128).

24.3 How Windows is checked

  • CI runs fmt, clippy (-D warnings) and the full cargo test --workspace on windows-2022 with FFmpeg from Chocolatey.
  • A cross-compile check from the Mac (cargo check --target x86_64-pc-windows-msvc) catches Windows-only warnings before pushing (D-132).
  • Windows sessions ran the shell gates (23/23 for M2, D-176) and took the measurements in ffmpeg-findings.md §13.
  • Several tests are Unix-only (FIFO-based tests, the fake edge-tts shell script). Each has a cfg(not(unix)) twin that prints what is not checked, so the gap is visible rather than silent.

Not run for this book. All runtime evidence in this book comes from macOS. Windows behaviour is described from source code, CI configuration and the project's own recorded Windows measurements.
