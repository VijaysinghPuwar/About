31 How to Modify the Project Safely

The architecture tells you where a change belongs. These are guides, not instructions; none of these changes were made.

Adding a CLI option. Add a field to the right XxxArgs struct in crates/spoonstill-cli/src/main.rs with a #[arg] attribute; pass it into the matching spoonstill_app options struct (for example a new field on RenderProjectOptions in film.rs); implement the behaviour in spoonstill-app or below. Rule: if the window should offer it too, add it to the window's request struct and app.js, and keep the logic in spoonstill-app so both surfaces share it. Run cargo test -p spoonstill-cli (clap's debug_assert) and update README's command reference.

Adding a project.yaml field. Add it to RawSettings and Settings in crates/spoonstill-app/src/import/settings.rs with a default, validate it in resolve, and produce an UnusableSetting problem for bad values. If it changes pixels or audio, it must reach the segment key or audio key, or the cache will reuse stale output (D-107 is the cautionary tale). Document it in the README.

Adding a validation rule. Pure rules (no I/O) go in crates/spoonstill-core/src/project.rs as a new ProblemKind with a severity and a Display sentence; rules needing files or probes go in spoonstill-app/src/import. Add a test that fails without the rule, and consider whether it is an error or a warning.

Changing video encoding settings. The encoder arguments are built in crates/spoonstill-media/src/scene.rs (run_ffmpeg) and hardware.rs (quality_args). The expected result lives in profile.rs (SegmentProfile), which every segment and film is checked against, so change both together. The settings that affect bytes are in segment_key in film.rs; changing the key's inputs re-encodes every cached segment once.

Changing the motion. build_filter in crates/spoonstill-core/src/motion.rs. The exact string is pinned by a test and feeds every cache key, so any change re-renders every project. The CLAUDE.md rule: change it there and record the decision in decisions.md in the same commit.

Adding another TTS provider. Implement Provider in a new module in crates/spoonstill-tts/src/, add one line to providers(), and spawn any tool through spoonstill_media::command. Keys would need secure storage (D-014 planned keyring-rs, not built) and must never reach logs (the redaction in core helps; plan.md asks for a test that greps outputs for the key). The cache key already includes the provider id.

Adding another output format. A different container or codec affects profile.rs (the expected profile), scene.rs (arguments), concat.rs (joining rules), geometry.rs (if sizes change), and the segment key. Because concat requires identical segment parameters, the profile is the contract to update first.

Changing the desktop UI. Markup in apps/desktop/ui/index.html, behaviour in app.js, styles in styles.css; Rust commands in apps/desktop/src/main.rs. Keep logic in spoonstill-app. Run cargo test -p spoonstill-desktop (the contract tests catch missing ids and unregistered commands) and make ui. Every new command returning Result must call journalled.

Adding an operating system (for example Linux releases). Package-manager folders in tools.rs already include Linux paths; runs::config_dir already handles XDG; hardware candidates have a Linux list. Missing: a CI leg, a release leg in release.yml, an installer, and Tauri's Linux dependencies, several of which carry the advisories ignored in .cargo/audit.toml "because Linux is not shipped".
