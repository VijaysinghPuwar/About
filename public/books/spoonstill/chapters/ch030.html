25.2 Categories

  • Unit tests live beside the code in #[cfg(test)] mod tests blocks. Pure logic (filter strings, frame maths, validation, cue splitting, hashing, the pace schedule) is tested directly with no I/O.
  • Real-FFmpeg integration tests in crates/spoonstill-media/tests/ render actual media. tests/common/mod.rs builds fixtures in Rust (so Windows needs no bash) and gives each test run its own output folder so parallel sessions do not delete each other's files (D-180).
  • Architecture tests (architecture.rs, no_shell_strings.rs) read manifests and source text to enforce structure.
  • Documentation tests (readme_claims.rs, cited_decisions.rs, release_assets.rs) keep the README's numbers, the decision citations and the release asset names honest.
  • Contract tests (ui_contract.rs) check the Rust/JavaScript seam by reading both as text.
  • Property tests: 1 500 random chapters per run; sweeps of texts x durations x budgets for captions.
  • Golden values: the exact filter string; a segment key computed by hand in Python and pinned as a literal u64 (0x342b94f321039a02, D-172); byte-for-byte caption output.
  • Live tests (edge_live.rs) are #[ignore] and run with make tts-live.
  • Benchmarks (caption_bench.rs) are #[ignore] and print a table instead of asserting a time.

25.3 Representative tests, explained

the_emitted_chain_is_exactly_the_documented_recipe (core, motion.rs:563). Behaviour: the filter string for a known input. Why: the string decides every pixel and is part of every cache key. Prevents: an innocent-looking edit silently changing every film or invalidating every cache. How: compares the full string.

odd_dimensions_sar (media, segment_integrity.rs). Behaviour: a 1999x1001 photo renders with SAR 1:1 in every aspect. Why: the measured trap in §4. Prevents: stretched pictures in films. How: renders with real FFmpeg and asserts the full profile; the fixture asserts its own oddness so the test cannot pass by accident (§8b).

hostile_paths_survive_the_process_boundary (media). Behaviour: names with quotes, $(...), ;, &, leading spaces and dashes, and Unicode render correctly. Why: shell injection and option injection. How: renders 15 frames from such paths and checks that no pwd file was created.

cancellation_leaves_no_valid_looking_stub (media). Behaviour: cancelling a long render leaves no output file. Why: a valid-looking partial file would be reused as a finished segment. How: cancels after the first progress report and checks the destination and every temporary.

the_black_edge_probe_catches_a_real_letterbox (media, motion_matrix.rs). Behaviour: the probe that checks "no black edges" reads 0 on a real letterbox. Why: a probe that always says "fine" makes 54 other renders meaningless. This is a control test.

concurrent_writers_produce_one_header_and_whole_rows (state). Eight threads write 40 rows each; the file must have exactly one header and 321 whole lines (D-122).

eight_workers_wanting_one_photograph_read_it_once (app). A barrier releases eight threads at once; an atomic counter proves the photo was read once (D-173).

results_come_back_in_input_order (app, pool). Determinism of the joined film depends on it.

every_command_the_frontend_calls_is_registered_in_rust (desktop). A typo in an invoke("name") would fail silently in the webview; this test fails the build instead.

25.4 What cargo test --workspace covers, and what it does not

It runs every unit and integration test in all seven packages, including real FFmpeg renders (FFmpeg must be installed). It does not run the ignored live TTS tests, the benchmarks, the shell gates, the JavaScript checks, actionlint or shellcheck, and it cannot click the window.

25.5 make gates: the milestone exit gates

make gates runs scripts/m0-gates.sh, m1-gates.sh and m2-gates.sh: 39 checks (8 + 8 + 23) that build the release CLI, generate fixtures, and drive the real still binary end to end. A selection:

Verified by test run. On the analysis machine, make gates reported M0 8/8, M1 8/8, M2 23/23 in 347 s. cargo fmt --check, cargo check --workspace, cargo clippy --workspace --all-targets -- -D warnings, make workflows (actionlint), make shell (shellcheck) and make ui (Node checks of app.js) all passed.

The gates have their own safety measures: a guard refuses to run if mktemp -d returns something unsafe before any rm -rf (D-175); with_machine_state redirects HOME, APPDATA and XDG_CONFIG_HOME so the gates never write to the operator's real runs.csv; and the check helper fails if called with no command, after a split line once let a gate "pass" while running nothing (D-153).

25.6 The testing culture

PROCESS.md describes the working rule: reproduce a defect first, fix it, then prove the new test fails without the fix. The decisions record many cases where a first test passed against the broken code (D-116, D-156, D-174), which is why so many tests are paired with control tests or mutation checks.
