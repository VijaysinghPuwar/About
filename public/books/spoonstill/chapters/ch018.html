14 The Render Path, Step by Step

This chapter follows spoonstill_app::render_project (crates/spoonstill-app/src/film.rs:544) in order. Line numbers are approximate pointers into film.rs unless another file is named.

14.1 Entry

// film.rs:544-548
pub fn render_project(
    options: &RenderProjectOptions,
    cancel: &Cancel,
    on_event: &(dyn Fn(FilmEvent) + Sync),
) -> Result<RenderedFilm, FilmError> {

options carries the project root and every per-run override (out, jobs, audio_jobs, force, voice, fallback_voice, provider, subtitles, subtitle_theme, subtitle_placement, encoder, keep_cache, aspect, short_edge, fps). on_event is called from several threads, so it must be Fn + Sync.

14.2 The steps

  1. Import and validate (553-558): import::load(root, &ProbeCheck::from_env(), cancel) (Chapter 12). A cancelled import becomes FilmError::Cancelled.
  2. Voice override (apply_voice_override, 980-1009): for every spoken scene, voice::resolve decides whether this run's voice or the machine fallback replaces the project's. Done on the in-memory model before any key is computed, so a different voice is a cache miss, as it should be.
  3. Geometry override (apply_geometry_override, 1073-1103): build a new OutputSpec from --aspect, --resolution/--short-edge, --fps, then recompute the undersized-stills warning for the new frame.
  4. Subtitle override (1115-1129): recompute the "characters no font can draw" warning if subtitles were switched.
  5. Gate (563-569): any error-severity problem stops here with FilmError::HasProblems; an empty project with NoScenes.
  6. Capacity (574-577): capacity::plan(output_spec) gives the automatic worker count; an explicit --jobs wins; capacity::pressure decides whether to warn.
  7. Destination (destination, 1141-1163): --out is used as given; otherwise output: must resolve inside the project (resolve_destination_within).
  8. Journal (587-588): open the project log and runs.csv.
  9. Lock (Lock::take, 1893-1942): .spoonstill/render.lock, try_lock, write pid N. Held in _lock until the function returns.
  10. Events: Planned (scenes, jobs, audio jobs, memory per worker), MemoryPressure if an explicit --jobs will not fit, one Warned per warning, and the unchosen-voice warning. All printed before any work starts, because a line printed under five minutes of progress is a line nobody reads (D-144, D-145).
  11. Tools (653-665): Tools::from_env() resolves absolute paths for ffmpeg and ffprobe; the FFmpeg version is written to the log once per run (D-151).
  12. Encode settings: preset and CRF from settings, encoder from --encoder (default libx264).
  13. Segments directory: create_dir_all(.spoonstill/segments).
  14. Pre-flight voice check (check_voice_service, 1173-1218): for scenes whose speech is not already cached, ask each provider availability() once. A missing edge-tts fails here, before any work, naming the provider and how many scenes need it (D-002, D-094). A fully cached project needs no provider at all.
  15. The pipeline (resolve_and_render, 1238-1353): pool::pipeline(&scenes, audio_jobs, jobs, cancel, first, second).
    • Stage one (per scene, up to audio_jobs at once): audio::resolve returns (normalized WAV path, measured duration, key, reused), emitting FilmEvent::Audio or Failed.
    • Stage two (per scene, up to jobs at once, starting as soon as that scene's audio is ready): plan_scene then render_one, emitting FilmEvent::Segment or Failed.
  16. plan_scene (1457-1518): frames = frames_for_duration(duration, fps); the image's content hash (read once per photo, shared between workers); the motion (MotionSpec::seeded_with(motion_seed, project_id, index, occurrence, hash), unless the scene names its own); the subtitle cues if captions are on; the segment key; and the output path segments/seg-{key:016x}.mp4.
  17. render_one (1533-1574): if the segment file exists, probe it; reuse it only if the profile matches and the frame count equals the plan; otherwise delete it. If not reusable, call spoonstill_media::render_scene (Chapter 15).
  18. Collect (1338-1351): audio outcomes first, then segment outcomes, so an error report names the cause (a failed narration) before its consequence (segments not started).
  19. Join (704-744): emit Joining, compute the expected total frames and duration, and call concat::concat (Chapter 16): write the list, ffmpeg -f concat -safe 0 -i list -c copy, validate the film, check for cancellation once more, rename into place.
  20. Prune (749-761): sweep segments and derived audio down to the live set plus two spare generations, unless --keep-cache.
  21. Record (770-783): a film complete row with duration_s, scenes, frames, reused_segments, reused_audio, spoken, freed_bytes.
  22. Return RenderedFilm; _lock drops and the OS lock is released.

A naming quirk (Verified by runtime experiment). The spoken field in the film complete row counts every narration that was not reused, including silent scenes and supplied recordings, not only lines spoken by a voice. The analysis run of the fixture project (no text at all) logged spoken: 6.

14.3 Errors

FilmError has twelve variants: Import, HasProblems, NoScenes, Locked, OutputOutsideProject, UnusableGeometry, VoiceService, Audio { failures, not_started }, Render { failures, not_started }, Cancelled, Media, Io. Each has a Display written as an operator sentence. Failures are collected per scene: one broken photo does not hide the others, and the report adds "N more scenes were not started, because ..." when the pipeline stopped admitting work.

14.4 Cancellation everywhere

The same Cancel flag is consulted at every layer: the import's probe pool, the pipeline's admission loops, audio::resolve before starting work, every child-process wait (with the q, 2 s, kill ladder), the join, and once more just before the final rename (D-181: a Ctrl-C during the join used to publish the film and exit 0). Finished segments are kept, so the next run resumes. A cancelled run always surfaces as the single FilmError::Cancelled.

14.5 Determinism

Nothing in plan_scene depends on which worker ran it or when. Results come back in input order. The motion seed is a pure function of content and settings. Therefore --jobs 1 and --jobs 8 produce byte-identical films; M2 gate 3 asserts this on every make gates run (D-077).
