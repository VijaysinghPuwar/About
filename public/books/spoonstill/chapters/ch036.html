30 How to Debug spoonstill

30.1 The three places evidence lives

  1. The terminal or window message. Every error is written as a sentence that names the scene, file or program. Read it fully; the second line often holds the tool's own output.
  2. The project log, <project>/.spoonstill/logs/spoonstill-YYYYMMDD.jsonl: every event of every run of this project, including every FFmpeg command line ("message":"running","command":"..."), the filter chosen for each scene ("scene resolved"), and full stderr on failure.
  3. The machine log, runs.csv, found with still diagnostics where: one row per event for every project. A command with an invoked row and no finished or failed row died (crash, kill, frozen machine), because spoonstill always writes one of those when it returns.

still diagnostics export --project DIR --out bundle.txt puts the logs and an environment description in one file, with credentials redacted.

30.2 Useful commands

still doctor                         # which ffmpeg, ffprobe, edge-tts; hardware encoders
still validate DIR                   # every problem at once; exit 1 on errors
still validate DIR --list            # also list every scene
still validate DIR --no-probe        # skip ffprobe (is FFmpeg the problem?)
still render DIR --jobs 1            # one scene at a time: simpler logs
still render-scene --image X --audio Y --out /tmp/s.mp4   # one segment, no project
still diagnostics where              # paths of the logs
ffprobe -v error -show_streams -of compact FILE   # what a file really is

To replay a failing FFmpeg call, copy its command field from the project log and paste it into a terminal: that is exactly what the display quoting exists for.

30.3 By symptom

Render failure. Run still validate first; a render refuses projects with errors, and validation lists them all. If validation is clean, read the failing scene's lines in the project log: the running command and the exited stderr.

FFmpeg failure (ffmpeg exited N). The message includes the tail of stderr indented with |. Paste the logged command to reproduce. Check still doctor for which binary is used; SPOONSTILL_FFMPEG can point to a different build.

Bad image. NotUsableMedia names the file and quotes ffprobe. A truncated JPEG probes as 0x0. Open the file in an image viewer; re-export it as JPEG if needed. Very small photos are not errors but trigger the undersized warning with a suggested --short-edge.

Bad narration. A recording without an audio stream or duration is refused at validation. A cached WAV that was damaged is detected by its header and rebuilt (D-190). If a film is shorter than expected, look for a JoinStopped error naming the scene.

TTS failure. still voices tests the service and lists voices. DNS errors mean no route to speech.platform.bing.com (check network, VPN, firewall). "Stopped accepting connections" means the service is throttling this machine; wait, then render again (cached lines are not re-spoken). "Cannot read this line" with a language name means the voice cannot read the script: choose the suggested voice. make tts-live checks the error classifier against the installed edge-tts.

Project validation failure. Typical causes: two images for one number (AmbiguousScene), a typo in project.yaml (unknown key), resolution and short_edge both set, a manifest path outside the project, leftover .arranging- files (run any arrange command, which recovers first).

Windows-only issue. Check still doctor's paths (winget's Gyan.FFmpeg folder, Python's Scripts); remember that Windows forbids some names macOS allows; if test binaries fail with "An Application Control policy has blocked this file", that is Windows Smart App Control, not spoonstill (CLAUDE.md records the workaround).

macOS-only issue. An app opened from Finder does not see your shell's PATH; spoonstill searches Homebrew folders itself, so check still doctor from the same app. A downloaded app may be quarantined; the installer clears that, a manual download may need it cleared.

Performance issue. Look at the Planned line: how many workers and why (memory or cores). Check for the undersized-stills warning (rendering small photos at 4K is slow for nothing). Check whether the project or output is on a network share. Compare reused_segments and spoken in the film complete row to see whether the cache worked.

CI failure. Read which job failed: audit can fail with no code change (a new advisory); windows catches Windows-only warnings (run the cross-compile check locally); gates runs without edge-tts; installer-* depend on the latest published release. A workflow that shows no jobs at all has a syntax error: run make workflows.
