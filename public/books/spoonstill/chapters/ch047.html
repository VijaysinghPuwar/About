Appendix B: Answers

Exercise answers

1.1. Yes. rows.rs lists images jpg jpeg png webp tif tiff bmp heic, audio mp3 m4a wav aac flac ogg opus wma, text txt md, matching the README; .md is only paired by matching stem (D-152).

2.1. 5.3 x 30 = 159.0 exactly, already on the frame grid, so ceil(159 - 1e-9) = 159 and there is no padding. 3.717 x 30 = 111.51 is not.

3.1. 4.0 x 25 = 100 frames; samples = (100 x 48000 + 12) / 25 = 192 000.

3.2. In yuv420p the colour planes are half width and half height, so each 2x2 block of pixels shares one colour sample; an odd dimension has no whole block at the edge. OutputSpec::new refuses an odd short edge at geometry.rs:317 ("even, H.264 4:2:0 cannot represent odd dimensions") and checks the derived long edge the same way at line 346.

4.1. cli_does_not_reach_past_the_application_layer fails, naming spoonstill-media as a crate the CLI may not depend on directly.

5.1. Seeds index into ALL; reordering would map the same seed to a different motion, silently changing the move of every seeded scene in every existing project and invalidating every cached segment.

5.2. fnv1a_fields writes the separator byte 0x1f between fields, so ["a","b"] feeds a, 0x1f, b, and ["a\x1fb"] feeds a, 0x1f, b too: identical bytes, identical hash.

6.1. The cause of a failure is printed last; the beginning is banner and stream information. When it drops data it prepends [earlier stderr dropped - retained the last 256 KiB].

10.1. --keep-cache, which sets keep_cache: true in RenderProjectOptions and skips prune_segments and prune_audio.

11.1. FilmEvent::Segment, converted by view_of into ProgressView::Segment, serialized with kind: "segment".

12.1. By stem first: b.m4a pairs with b.jpg. Then by position: the leftover x.m4a goes to the first photo still without a recording, a.jpg.

13.1. Renaming the project folder changes project_id, which seeds the motion: re-encodes every seeded scene. Renaming 003.jpg to 003.jpeg changes no key (keys use the image's content, not its name): reused. Changing CRF changes the encoder field: every segment re-encodes. Moving the project to another disk keeps the same folder name and contents: reused.

14.1. Because a fully cached project should render on a machine that has since lost edge-tts, or that is offline. Checking all lines would refuse a project that needs no speech at all.

15.1. 3240x5760 (3 x 1080 by 3 x 1920). scale=3240:5760:force_original_aspect_ratio=increase makes 4000x3000 into 7680x5760 (scale factor 1.92), and crop=3240:5760 keeps a centred vertical strip, discarding about 58% of the width.

15.2. The WAV is 3.717 s but the video is 112 frames (3.7333 s). atrim=end_sample=179200 cannot extend audio, only cut it. apad first appends endless silence, so the trim can produce exactly 179 200 samples. Without it, the audio would be 16 ms short of the video.

16.1. seg-0123abcd.mp4 yes; my film.mp4 no (space); .hidden.mp4 no (leading dot).

16.2. Other errors are answers: "not media" or a non-zero exit will not change on retry. Only a timeout may be a temporary stall (such as a network share), and retrying everything would double the cost of genuine failures.

17.1. Wanted +6 dB (-16 - (-22)); allowed -1.5 - (-3) = +1.5 dB; so the gain is +1.5 dB. With a -6 dBTP peak, allowed is +4.5 dB, so the gain is +4.5 dB. Either way the result stays below -16 LUFS rather than clipping.

20.1. Rust will not let several threads hold &mut to the same Vec at once, even at different indices, because it cannot prove they are different. A Mutex gives exclusive access; without it the closure would not compile (the vector is not Sync for mutation through a shared reference).

20.2. A binding named _lock keeps the value alive until the end of the scope. The special pattern _ does not bind at all, so the value is dropped immediately and its Drop releases the lock.

21.1. The row declares two audio sources, so validation reports ConflictingAudioSources listing text and audio_file, and the render is refused.

22.1. project/link resolves to /etc; reporting Missing for nope would reveal that /etc/nope does not exist while /etc/passwd would report differently. Returning Outside for both leaks nothing.

23.1. 1440p prescale is 7680 x 4320 = 33 177 600 pixels; 33 177 600 x 36 = 1.19 GB, plus 192 MiB, about 1.39 GB per worker. A 16 GB machine's budget is about 11.2 GB, room for 8 workers; 8 cores give 4 by cores, so 4 workers.

25.1. 21 tests run (on the analysis machine: running 21 tests), because the filter matches every test whose path contains motion. Example: a_single_frame_segment_emits_no_division protects against on/0 producing NaN inside FFmpeg.

30.1. The event has fields motion (for example zoom-in@center:0.1000) and filter. still render-scene --image X --audio Y --out s.mp4 --motion zoom-in --anchor center --amount 0.1 reproduces it at the default size.

Knowledge check answers

  1. Text spoken by a voice (Tts), a supplied recording (File), or silence (Silent); each becomes a normalized 48 kHz stereo WAV plus its measured duration.
  2. spoonstill-media (command.rs); crates/spoonstill-media/tests/no_shell_strings.rs.
  3. 2.001 x 30 = 60.03, rounded up to 61 frames; 61 / 30 = 2.0333 s.
  4. At 2x, motion visibly stepped (280 of 300 unique frames); at 3x all frames were unique; 4x and 6x were slower and no better (ffmpeg-findings.md §1).
  5. It scales until the image covers the box in both directions (cropping the overhang). The window's position is always a fraction in [0, 1] of the legal travel iw - iw/zoom, so it never leaves the canvas.
  6. setsar=1 then format=yuv420p; setsar=1 must be last before the format (with setparams just before it).
  7. JPEGs are full range, which leaks through as yuvj420p; spoonstill adds out_range=tv to the first scale and pins setparams=range=tv:...bt709.
  8. FFmpeg's concat accepts mismatched segments with exit 0 and no warning (§5); exit status is not validation.
  9. Any four of: image content hash, narration key, frame count, motion descriptor and seed, geometry, encoder settings, pixel format, colour space, timescale, subtitle fields. D-107 added the narration key: a different take of the same length used to reuse the old segment.
  10. V1 seeds from the scene index (reordering changes moves); V2 from occurrence (reordering changes nothing). New projects get motion_seed: v2; projects without the key stay V1.
  11. .spoonstill/render.lock, held with the OS lock File::try_lock; the OS releases it when the process dies; the file is never deleted.
  12. Finished segments are on disk under content-derived names; the next run computes the same keys and reuses them.
  13. Command lines have length limits, are visible to other processes, and are logged into diagnostics; the script is the operator's content.
  14. At most 2 in flight; starts at least 1.2 s apart; after a refused connection, a cool-down of 15 s doubling to 120 s for everyone.
  15. The last non-empty line of stderr (the Python exception's class name); unknown errors are permanent.
  16. -16 LUFS integrated with a -1.5 dBTP peak ceiling; a constant gain is deterministic and does not compress, so caches stay byte-identical.
  17. An operator's pauses are deliberate; only a provider's padding is an artifact.
  18. Resolving narrations (network bound) and rendering segments (CPU bound); before, each waited for the other, leaving a resource idle for about a quarter of a cold render.
  19. Half the available cores, at most 4, then capped by 70% of RAM divided by the modelled memory per worker; never less than 1.
  20. An Arc<AtomicBool>; FFmpeg is sent q on stdin, given 2 s, then killed and reaped.
  21. Escaping is error-prone; refusing anything but simple ASCII names it generated itself removes the whole class of parsing problems.
  22. It finds the first segment whose running frame total passes the film's actual frame count, then the damaged segment is deleted and named; a segment damaged on a network volume had made FFmpeg stop the join with exit 0.
  23. A parse error: deny_unknown_fields rejects the unknown key, so a typo is never silently ignored.
  24. An AmbiguousScene error naming both files; spoonstill refuses to guess which still you meant.
  25. Drop (RAII): the guard's destructor runs on every exit path, including ? returns and panics.
  26. Paths may contain bytes that are not valid UTF-8; OsString carries them to FFmpeg unchanged.
  27. Through a Tauri Channel<ProgressView> passed with invoke; each event is JSON tagged with kind.
  28. runs.csv (find it with still diagnostics where): an invoked row without a finished or failed row means the process died; then the project's .jsonl log.
  29. edge-tts, so M2 gate 7 checks that a render with a written line fails and names the missing tool instead of substituting silence.
  30. RawSettings/Settings and validation in import/settings.rs; the code that uses it (media or app); and segment_key in film.rs so the cache misses when it changes.
