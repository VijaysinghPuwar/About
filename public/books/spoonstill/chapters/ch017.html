13 The Project Format and Its State

13.1 Two kinds of files

Decision D-013 splits a project into two artifacts:

  • Human-owned inputs: your photos, recordings, scripts, and an optional project.yaml and scenes.csv. The renderer never writes these.
  • Machine-owned state: everything under .spoonstill/. Disposable: delete it and the next render rebuilds it.

13.3 Convention mode and manifest mode

Convention mode (no scenes.csv): every file in the folder is grouped by its stem. The rules (Verified from source, import/rows.rs:295-509):

Files sharing a stem Result
image + recording narrated by the recording
image + text text is spoken
image + recording + text recording narrates, text is the caption
image only silent for defaults.duration
two images (001.jpg, 001.png) error: AmbiguousScene, naming both
numbered text or recording, no image waiting for a picture (warning, not rendered)
non-numbered text or recording, no image UnpairedFile warning

Order is the natural order of stems: scene2 before scene10. Hidden files are skipped, except that leftover .arranging- or .removing- files are reported as an interrupted rename.

Manifest mode (scenes.csv, or the file named by manifest:): one row per scene, and the manifest is the complete list. Columns: image (required), text, audio_file, voice, duration, zoom_direction, zoom_anchor, caption. Unknown columns are an error. A scene's id is its image's stem, so moving between modes keeps identity.

image,text,audio_file,voice,duration,zoom_direction,zoom_anchor,caption
img/001.jpg,The harbour at dawn.,,en-GB-RyanNeural,,in,center,
img/002.jpg,,audio/take2.m4a,,,,,The tide came in.
img/003.jpg,,,,4.5,,,

13.4 project.yaml: every key

Unknown keys are rejected (a typo is an error, not a silently ignored setting, D-055). Every key is optional:

Key Type Default Notes
output path out.mp4 must stay inside the project (symlinks resolved, D-112)
aspect text 16:9 also landscape, 9:16, portrait, shorts, reel, tiktok, story, 1:1, square
resolution text none 720p, 1080p, 1440p/2k, 2160p/4k; error if short_edge is also set
short_edge number 1080 even; divisible by 9 for 16:9 and 9:16; at most level 5.2
fps number 30 1 to 120
manifest path none then scenes.csv if present, else convention mode
motion_seed text v1 when absent v1 or v2
tts.provider text edge
tts.voice text default default means "chosen from the script's language"
tts.trim_head, tts.trim_tail seconds 0.10, 0.25 how much provider silence to keep
encode.preset text medium libx264 preset
encode.crf number 18 0 to 51
defaults.duration seconds 4.0 length of a silent scene
defaults.zoom_amount number 0.10 0.02 to 0.50
subtitles.enabled bool false captions are off by default (burning in is irreversible)
subtitles.theme text classic classic boxed band card punch minimal
subtitles.position text bottom bottom or top

A complete example:

motion_seed: v2
output: renders/chapter-3.mp4
aspect: "16:9"
resolution: 4k
fps: 30
tts:
  provider: edge
  voice: en-GB-RyanNeural
  trim_head: 0.10
  trim_tail: 0.25
encode:
  preset: medium
  crf: 18
defaults:
  duration: 5.0
  zoom_amount: 0.12
subtitles:
  enabled: true
  theme: boxed
  position: bottom

(Quoting "16:9" is the safe spelling in YAML. Whether the unquoted form parses as text with serde_yaml_ng was not independently verified.)

13.5 Content-addressed caches

The key idea that makes re-renders cheap and resume possible: every intermediate file is named by a hash of everything that affects its bytes, never by its position or path (D-043).

A segment file is seg-<16 hex digits>.mp4, where the hex is segment_key, a length-prefixed FNV-1a hash (film.rs:1800-1857) of:

  1. the image's content hash (its bytes, not its path);
  2. the narration's cache key (so two different takes of the same length are different segments, D-107);
  3. the frame count;
  4. the motion descriptor and seed (for example zoom-in@center:0.1000:86ff68c605f4705e);
  5. the geometry, WIDTHxHEIGHT@FPS;
  6. the encoder settings (medium:18, or h264_nvenc:medium:18 for hardware);
  7. the pixel format, colour space and video timescale constants;
  8. the subtitle theme, placement and every cue's timing and text.

Not in the key: the scene's file path, its scene id, its position (except through a V1 motion seed), or the machine.

Consequences:

  • Second render: every key matches an existing file, the file is re-checked, and nothing is encoded.
  • Edit one narration: one audio key changes, so one segment key changes; 499 of 500 segments are reused (measured, D-154).
  • Crash or kill midway: finished segments are already on disk under their keys, so the next run reuses them. This is how resume works without a database: in a measured run killed at 60 s with 167 of 500 scenes done, the next run reused exactly 167 (D-154).
  • Reorder under motion_seed: v2: nothing changes in any key, so nothing re-encodes. Under v1 every scene's index changes, so every segment misses (D-140, D-153).

13.5.1 Reuse is checked, not trusted

A cached segment is reused only if ffprobe says it matches the full segment profile and its frame count equals the plan (D-110). A cached WAV is reused only if its RIFF header size matches its file length (D-190). A bad entry is deleted and rebuilt.

13.5.2 The cache does not grow forever

After a successful join (and unless --keep-cache is given), prune keeps the files the film used plus two spare generations of older files, newest first, and deletes the rest. Two spares make flipping back and forth between two subtitle themes free. It touches only names spoonstill writes, never spoken- speech, and never fails the render (D-109, D-147).

13.6 The render lock

.spoonstill/render.lock is opened and locked with File::try_lock (an OS-level lock). A second render of the same project is refused; renders of different projects run freely. The file's existence means nothing: it is never deleted, and if a render crashes, the OS releases the lock automatically. --force is kept for scripts but cannot break a live lock (D-113).

13.8 Temporary files

Every writer uses atomic::partial_path: a hidden name beside the destination, such as .seg-<key>.mp4.partial-<pid>-<n>.mp4 or .film.mp4.partial-<pid>-<n>.mp4. The process id and a counter make each name unique. Writing beside the destination (not in /tmp) keeps the final rename on the same filesystem, where it is atomic. Abandoned partials from dead runs are swept later: in .spoonstill/ after the join, and beside the film only if older than 60 seconds (another run might still be writing, D-178).

13.9 Versioning and migration

There is no schema version number. Compatibility is handled case by case: motion_seed absent means V1 forever; old segment names (seg-NNNN-<key>.mp4) are still recognised as spoonstill's so the sweep can remove them; a cache key change (D-107, D-118, D-153) simply misses old files once, re-encodes, and produces a byte-identical film.
