10.2 Parsing with clap

clap's derive macros build the parser from Rust types: #[derive(Parser)] on Cli, #[derive(Subcommand)] on enum Command (each variant becomes a subcommand, its doc comment becomes help text), and #[derive(Args)] on each argument struct. Constraints like conflicts_with = "short_edge" are declared on fields, so --resolution 4k --short-edge 1080 is rejected by clap before any spoonstill code runs.

10.3 main, run, dispatch

// crates/spoonstill-cli/src/main.rs:480-489
fn main() -> ExitCode {
    let cli = Cli::parse();
    match run(cli) {
        Ok(()) => ExitCode::SUCCESS,
        Err(message) => {
            eprintln!("still: {message}");
            ExitCode::FAILURE
        }
    }
}
  • Exit codes: 0 on success, 1 on any handler error. A parsing error is handled by clap itself, which prints usage and exits with its own code (2 by clap's default; not set in this file).
  • run wraps every command with two journal rows: command invoked before, command finished or command failed (with the error as detail) after. The "invoked" row is what proves a command started and never came back, which is how a frozen machine was diagnosed (D-144, D-148).
  • dispatch is one exhaustive match; adding a subcommand without a handler is a compile error.

Every handler returns Result<(), String>, converting typed errors with .map_err(|e| e.to_string()), so the typed error's Display text is exactly what the operator reads.

10.4 Progress and Ctrl-C

The render handler passes a closure to render_project that prints each FilmEvent. Because worker threads call it, it is wrapped in SerialEvents, which is just a Mutex around a closure:

  [  3/6 done] 004              75 frames    2.500s  (reused)

Ctrl-C only sets the shared Cancel flag:

// crates/spoonstill-cli/src/main.rs:1476-1480
let cancel = Cancel::new();
let handler = cancel.clone();
if let Err(error) = ctrlc::set_handler(move || handler.request()) {
    eprintln!("still: warning: Ctrl-C will not be graceful ({error})");
}

The ctrlc crate is used because a hand-written signal handler would need unsafe, which the workspace forbids, and it also covers Windows console events. The graceful-then-forced escalation (q, 2 s, kill) lives in the media crate, not here; a second Ctrl-C does not escalate faster. still validate installs no handler on purpose, so Ctrl-C ends it immediately.

10.5 The CLI's tests

Besides 11 unit tests (Cli::command().debug_assert() checks clap's own consistency), the CLI crate hosts four repository-wide integration tests:

  • architecture.rs: the layering rules (Chapter 4).
  • cited_decisions.rs: every D-nnn mentioned anywhere in crates/, apps/ or scripts/ must exist as a heading in decisions.md.
  • readme_claims.rs: README's numbers (gate count, #[test] count, decision count, integration suites, line counts within 3%) must match the tree.
  • release_assets.rs: the release workflow, its publish gate and both installers must agree on the five asset names and on SHA256SUMS.txt.
