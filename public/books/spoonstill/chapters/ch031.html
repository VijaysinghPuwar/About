26 CI/CD and Release Engineering

26.1 Continuous integration: ci.yml

Triggered on every push to master and every pull request. Workflow-wide: RUSTFLAGS: -D warnings (any compiler warning fails), and the token has read-only permissions. Six independent jobs run in parallel:

Job Runner What it proves
audit ubuntu-latest cargo audit --deny warnings against the RustSec database; can fail without any code change
check macos-14 fmt, clippy, the whole test suite with real FFmpeg, the JavaScript parse and smoke test, the release-asset and architecture tests, the cargo tree core check
windows windows-2022 fmt, clippy and the whole test suite on Windows
installer-macos macos-14 runs install.sh from the checkout against the latest release; the installed still --version matches the tag; the .app carries no quarantine attribute
installer-windows windows-2022 runs install.ps1; still.exe runs; the install folder is an exact entry on the user PATH
gates macos-14 (full history) make gates, deliberately without edge-tts, so gate 7 checks the "fail and name the missing tool" path

Toolchain setup uses dtolnay/rust-toolchain, but rust-toolchain.toml pins 1.94.0 and rustup obeys the file, so every job builds with 1.94.0. Swatinem/rust-cache caches dependencies. All actions are pinned to full commit SHAs (D-125). Workflow syntax is checked locally with actionlint (make workflows), because a workflow GitHub rejects runs no jobs and shows no logs (D-136).

26.2 Releases: release.yml

Triggered by pushing a tag v* (or manually with a tag name).

  1. draft: the tag must equal the version in both Cargo.toml and apps/desktop/tauri.conf.json, or the job fails (D-102). A draft release is created, or reused when re-running.
  2. cli (three legs, fail-fast: false): macOS arm64 and x86_64 (tar.gz), Windows x86_64 (zip). Each runs rustup target add for the pinned toolchain (the action alone added the target to the wrong toolchain, D-097), builds with cargo build --release --locked, packages the binary with THIRD-PARTY-NOTICES.md, writes a .sha256, smoke-tests where it can run the binary, and uploads with --clobber so a failed leg can be re-run.
  3. desktop (two legs): a universal macOS .dmg and a Windows NSIS installer, built with cargo tauri build -- --locked after installing tauri-cli =2.11.4 with cargo binstall --locked, so even a fallback source build uses tauri-cli's own lock file (D-197). Assets are renamed to friendly names (spoonstill-macOS.dmg, spoonstill-Windows-Installer.exe, D-098).
  4. publish: require exactly the ten expected files (five assets plus five checksums); download each and verify sha256sum -c; fold the checksums into one SHA256SUMS.txt; delete the individual .sha256 files; mark the release latest only if it is the newest version by sort -V (a re-pushed old tag once became "latest" and broke both installers, D-138); undraft.

The release page ends with five downloads plus SHA256SUMS.txt: spoonstill-macOS.dmg, still-macOS-AppleSilicon.tar.gz, still-macOS-Intel.tar.gz, spoonstill-Windows-Installer.exe, still-Windows.zip.

26.3 The installers

scripts/install.sh (macOS): find the latest tag through the GitHub API; download the right archive and SHA256SUMS.txt; refuse if the checksum line is missing or wrong; install still to ~/.local/bin by staging beside and renaming; download, verify and copy the .app to /Applications (or ~/Applications) and remove its quarantine attribute; offer brew install ffmpeg; print hints for edge-tts and PATH. It never uses sudo and never downloads FFmpeg itself.

scripts/install.ps1 (Windows): the same verification; installs still.exe to %LOCALAPPDATA%\Programs\spoonstill\bin; Unblock-File; adds the folder to the user PATH after an exact (not substring) comparison (D-128); offers winget install --id Gyan.FFmpeg. It installs only the CLI; the Windows window is installed from the .exe on the release page.

26.4 What is not done (M5)

No code signing, no notarization, no auto-updater, no bundled FFmpeg (that needs an LGPL build first, D-062), and Rust dependency licence notices are not generated yet (THIRD-PARTY-NOTICES.md says so).
