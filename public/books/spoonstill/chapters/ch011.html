8 spoonstill-state: Logs and the Activity Record

8.1 Why it exists

When a render fails on someone's machine, the explanation (FFmpeg's stderr, the exact command, the file) is gone by the time they report it. Decision D-016: write every failure down as it happens, and make it easy to send. spoonstill-state holds the two sinks and the bundle exporter. It depends only on core.

Docs and code disagree. The crate's module comment (src/lib.rs:1-11) describes "machine-owned render state, in SQLite" with typed transitions Pending -> Resolving -> .... None of that exists; the crate has only logs.rs and runs.rs. Its Cargo.toml description is correct: "No SQLite yet, that is M3."

8.2 The per-project log: JSON Lines

FileLog writes one JSON object per line to <project>/.spoonstill/logs/spoonstill-YYYYMMDD.jsonl:

{"at":"2026-10-07T06:20:24.884Z","level":"info","scope":"render",
 "message":"project invoked","root":"...","scenes":"6","jobs":"2",...}

The JSON is written by hand (no serde in this crate), with careful escaping so a multi-line FFmpeg error stays on one line. Files rotate at 8 MiB and the newest five are kept. A write failure disables the file and records the error once, so a full disk produces one failure, not thousands. Logging can never fail a render.

Secrets are scrubbed earlier, when the Event is built in core, so every sink receives already-redacted text.

8.3 The machine-wide runs.csv

Every event also goes to one CSV file for the whole machine, for the question "what went wrong?" when you do not know which folder to look in:

  • macOS: ~/Library/Application Support/spoonstill/runs.csv
  • Windows: %APPDATA%\spoonstill\runs.csv
  • elsewhere: $XDG_CONFIG_HOME/spoonstill or ~/.config/spoonstill

Columns: when, level, scope, project, what happened, details, folder. Every field is quoted. Three engineering details:

  1. Formula injection. A spreadsheet treats a cell starting with =, +, - or @ as a formula even inside quotes, and the project column is the folder name, which the operator controls. A folder called =1+1 would become a live formula. defuse_formula prefixes such values with ', leaving real numbers like -16.0 alone (D-122).
  2. Locking across processes. Several renders may append at once. append_line takes the OS file lock (File::lock, stable in Rust since 1.89), decides whether the file is empty from the locked file's length, and writes header plus row in one write_all. Before this, four concurrent renders produced three header lines welded onto rows. On Windows the lock silently failed for months because an append-only handle lacks the access right LockFileEx needs; adding .read(true) to the open options fixed it (D-135).
  3. Rolling. At 16 MiB the file becomes runs-previous.csv and a fresh one starts.

8.4 Journal: two sinks as one

// crates/spoonstill-state/src/runs.rs:267-348 (abridged)
pub struct Journal { project: Option<FileLog>, machine: Option<ActivityLog> }

impl Diagnostics for Journal {
    fn record(&self, event: &Event) {
        if let Some(log) = &self.project { log.record(event); }
        if let Some(index) = &self.machine { index.record(event); }
    }
}

Journal::for_surface(path) opens the project log only if .spoonstill/ already exists, so running still validate ~/Pictures does not create state in your Pictures folder. Before Journal, combining two optional sinks was awkward enough that only the render command ever did it, and runs.csv recorded nothing else (D-148).

8.5 The diagnostics bundle

still diagnostics export writes one text file containing a plain-language header ("WHAT IS IN THIS FILE": paths and FFmpeg commands, but no keys, media or video), an ENVIRONMENT block (spoonstill version, OS, FFmpeg path and version, FFmpeg's configuration flags, the TTS tool status, usable hardware encoders, the raw PATH), and every JSON Lines log of the project. It is designed to be attached to a bug report.

8.6 Tests

20 unit tests, including credentials_never_reach_the_file, concurrent_writers_produce_one_header_and_whole_rows (8 threads x 40 rows, exactly one header), and the_log_handle_can_actually_be_locked.
