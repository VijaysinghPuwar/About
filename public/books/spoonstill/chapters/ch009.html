6 spoonstill-media: The Process Boundary

6.1 Why it exists

spoonstill-media is the only place where spoonstill touches the outside world through other programs. Its module comment states two rules:

  1. Argument vectors, never shell strings. Every invocation is a list of separate arguments, so a filename containing a space, a quote, $(...), an emoji or a newline is just data.
  2. Exit status is not validation. FFmpeg can return 0 for a broken join, so the crate checks outputs with ffprobe itself.

6.3 command.rs: one way to start a program

// crates/spoonstill-media/src/command.rs:116-160 (abridged)
pub struct FfmpegCommand {
    program: PathBuf,
    args: Vec<OsString>,
    progress: bool,
}
impl FfmpegCommand {
    pub fn arg(&mut self, arg: impl AsRef<OsStr>) -> &mut Self {
        self.args.push(arg.as_ref().to_os_string());
        self
    }
    /// Append an input file. Exists so `-i` and its path cannot drift apart.
    pub fn input(&mut self, path: &Path) -> &mut Self {
        self.arg("-i").arg(path)
    }
}

Despite the name, FfmpegCommand starts any program: FFmpeg, ffprobe, edge-tts, brew, winget. Arguments are OsString, not String, because file paths on Unix may contain bytes that are not valid UTF-8.

spawn() (lines 207-262) does four things:

  • builds a std::process::Command from the absolute program path, putting -progress pipe:1 first when progress was requested;
  • pipes all three standard streams (stdin is kept so the program can be asked to quit by writing q);
  • on Windows sets CREATE_NO_WINDOW so no console flashes up behind the window;
  • maps a "not found" spawn error to MediaError::BinaryMissing naming the exact path tried.

Two reader threads drain stdout and stderr immediately. Reading them one after another after the program exits can deadlock, because a child blocks when its output pipe's OS buffer fills. The stderr reader keeps only the last 256 KiB, because the cause of an FFmpeg failure is at the end and the head is banner text. The stdout reader either parses FFmpeg's key=value progress blocks and sends Progress values through a channel, or collects bytes (for ffprobe's JSON).

6.3.1 Waiting: polling with a backoff

std::process::Child has no portable "wait with a timeout", so waiting is a loop of try_wait and short sleeps. The sleep is clamp(waited / 8, 1 ms, 20 ms), where waited is the total time already slept. A short-lived ffprobe is noticed within a millisecond or two; a long encode is checked every 20 ms. This one change took still validate on 200 scenes from 11.82 s to 1.31 s when combined with parallel probing (D-149).

wait_until(limit) kills the child if the limit passes and returns MediaError::Timeout. The child is killed rather than abandoned because an orphaned FFmpeg writing a half-finished file is exactly the "valid-looking stub" the project forbids.

6.3.2 Cancellation

// crates/spoonstill-media/src/command.rs:339-370 (abridged)
#[derive(Debug, Clone, Default)]
pub struct Cancel(Arc<AtomicBool>);
impl Cancel {
    pub fn request(&self) { self.0.store(true, Ordering::SeqCst); }
    pub fn is_requested(&self) -> bool { self.0.load(Ordering::SeqCst) }
    pub fn sleep(&self, total: Duration) { /* sleeps in 20 ms steps,
                                              returns early if cancelled */ }
}

Cancel is a shared flag. The CLI's Ctrl-C handler and the window's Stop button each hold a clone and call request(). Workers check it. When a running FFmpeg must stop, cancel(grace) follows a ladder (D-045): write q to its stdin (FFmpeg's polite stop), poll for up to CANCEL_GRACE = 2 s, then kill(), then reap. Writing q was chosen over sending a signal because there is no portable way to signal a child on Windows.

6.3.3 Display quoting (for humans only)

display() produces a copy-pasteable command line for logs, quoted for POSIX shells on macOS and for PowerShell on Windows. It is never executed; a test asserts that the only process construction is Command::new(&self.program).

6.4 tools.rs: finding programs

A macOS app started from Finder gets a minimal PATH (/usr/bin:/bin:/usr/sbin:/sbin) that does not include Homebrew, so a bare ffprobe was not found and a folder of photos opened as zero scenes (D-103). locate(program) therefore searches PATH first and then a list of package-manager folders:

  • macOS: /opt/homebrew/bin, /usr/local/bin, /opt/local/bin (MacPorts), ~/.local/bin (pipx), every ~/Library/Python/*/bin (pip --user).
  • Windows: %LOCALAPPDATA%\Microsoft\WinGet\Links, the Gyan.FFmpeg winget package folders (which publish no shim, D-142), python.org's default install folders and their Scripts, Store Python, Program Files Python, Chocolatey, Scoop, pipx, Conda, and %APPDATA%\Python\*\Scripts (D-191).

If nothing matches, it returns the bare name so the spawn fails with a clear BinaryMissing. SPOONSTILL_FFMPEG, SPOONSTILL_FFPROBE and SPOONSTILL_EDGE_TTS override the search.

install() runs the platform's package manager (brew install ffmpeg, winget install --id Gyan.FFmpeg ...), with a 15-minute ceiling, and then re-locates and runs -version to confirm. It never downloads a binary from a URL (D-012). describe_failure turns the error into an honest sentence: a timeout says the install ran too long, not "not on this machine" (D-123).

6.5 probe.rs

ffprobe -hide_banner -v error -print_format json -show_format -show_streams
        [-count_frames] -i <path>

The JSON is parsed with serde_json into typed structs. A header probe has a 30 s ceiling; a probe that decodes every frame (-count_frames) gets 30 s + 5 ms per frame, capped at 20 minutes, because a fixed 30 s ceiling failed every scene of an hour-long test film (D-096). A timeout is retried once (D-179): nine of ten timeouts in a real log were a read-after-write stall on a network share.

6.6 profile.rs: the segment profile

SegmentProfile is the full description of a valid segment: container mov,mp4,..., codec h264, profile High, the derived level, yuv420p, tv, bt709, SAR 1:1, frame rate, time base 1/90000, AAC LC fltp 48 kHz stereo, stream order video then audio. assert_matches_profile compares every field against ffprobe's answer and returns all mismatches at once. An absent field counts as a mismatch, never a pass.

Why this matters is proven in ffmpeg-findings.md §5: concatenating a segment with SAR 30007:30000 between two segments with SAR 1:1 exits 0 with no warning, and the output claims SAR 1:1 for every frame. "FFmpeg is not a validator."

6.7 scene.rs: one segment

render_scene follows a strict sequence: probe the still and the narration, compute frames, choose the motion, build the filter, write any caption bands, run FFmpeg to a temporary file, validate it (decode every frame and check the exact count, plus the profile), and only then rename it into place. Chapter 15 shows the complete argument vector.

6.8 audio.rs, concat.rs, caption.rs, atomic.rs

These are covered in depth in Chapters 15 to 17. In brief:

  • audio.rs normalizes any audio to a 48 kHz stereo 16-bit WAV at -16 LUFS in two FFmpeg passes (measure, then write), generates exact-length silence, and measures files after checking that a WAV's header-declared size matches its length (D-190, which caught a truncated cache file that would have shortened a film silently).
  • concat.rs writes the concat list, runs ffmpeg -f concat -safe 0 -i list -c copy, and checks the film's profile, frame count and duration; if the film is short, it names and deletes the damaged segment so the next render rebuilds just that scene (D-178).
  • caption.rs rasterises subtitles with bundled fonts because the Homebrew FFmpeg has no drawtext or subtitles filter.
  • atomic.rs writes every artifact to a hidden .name.partial-<pid>-<n>.ext beside the destination and renames it at the end. Rust's rename replaces an existing file on both macOS and Windows, so readers always see the old file or the new one, never nothing (D-119). The Partial guard deletes its temporary on drop unless the rename succeeded.

6.9 hardware.rs

Listing ffmpeg -encoders tells you what FFmpeg was compiled with, not what works: one Windows machine listed seven H.264 encoders, of which four worked (D-159). detect actually encodes a tiny black clip with each candidate (h264_videotoolbox on macOS; h264_nvenc, h264_amf, h264_qsv, h264_mf on Windows). VideoEncoder is Software (libx264, the default) or Hardware(name), and quality_args maps CRF to each encoder's own quality flag, because -crf means nothing to them and VideoToolbox even counts quality the other way.

6.10 error.rs

MediaError has eleven variants, each naming the path, program or field involved: BinaryMissing, Spawn, Exit (with the retained stderr, indented with |), Timeout, Cancelled, UnreadableProbe, UnusableInput, ProfileMismatch (all mismatches listed), JoinStopped (which scene the film stopped at), Io, and Geometry. A From<GeometryError> implementation lets ? convert core's geometry errors automatically.

6.11 Tests

185 test functions. The integration tests render real media with the real FFmpeg: segment_integrity.rs (odd dimensions, hostile filenames like it's a $(pwd) name, cancellation leaves no stub, determinism), motion_matrix.rs (54 renders across durations, rates, aspects and source shapes, checking exact frame counts and no black edges), subtitles.rs, cut_short_audio.rs, probe_retry.rs, caption_hostile_text.rs, hardware_report.rs, and the structural no_shell_strings.rs.
