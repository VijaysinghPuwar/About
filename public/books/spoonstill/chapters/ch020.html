16 FFmpeg Integration in Depth

16.1 Why a separate program and not a library

spoonstill could have linked FFmpeg's C libraries through Rust bindings. Decisions D-011 and D-012 rejected that: the bindings were in maintenance mode and hard to build across platforms, a WebAssembly build is slow, and the ffmpeg-sidecar crate downloads FFmpeg automatically by default and lacked timeout-bounded probes. The chosen design: run the ffmpeg and ffprobe programs as child processes with argument vectors, and reimplement a small, careful process boundary.

The cost: one process per job, and FFmpeg must be installed. The benefits: no C toolchain, no unsafe FFI, any FFmpeg the operator has works, and a failure is isolated in a child process.

16.2 Shell injection, simply

A shell (bash, zsh, PowerShell) reads a command line and interprets special characters: spaces split words, ; starts a new command, $(...) runs a command, quotes group things. If a program builds one string and asks a shell to run it:

UNSAFE:  shell("ffmpeg -i " + user_filename + " out.mp4")

then a file named holiday; rm -rf ~.jpg is not a file name any more; it is a second command. That is shell injection.

The safe pattern never involves a shell. The program is started directly, and each argument is passed as a separate item:

// SAFE: what spoonstill does (crates/spoonstill-media/src/command.rs)
let mut command = std::process::Command::new(&self.program);  // absolute path
command.args(&self.args);                                      // Vec<OsString>

The operating system hands each item to FFmpeg as one argument, whatever characters it contains. spoonstill's test fixtures include files named it's a $(pwd) \name`,semi;colon &and& ampersand, leading space,-leading-dashand Unicode, andsegment_integrity.rsrenders through them and checks that no straypwd` file appeared.

Two more guards: a file named -leading-dash.jpg could be mistaken for an option, so every input goes through .input(path), which always writes -i before it; and no path ever enters the filter graph (captions are passed as inputs, not file names inside filter text), because characters like : and \ in a Windows path are filter syntax (no_path_ever_enters_the_filter_graph).

16.3 Finding the binary

Tools::from_env() resolves ffmpeg and ffprobe once per run to absolute paths (Chapter 6), honouring SPOONSTILL_FFMPEG and SPOONSTILL_FFPROBE. The same Tools value is used for every scene, so a 500-scene render cannot half-run on one FFmpeg build and half on another. Tools::ready() checks that the files exist and are executable without starting them; if not, validation reports one ToolingMissing problem with an install button, not one error per photo.

16.4 Running, watching, stopping

Concern How it is handled
Output pipes filling up stdout and stderr drained by threads from the start
Diagnosing failures last 256 KiB of stderr kept and attached to MediaError::Exit
Progress -progress pipe:1 key=value blocks parsed into Progress { frame, out_time_us, speed } and sent over a channel
Waiting try_wait polled with a backoff from 1 ms to 20 ms

Probe timeouts 30 s for headers; 30 s + 5 ms per frame when counting frames; retried once (D-096, D-179)
Install timeout 900 s for a package manager
TTS timeout 60 s + 30 ms per character, at most 900 s
Concat timeout 3 600 s
Cancellation write q to stdin, wait up to 2 s, then kill, then reap
Windows console flash CREATE_NO_WINDOW creation flag
Exit code Finished::ok() turns non-zero into MediaError::Exit with program name, code and stderr

The CLI's Ctrl-C and the window's Stop only set a flag. The ladder above happens inside the child wait, so every running FFmpeg gets the same treatment.

16.5 Temporary files and cleanup

Every output is written beside its destination with a hidden partial name and renamed at the end (atomic.rs). RAII guards remove temporaries on every exit path: Partial for films, Captions for caption band files, Scratch for TTS pieces. Leftover partials from crashed runs are swept, carefully: only names that exactly match spoonstill's pattern, and beside the film only if untouched for 60 seconds.

16.6 ffprobe as the source of truth

spoonstill uses ffprobe for four different questions:

  1. Is this file usable? During validation, with a 10 s ceiling, in parallel.
  2. How long is this narration? After normalization, on the WAV. Duration is never estimated from text or trusted from an MP3 header (D-021).
  3. Is this segment exactly what we asked for? After rendering, decoding every frame.
  4. Is this film exactly the sum of its parts? After the join, header only (decoding a 500-scene film would take minutes).

16.7 Software and hardware encoders

The default is libx264 in software (D-036). Measurements on three machines agree that the filter graph, not the encoder, is most of the cost at normal speeds: on macOS the encoder was about 14% of a 4K render (§12c); on a Windows desktop with an RTX 3060, NVENC made a render about 1.2x faster (§13c, D-162); on a slow Linux laptop CPU, Intel Quick Sync was 1.67x faster (D-198). Hardware encoders also saved no memory, because the memory is the CPU's prescale canvas.

--encoder auto picks the first usable hardware encoder found by actually encoding a test clip; --encoder off (the default) uses libx264; --encoder NAME must be in the usable list. Each encoder gets its own quality flags:

Encoder Quality arguments from preset/CRF
libx264 -preset <preset> -crf <crf> (unchanged since before D-162, so old caches stay valid)
h264_nvenc -preset p1..p7 -rc vbr -cq <crf> -b:v 0
h264_amf -quality quality -rc cqp -qp_i <crf> -qp_p <crf> -qp_b <crf>
h264_qsv -preset <preset> -global_quality <crf>
h264_mf -rate_control quality -quality <crf>
h264_videotoolbox -q:v <100 - crf x 100 / 51, clamped 1..100> (higher is better)

Hardware output was measured to produce exactly the same segment profile as software (High profile, level, yuv420p, tv, bt709, SAR 1:1, 1/90000), so hardware and software segments can be joined. The software segment key is byte-identical to the pre-D-162 key, so adding this feature re-rendered nothing for existing projects. VideoToolbox has not been measured.
