4 The Big Picture

4.1 The simple version

spoonstill is one Rust workspace (a group of packages built together) containing six library or binary crates under crates/ plus the desktop app under apps/desktop/. They are stacked in layers. Each layer may use the layers below it and never the ones above.

4.2 The real dependency graph

This graph is read directly from each crate's Cargo.toml (Verified from source). A solid arrow means "depends on"; the dashed arrows to spoonstill-core are there too, drawn lighter because every crate uses core.

Crate Kind Depends on (internal) Third-party crates
spoonstill-core library none none at all
spoonstill-media library core serde, serde_json, fontdue, harfrust
spoonstill-state library core none
spoonstill-tts library core, media none
spoonstill-app library core, media, tts, state serde, serde_yaml_ng, csv, sysinfo
spoonstill-cli binary still app, core clap, ctrlc (dev: toml)
spoonstill-desktop (apps/desktop) binary app, core tauri, tauri-plugin-dialog, tauri-plugin-opener, serde, serde_json (build: tauri-build)

4.3 Why these boundaries

Each boundary answers a question the design documents asked (decision D-010, "CLI-first Rust workspace; Tauri is a late thin shell"):

  • spoonstill-core depends on nothing so that the most important logic (the exact FFmpeg filter string, the frame arithmetic, the validation rules, path containment) is pure, fast to test, and cannot accidentally start a process or open a network connection. Its own lib.rs says: "if a type here needs to do I/O, it is the wrong type. Model the result of the I/O, and put the doing behind a trait."
  • spoonstill-media is the only crate that spawns processes. One place for argument vectors, timeouts, cancellation and retained stderr means one place to get them right.
  • spoonstill-tts sits above media (decision D-081) because the Edge provider is itself a child process (edge-tts) and should use the same process boundary rather than growing a second one.
  • spoonstill-state is small and below the app because logging must never depend on the business logic it records.
  • spoonstill-app holds all business logic so both control surfaces share it. This is why the CLI and the window behave identically.
  • The CLI and the window are thin adapters. They translate arguments or clicks into calls on spoonstill-app and translate results back into text or JSON.

4.4 How the rules are enforced

Rules written only in documents decay, so this project enforces the important ones with tests and CI:

  1. crates/spoonstill-cli/tests/architecture.rs reads every crates/*/Cargo.toml with the toml crate and assigns layers:
// crates/spoonstill-cli/tests/architecture.rs:25-38
fn layer(crate_name: &str) -> Option<u8> {
    Some(match crate_name {
        "spoonstill-core" => 0,
        "spoonstill-media" | "spoonstill-state" => 1,
        // D-081: TTS sits above the process boundary ...
        "spoonstill-tts" => 2,
        "spoonstill-app" => 3,
        "spoonstill-cli" => 4,
        _ => return None,
    })
}

Its five tests check that core has no dependencies; that core reaches nothing from a denylist (tauri, wry, reqwest, hyper, ureq, elevenlabs, azure, rusqlite, sqlx, keyring, ffmpeg, duct, subprocess); that every internal dependency points strictly downward; that the CLI does not depend on media, tts or state directly; and that every member's name starts with spoonstill-. A new crate that forgets to declare a layer makes the test panic.

  1. CI repeats the core check with cargo tree -p spoonstill-core -e normal | grep -iE 'tauri|reqwest|elevenlabs|rusqlite|keyring', failing if anything is found (.github/workflows/ci.yml).

  2. crates/spoonstill-media/tests/no_shell_strings.rs reads the media crate's source and fails if any file other than command.rs constructs a process, or if shell fragments like sh -c or cmd /c appear anywhere.

  3. unsafe_code = "forbid" in the workspace Cargo.toml applies to every crate (Chapter 22).

Docs and code disagree. apps/desktop/Cargo.toml says the desktop app's rule ("may not depend on spoonstill-media or spoonstill-state") is "enforced by crates/spoonstill-cli/tests/architecture.rs". It is not: that test only reads workspace_root().join("crates") (line 71), so apps/desktop/Cargo.toml is never inspected. Today the desktop manifest obeys the rule anyway (it depends only on spoonstill-app and spoonstill-core internally), but nothing mechanical holds it.

There is no database. The planning documents describe a SQLite state.db for milestone M3; it has not been built, and decision D-154 records that resume already works without it (Chapter 13).

4.6 Size of the codebase

Counted at this commit (wc -l): about 54 600 lines of Rust, TOML, JSON, HTML, CSS and JavaScript under crates/ and apps/, of which the largest files are spoonstill-app/src/film.rs (3 438 lines, the render path), apps/desktop/src/main.rs (2 921), apps/desktop/ui/app.js (2 823) and spoonstill-tts/src/edge.rs (2 732). A large share of every file is tests: there are 776 #[test] functions in the tree.
