15 The Video Pipeline: From Still to Moving Picture

15.1 The idea, simply

A photograph does not move. To make it feel alive, spoonstill makes a picture slightly larger than the screen and slides a window across it, or shrinks the window so the picture seems to come closer. Each output frame is what the window sees at that moment. Thirty slightly different windows per second look like smooth motion.

15.2 The real mechanism

spoonstill does not compute frames in Rust. It writes one FFmpeg filter chain (spoonstill_core::motion::build_filter) and FFmpeg executes it. Here is the exact string pinned by the test the_emitted_chain_is_exactly_the_documented_recipe for a 4000x3000 photo, 1920x1080 at 30 fps, ZoomIn 0.10 at Center, 112 frames (shown on several lines; the real string has none):

scale=5760:3240:force_original_aspect_ratio=increase:out_range=tv,
crop=5760:3240,
zoompan=z='1+0.100000*min(on/111,1)':x='(0.500000)*(iw-iw/zoom)':
        y='(0.500000)*(ih-ih/zoom)':d=112:s=1920x1080:fps=30,
setparams=range=tv:color_primaries=bt709:color_trc=bt709:colorspace=bt709,
setsar=1,format=yuv420p

15.2.1 Filter by filter

  1. Square-pixel correction (only sometimes). If the source's SAR is not 1:1, a first scale=W:H, stretches it to square pixels. A 720x576 image with SAR 16:11 becomes scale=1048:576, first.
  2. scale=5760:3240:force_original_aspect_ratio=increase:out_range=tv. Scale to the prescale canvas, three times the output (5760 = 3 x 1920). increase means "scale until the picture covers the box in both directions" (cover-fit), so it may overhang one side: 4000x3000 becomes 5760x4320. out_range=tv converts the JPEG's full colour range to limited range right here, at the first scaler (D-037).
  3. crop=5760:3240. Cut the overhang. With no x and y given, FFmpeg centres the crop. Now the canvas is exactly the output's shape, three times as large, with picture everywhere: the window can never show a black edge (D-034).
  4. zoompan=...:d=112:s=1920x1080:fps=30. For one input image, emit d=112 output frames of size 1920x1080. For each output frame number on (0 to 111), evaluate:
    • z (zoom): 1+0.1*min(on/111,1) rises from 1.0 to 1.1;
    • x, y (top-left corner of the window): a fraction times the legal travel iw - iw/zoom.
  5. setparams=range=tv:color_primaries=bt709:color_trc=bt709:colorspace=bt709. Pin all four colour properties. Encoder options alone left two of them unset in a measurement (ffmpeg-findings.md §7b).
  6. setsar=1 then format=yuv420p. setsar=1 must be last before the format conversion; an earlier setsar does not survive and a 1999x1001 source came out with SAR 30007:30000 (§4, D-033).

15.2.2 The motion maths

Progress is linear: p = min(on/(N-1), 1), from 0 on the first frame to exactly 1 on the last. There is no easing curve. N-1 is computed in Rust and written as a number, and a one-frame scene writes 0 instead, so FFmpeg never evaluates on/0 (which gives NaN and would break the crop silently).

Kind zoom z x fraction y fraction
ZoomIn 1 + a*p anchor x anchor y
ZoomOut 1 + a - a*p anchor x anchor y
PanRight 1 + a (constant) p anchor y
PanLeft 1 + a 1 - p anchor y
PanDown 1 + a anchor x p
PanUp 1 + a anchor x 1 - p

Anchors are fractions in [0, 1]: Center is (0.5, 0.5), NorthWest is (0, 0), SouthEast is (1, 1). Because the window's top-left x is always a fraction between 0 and 1 of the legal travel iw - iw/zoom, the window can never leave the canvas. As the source comment puts it, "There is no clamp because there is nothing to clamp."

Worked numbers for the pinned case:

  • Frame 0: zoom 1.0, the window is the whole 5760x3240 canvas, scaled down 3x to 1920x1080.
  • Frame 55: p = 0.4955, zoom 1.0496, the window is about 5488x3087, x about 136, y about 76.
  • Frame 111: p = 1, zoom 1.1, the window is about 5236x2945, x about 262, y about 147.

Even at the last frame, the window is scaled down by about 2.73x, so every output pixel still has more than one source pixel behind it. That is the purpose of the 3x prescale: at 2x, 280 of 300 frames were unique and the motion visibly stepped; at 3x, all 300 were unique; 4x and 6x improved nothing and were slower (ffmpeg-findings.md §1, D-032).

15.2.3 Why zoompan and not animated scale plus crop

A common alternative scales and crops per frame with eval=frame. Measured on this project's machine (§3): 4 s at 1080p30 took 8.32 s and 1 501 MB that way, against 1.08 s and 757 MB with zoompan, because the alternative re-resamples the whole prescaled image every frame while zoompan resamples only the window. A reference repository had switched away from zoompan to escape a different bug: using -loop 1 with zoompan and no frame limit produces frames forever (killed at 8 400 frames and 312 MB in a test). spoonstill avoids that by giving zoompan a single, non-looped still and d=N, so the frame count is structural (D-030, D-031).

15.3 The complete segment command

This command was captured from a real render log on the analysis machine (scene 001 of the fixture project, 960x540 output, paths shortened to <run>). It is the argument vector scene.rs builds, displayed with POSIX quoting:

/opt/homebrew/bin/ffmpeg -progress pipe:1 -hide_banner -nostats -loglevel warning -y
  -i <run>/renderable/img/001.jpg
  -i <run>/renderable/.spoonstill/cache/audio/file-6595651cd59129ac.wav
  -filter_complex '[0:v]scale=2880:1620:force_original_aspect_ratio=increase:out_range=tv,crop=2880:1620,zoompan=z='\''1+0.100000*min(on/111,1)'\'':x='\''(0.500000)*(iw-iw/zoom)'\'':y='\''(0.500000)*(ih-ih/zoom)'\'':d=112:s=960x540:fps=30,setparams=range=tv:color_primaries=bt709:color_trc=bt709:colorspace=bt709,setsar=1,format=yuv420p[v];[1:a]aresample=48000,apad,atrim=end_sample=179200,asetpts=N/SR/TB[a]'
  -map '[v]' -map '[a]'
  -frames:v 112
  -c:v libx264 -preset medium -crf 18
  -profile:v high -level:v 40
  -c:a aac -b:a 192k -ar 48000 -ac 2
  -video_track_timescale 90000
  <run>/renderable/.spoonstill/segments/.seg-b1e892e91177a56c.mp4.partial-16446-11.mp4

The '\'' sequences are only how a POSIX shell would spell an embedded single quote; the real argument contains plain ' characters, which are FFmpeg's own expression quoting. No shell ever sees this line.

Argument Why it is there
/opt/homebrew/bin/ffmpeg an absolute path found by tools::locate, never a bare name
-progress pipe:1 machine-readable progress on stdout, parsed by a reader thread
-hide_banner -nostats -loglevel warning keep stderr short so the retained tail is the useful part
-y overwrite the temporary without asking (FFmpeg would otherwise wait for an answer)
-i image input 0: the still. No -loop 1, no -framerate: zoompan d=N creates the frames
-i audio input 1: the normalized 48 kHz stereo WAV
-filter_complex the whole graph as one argument
[1:a]aresample=48000,apad,atrim=end_sample=179200,asetpts=N/SR/TB[a] resample defensively, pad with endless silence, cut at exactly 112 frames' worth of samples, restart timestamps at zero
-map [v] -map [a] output exactly those two streams, video first (order is part of the profile)
-frames:v 112 the frame count enforced a second time
-c:v libx264 -preset medium -crf 18 the default encoder and quality (D-036)
-profile:v high -level:v 40 pin the H.264 profile and the derived level so the encoder does not choose
-c:a aac -b:a 192k -ar 48000 -ac 2 AAC-LC, 192 kb/s, 48 kHz, stereo
-video_track_timescale 90000 one time base for every segment so they join cleanly
.seg-<key>.mp4.partial-<pid>-<n>.mp4 a hidden temporary beside the final name; the .mp4 ending lets FFmpeg pick the MP4 muxer

Things a reader might expect but that are not there: no -movflags, no -x264-params, no -color_range or -colorspace output flags (colour is pinned in the filter), no -r (the rate comes from zoompan fps=).

With captions on, each cue adds one raw-image input and one overlay (Chapter 18). With a hardware encoder, -c:v and the quality flags change (Chapter 16).

15.4 Validate, then rename

After FFmpeg exits 0, scene.rs does not trust it. It runs a counting probe (ffprobe -count_frames, which decodes every frame), checks the full SegmentProfile, and requires the decoded frame count to equal the planned count exactly. Only then does it rename the temporary to seg-<key>.mp4. If anything fails, the temporary is deleted and the scene fails with every mismatching field listed. A cancelled render never leaves a valid-looking file (tested by cancellation_leaves_no_valid_looking_stub).

15.5 Joining the film

When all segments exist, concat.rs writes a list file beside them, one line per segment:

file 'seg-21ecedf4779e604e.mp4'
file 'seg-84af12ca28a5ed0a.mp4'
...

Instead of escaping names, it refuses any name it did not generate: only ASCII letters, digits, -, _ and ., and not starting with a dot. Then:

ffmpeg -hide_banner -nostats -loglevel warning -y
  -f concat -safe 0 -i <segments>/.concat.txt.partial-16446-12.txt
  -c copy <run>/.film.mp4.partial-16446-13.mp4

-f concat uses the concat demuxer; -safe 0 allows the relative names (the list was written by spoonstill, so the "safe mode" protection against untrusted playlists is not needed); -c copy copies compressed packets without re-encoding, so joining 500 segments costs only disk I/O.

Then the film is checked with a header probe: the same profile, a declared frame count equal to the sum of the segments, a video duration within one frame, and a container duration within one frame plus one AAC frame (the 21.3 ms the muxer adds once per film, D-078). If the film is short, stopped_at finds the first segment where the running frame total passes the actual count, deletes that cached segment, and reports which scene it was (D-178):

// crates/spoonstill-media/src/concat.rs:119-128
pub fn stopped_at(segment_frames: &[u64], actual: u64) -> Option<usize> {
    let mut running = 0u64;
    for (index, frames) in segment_frames.iter().enumerate() {
        running = running.saturating_add(*frames);
        if running > actual {
            return Some(index);
        }
    }
    None
}

This was found in a real log: a segment damaged on a network volume still had a valid header, the cache accepted it, and FFmpeg stopped the join there with exit 0. Finally, cancellation is checked once more and the film is renamed into place.
