2 A First Render, From the Outside

Before reading any code, run the tool. Every command below was run for this book on the analysis machine (with the machine-wide state redirected to a scratch folder so the author's real logs were not touched).

2.1 Installing the pieces

spoonstill needs FFmpeg (and ffprobe, which comes with it). For spoken lines it also needs the edge-tts Python tool. It does not bundle either. still doctor checks both:

$ still doctor
  ok       ffmpeg - turning your photos into video
           9.0.1
  ok       edge - reading your written lines aloud

  graphics - hardware encoders this machine can run
    usable               Apple (VideoToolbox) (h264_videotoolbox)
    Films render on the CPU with libx264 (D-036) - the better picture on slow
    pans across smooth gradients. ...

(The real output uses long dashes; they are shown as hyphens here.) If something is missing, still doctor --install runs the platform's package manager for you: Homebrew on macOS, winget on Windows.

2.2 Making a project the easy way

$ still new demo land.jpg port.jpg n.wav
  001.jpg      land.jpg  +  n.wav
  002.jpg      port.jpg  +  silent
  2 photos, 1 narration paired, 1 silent

still new created the folder, copied the files in under numbered names, paired the one recording with the first photo, and wrote a small starter project.yaml:

# How each scene's Ken Burns move is chosen (D-153). ...
motion_seed: v2

Your originals are never moved or modified.

2.3 Checking it

$ still validate renderable
.../renderable - manifest scenes.csv
  6 scenes - 0 narrated, 2 supplied, 4 silent
     0  001                file    img/001.jpg
     1  002                file    img/002.jpg
     2  003                silent  img/003.jpg
     ...
  no problems

validate reports every problem at once, not just the first. It exits with status 1 if there is at least one error, so scripts can use it.

2.4 Rendering it

$ still render renderable --out film.mp4 --jobs 2
  6 scenes, 2 at a time (8 for audio)
  audio  003          silent    2.000s
  audio  001          file      3.717s
  ...
  [  1/6 done] 003              60 frames    2.000s
  [  2/6 done] unicode spaced   90 frames    3.000s
  ...
  [  6/6 done] 001             112 frames    3.733s
  joining 6 segments (stream copy, D-040)
.../film.mp4
  6 scenes, 541 frames, 18.055s (expected 18.033s)
  0 narrations from cache, 0 segments reused

Three details are worth noticing already:

  1. Lines finish out of order. Scene 003 finished first. Workers run in parallel, which is why the counter says [1/6 done] and not "scene 1": the word "done" is deliberate (D-091, D-140).
  2. Scene 001 is 112 frames, 3.733 s, for 3.717 s of narration. The frame count is rounded up so the narration is never cut off; the audio is padded with silence to fill the last frame (Chapter 3 and Chapter 15).
  3. The film is 18.055 s against an expected 18.033 s. The difference is exactly one AAC audio frame (1024 samples at 48 kHz = 21.3 ms), which the MP4 container adds once per film. spoonstill knows about this and allows it (D-078).

Run it again:

$ still render renderable --out film.mp4 --jobs 2
  ...
  6 narrations from cache, 6 segments reused

The second run did no encoding at all. It reused every normalized audio file and every segment, re-checked them, and re-joined them.

2.5 A spoken, captioned scene

$ echo "The harbour wakes slowly, one light at a time." > line.txt
$ still new spoken land.jpg line.txt
  001.jpg      land.jpg  +  line.txt (spoken)
$ still render spoken --out spoken.mp4 --subtitles boxed --voice en-GB-RyanNeural
  audio  001          tts       2.836s
  [  1/1 done] 001              86 frames    2.867s

Here spoonstill sent the text to edge-tts, received an MP3, normalized it, measured 2.836 s, computed 86 frames, drew the caption itself as an image, and asked FFmpeg to overlay it. Figure 2.1 shows three frames from that film: the picture slowly pans while the caption stays put.

2.6 Where things ended up

renderable/

  .spoonstill/                                  <- machine state, safe to delete
    render.lock                                 <- "pid 16501"
    logs/spoonstill-20261007.jsonl              <- every event of every run
    segments/seg-21ecedf4779e604e.mp4 ...       <- six cached segments
    cache/audio/file-64bbaa4704c542e8.wav ...   <- normalized narrations
                silent-1ec4b61a28ece966.wav ...

And a machine-wide activity log appeared at ~/Library/Application Support/spoonstill/runs.csv. Chapter 13 explains every one of these files.
