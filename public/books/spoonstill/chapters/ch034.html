29 Design Tradeoffs

Batch renderer versus timeline editor. Benefits: timing comes from the narration, so there is nothing to drag; scales to hundreds of scenes; scriptable and testable. Costs: no per-clip creative control, no transitions yet, no moving sources. The project's view is that its users want a finished film from a folder, not an editor.

CLI first versus GUI first. Benefits: every feature is testable in CI from day one; automation is free; the GUI cannot drift because it holds no logic. Costs: the window lagged behind the CLI and was built ahead of its milestone; some window behaviour is tested only at its seams.

FFmpeg as a subprocess versus a native library. Benefits: no C toolchain, no FFI unsafe, crash isolation, any FFmpeg works, commands are loggable and reproducible by pasting. Costs: a process per job, text parsing of progress and probes, the operator must install FFmpeg, and FFmpeg's version can change underneath (it moved from 8.0.1 to 9.0.1 during development; the version is now logged on every render).

Software versus hardware encoding. Benefits of libx264: identical output on every machine (good for caches and comparisons), better quality on slow gradients. Costs: slower, especially on weak CPUs (1.67x slower than Quick Sync on one laptop). Hardware is offered as an explicit draft mode.

Workspace crates versus one crate. Benefits: compiler-enforced boundaries, a pure core, faster incremental builds of leaf crates. Costs: more manifests, re-exports in spoonstill-app, and boundary rules that need their own tests.

External versus bundled FFmpeg. Benefits: no GPL redistribution problem; smaller downloads; the operator's package manager handles updates. Costs: a missing-tool experience to design for (Install buttons, still doctor), and builds the project did not test.

External versus built-in TTS. Benefits: free, high-quality neural voices; no protocol code to maintain in Rust; the tool's maintainers track Microsoft's changes. Costs: Python must be installed; an unofficial endpoint that can throttle or change; quality capped at 24 kHz mono.

Pure core plus traits versus direct I/O. Benefits: fast, deterministic tests with fakes (FakeFs, SkipProbe, injected clocks). Costs: more types and indirection.

Content-addressed cache versus a database. Benefits: resume and reuse are automatic and cannot disagree with the files on disk; .spoonstill/ can be deleted at any time. Costs: no queryable history per project (the logs and runs.csv partly fill that gap), and up to three generations of segments on disk.

Cross-platform abstractions versus platform code. The project chose portable mechanisms where they exist (stdin q instead of signals, Path instead of strings) and small, tested #[cfg] islands where the platforms truly differ (binary search folders, quoting, drag coordinates). The cost is that Windows-specific behaviour is mostly verified by CI and occasional sessions on a Windows machine, not by the primary developer's daily use.
