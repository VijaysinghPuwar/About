4 BreachScope, an Honest Live Threat Map

Public "cyber attack maps" are some of the most shared security images on the internet, and some of the least trustworthy. BreachScope is the author's answer to them: a live map of threat-intelligence records in which every dot can tell you who reported it, under what licence, when, and how precisely its location is known. This chapter walks through the whole system, from the Go code that politely pulls public feeds, through the Postgres schema built for a resumable live stream, to the React and MapLibre front end and the optional Azure honeypot that signs its own data.

BreachScope

At a Glance

BreachScope is a web console that shows cyber threats reported by public security feeds on a flat map or a 3D globe. A Go backend pulls six free threat-intelligence sources (plus two optional ones), works out where each reported IP address is, and serves one merged snapshot. A React front end draws that snapshot and lets you click any dot to see its full provenance (where the record came from). It is aimed at students, analysts and curious visitors who want to see real threat data without being misled by vendor marketing maps. The whole system runs for $0 a month on free tiers.

How It Works (Simple Version)

Imagine a newsroom that watches several wire services. Each wire service (a "feed") publishes a list of things it has spotted: a server that controls a botnet, a web address that hands out malware, a computer that keeps scanning the internet, a software flaw that criminals are actively using, a company that has just admitted a data breach.

BreachScope is the editor at that newsroom. Every few minutes the editor checks each wire, but never more often than the wire asks, and always asks "has anything changed since last time?" so the wire can simply answer "no". For each new item the editor looks up the address in a big printed atlas of internet addresses (the DB-IP database) to find the city. If the atlas only knows the country, the editor writes "country only" and refuses to invent a city.

The editor then pins every item on a wall map. Next to each pin is an index card listing the source, its licence, three different timestamps, how confident the source is, and how accurate the location is. Visitors to the newsroom do not each call the wire services. They all read the same wall map, which is photocopied once and handed out from a front desk (the CDN cache). So a thousand visitors cause the same number of wire checks as one visitor.

One rule makes BreachScope different from the famous attack maps: it only draws a line from A to B when it actually knows both A and B. A feed that says "this IP is bad" names one place, so it becomes a dot, not an arrow. The only arrows come from the author's own honeypot (a fake server that attackers try to break into), where the attacker's address and the target are both known for certain.

The pieces talk like this:

  • api/index.go is the Vercel entry point. Vercel rewrites every /api/* path to it, and the chi router inside dispatches on the original path.
  • pkg/app builds the router from configuration. Both the Vercel function and the local cmd/apiserver call the same app.Build, so production and Docker run identical code.
  • pkg/feeds holds one Source description per feed and a Hub that refreshes them, keeps the last good data in memory and builds the merged snapshot.
  • pkg/geoip turns an IP address into a city, country and network owner using DB-IP Lite files.
  • pkg/httpapi defines the routes and the JSON error format.
  • pkg/store, pkg/stream, pkg/db are the database tier: hand-written SQL, a server-sent events stream with resume, a small connection pool and migrations. They work and are tested, but the live site currently runs without a database and the browser uses /api/live.

Deep Dive

The security problem being addressed

Threat intelligence (information about attackers, their servers and their tools) is published by many free sources, but each one uses its own format and its own meaning. A ThreatFox record says "this IP:port was seen as a botnet command server". A DShield record says "this IP sent many packets to our sensors". A CISA KEV record says "this software bug is being exploited", with no location at all. A Have I Been Pwned record says "this company leaked this many accounts".

Popular attack maps flatten all of that into glowing arcs between countries. The planning document (plan.md, section 3) states the gap directly: public maps from big vendors "show one vendor's sensors as arcs plus a feed. Their public pages do not show provenance, confidence, drill-down or replay." BreachScope's thesis is that a security tool should never overstate what it knows. That idea drives almost every design choice below: the data-class badges, the geo_method field, the refusal to draw country-centre dots, and the "arcs only when both ends are known" rule.

Data classes: one vocabulary for six very different feeds

Every record carries a data_class. The set is fixed in three places that must agree: a Postgres CHECK constraint, a Go validation map in pkg/store/events.go, and the front end's classCodes table in web/src/data/live.ts.

data_class UI badge Meaning Drawn as
indicator IOC Reported as malicious, not an observed attack Point
aggregate_telemetry AGG A third party's counted observations Point (DShield), list only (Radar)
telemetry TEL Seen directly on our own sensor Arc to the sensor
vulnerability KEV Exploited CVE, not geographic Timeline and Reports
breach_report BRCH Public breach disclosure Reports and alerts
simulated SIM Demo data Off by default

An IOC (indicator of compromise) is a piece of evidence such as an IP, URL or file hash that is associated with malicious activity. The badge exists because "this IP was reported" and "this IP attacked us" are very different claims, and the UI must never let one pass for the other.

Data sources and how each is parsed

pkg/feeds/sources.go defines the default sources. Each Source is a plain struct: a name, data class, licence, the URL to fetch, a minimum refresh interval, an optional Verify function and a Parse function that turns the response body into store.Event values.

The parsers encode a surprising amount of security judgement:

  • ThreatFox. The threat_type decides the category and severity: botnet_cc becomes "C2 server" at severity 3, payload_delivery severity 2, anything else "Malware indicator". A C2 (command and control) server is the machine that sends orders to infected computers. Only ip:port indicators are geolocated. URL indicators are stored defanged, domains have their dots replaced with [.], and hashes are kept as attributes.
  • URLhaus. A malware URL is severity 2 if it is still online, else 1. If the URL's host is a literal IP, it is located; if it is a domain name, it is not resolved.
  • Feodo Tracker. Verified botnet C2 servers (for families such as Dridex or Emotet). Online servers are severity 3. last_online becomes observed_at and first_seen becomes reported_at.
  • DShield. The SANS Internet Storm Center's list of top attacking sources. Severity rises to 2 at 100,000 reports. The confidence basis string records both numbers, for example "Seen by DShield sensors: N reports against M targets". The parser also fixes a quirk: some DShield endpoints zero-pad IPv4 octets (079.124.059.078), which Go's strict netip parser rejects, so trimOctets strips the padding first.
  • CISA KEV. The Known Exploited Vulnerabilities catalogue. Only entries added in the last 30 days are kept. Every entry is severity 3, raised to 4 when knownRansomwareCampaignUse is Known. Confidence is 100 because CISA is the authority for this list.
  • Have I Been Pwned. Breaches added in the last 90 days. Fabricated breaches, spam lists and sensitive breaches are skipped. Severity comes from breachSeverity: any leak of passwords, card data, bank numbers, government IDs or social security numbers is severity 4 regardless of size; otherwise 1M or more records is 3, 100k or more is 2. Verified breaches get confidence 100, unverified ones 50.

Two caps keep the snapshot small: recentWindow (48 hours) for the large abuse.ch exports, perSourceCap (1,200) so one busy feed cannot crowd out the others, and MaxEvents (3,000) for the merged result.

Here is the helper that makes malicious URLs safe to display:

// defang makes a malicious URL safe to display and
// impossible to click by accident: http becomes hxxp and
// the dots in the host become [.].
func defang(raw string) string {
    u, err := url.Parse(raw)
    if err != nil || u.Host == "" {
        return strings.ReplaceAll(raw, "http", "hxxp")
    }
    host := strings.ReplaceAll(u.Host, ".", "[.]")
    scheme := strings.Replace(u.Scheme, "http", "hxxp", 1)
    rest := strings.TrimPrefix(raw, u.Scheme+"://"+u.Host)
    return scheme + "://" + host + rest
}

"Defanging" is a standard analyst convention: http://evil.example/x becomes hxxp://evil[.]example/x. Browsers and chat apps will not turn it into a live link, so nobody infects themselves by clicking a record. It is applied on the server, so no client can forget to do it.

Stable event identifiers

Every event needs an ID that is the same each time the same upstream record is seen, so the browser can merge polls without duplicates and the database can ignore re-ingested rows. uid in pkg/feeds/hub.go hashes source + "|" + upstream id with SHA-256 and formats the first 16 bytes as a UUID, setting the version and variant bits so it looks like a name-based UUID (a UUID derived deterministically from a name rather than at random). The upstream ID differs by feed: ThreatFox's numeric ID, Feodo's IP, DShield's ip|lastseen, KEV's CVE number, HIBP's breach name, the sensor's ip|protocol|hour.

The refresh engine: feeds.Hub

Hub is the heart of the backend. It holds per-source state (sourceState): the last events, the last attempt time, the last success time, the last error, and the ETag and Last-Modified values from the previous response.

func (h *Hub) Snapshot(ctx context.Context) Snapshot {
    h.mu.Lock()
    done := h.refresh
    if done == nil && h.anyDue() {
        done = make(chan struct{})
        h.refresh = done
        go h.runRefresh(done)
    }
    h.mu.Unlock()

    if done != nil {
        select {
        case <-done:
        case <-ctx.Done():
        }
    }
    return h.build()
}

This is a "single-flight" pattern: no matter how many requests arrive, at most one refresh runs. The refresh field is a channel that exists only while a refresh is running. The first caller that finds a source past its MinInterval creates the channel and starts the refresh in a goroutine (Go's lightweight thread). Every other caller sees the existing channel and waits on it. When the refresh finishes it closes the channel, which wakes all waiters at once. If a visitor's request context ends first (they closed the tab), that visitor gets whatever is in memory and leaves; the refresh keeps going.

runRefresh deliberately runs on context.Background() with a 45-second timeout, not on the visitor's context. The comment explains: "a slow feed should finish and be cached even if the visitor who triggered it has gone." Inside, every due source is fetched in parallel with a sync.WaitGroup. Each result updates state under the mutex with three outcomes: an error keeps the old events and records lastError; a 304 Not Modified counts as a success and keeps the old events; a new body replaces the events and stores the new validators.

The test TestHubIsPoliteToFeeds proves the behaviour with a fake clock and a fake server: 20 concurrent Snapshot calls cause exactly one upstream hit; a call inside the interval causes none; a call after the interval sends If-None-Match and gets a 304 with data kept; a 429 response is reported as last_error while the last good data stays on screen. The same test checks that the User-Agent names the project and includes a contact address, because DShield asks for that.

Fetching politely

pkg/feeds/fetch.go builds each request. It sets a User-Agent with the project URL and a contact address, Accept: application/json, any per-source headers (the Radar bearer token), and the conditional headers If-Modified-Since and If-None-Match. These conditional headers let the server reply with a tiny 304 instead of resending a 20 MB file. The body is read through io.LimitReader capped at 64 MB, because the largest feed (URLhaus recent) is about 20 MB and an unbounded read could exhaust memory if a feed misbehaved. If a source has a Verify function, it runs before parsing, so tampered data never reaches the parser.

Encode once, serve many

Under local load testing, the hot path turned out not to be the feeds but JSON encoding: the comment in hub.go records that encoding 2,000+ events per request capped throughput at about 60 requests a second. The fix is a version counter. Every refresh bumps h.version. EncodedSnapshot keeps the last JSON bytes, their gzip form and an ETag, and rebuilds them only when the version has changed.

body, err := json.Marshal(h.buildLocked())
if err != nil {
    return nil, err
}
var buf bytes.Buffer
zw, _ := gzip.NewWriterLevel(&buf, gzip.BestSpeed)
if _, err := zw.Write(body); err != nil {
    return nil, err
}
if err := zw.Close(); err != nil {
    return nil, err
}
sum := sha256.Sum256(body)
h.encoded = &Encoded{JSON: body, Gzip: buf.Bytes(),
    ETag: fmt.Sprintf(`"%x"`, sum[:12])}
h.encodedVersion = h.version

The ETag (entity tag, a fingerprint of the response) is the first 12 bytes of the body's SHA-256. The README reports the snapshot going from 1.4 MB to 175 KB after gzip. The live handler in pkg/httpapi/router.go then does three cheap things: answers 304 if the browser's If-None-Match matches, sends the pre-gzipped bytes if the client accepts gzip, and sets Cache-Control: public, max-age=30, s-maxage=120, stale-while-revalidate=600. That header tells Vercel's CDN it may serve the same bytes for two minutes and keep serving a stale copy for ten more while it fetches a fresh one in the background. In practice most page views never reach the Go function at all, so they never reach the feed operators either.

Geolocation: honest by construction

pkg/geoip/geoip.go wraps DB-IP Lite, a free IP-to-location database under CC BY 4.0. The files use the MaxMind .mmdb format: a binary search tree over IP ranges, so a lookup is a handful of memory reads and needs no network call. There are two files: city (country, city, coordinates) and ASN. An ASN (autonomous system number) identifies the network that announces an IP range, such as a hosting company or ISP.

The important logic is in Lookup:

func (d *DB) Lookup(ip netip.Addr) (loc Location, ok bool) {
    if d == nil || !ip.IsValid() ||
        !ip.IsGlobalUnicast() || ip.IsPrivate() {
        return loc, false
    }
    var rec cityRecord
    err := d.city.Lookup(ip.Unmap()).Decode(&rec)
    if err != nil || rec.Country.ISOCode == "" {
        return loc, false
    }
    loc.CountryCode = strings.ToUpper(rec.Country.ISOCode)
    loc.CountryName = rec.Country.Names["en"]
    loc.City = rec.City.Names["en"]
    // DB-IP also carries coordinates for country-only
    // records (the country's centre); never draw those.
    if rec.Location.Latitude != nil &&
        rec.Location.Longitude != nil && loc.City != "" {
        loc.Lat, loc.Lon = *rec.Location.Latitude, ...
        loc.HasPoint = true
    }
    ...
}

Private, loopback and link-local addresses are never looked up. A result counts as city-level only when it has both a city name and coordinates. DB-IP stores the centre of the country for records it cannot place more precisely, and drawing that would pile fake dots in the middle of Kansas or central Russia. So such records get geo_method = dbip_country and no coordinates, and the front end shades the country polygon instead. Location.Method returns one of dbip_city_lite, dbip_country or none, and every event carries it. DB-IP Lite publishes no accuracy radius, so geo_accuracy_km is left empty rather than guessed.

One more principled choice: URLs and domains are never DNS-resolved to find their IP. pkg/feeds/NOTES.md explains that resolving would contact infrastructure run by the people being tracked, and the answer changes with the resolver and the time.

The geo database has two loading paths, chosen with a Go build tag (a compile-time switch that includes or excludes files). Vercel's Go runtime does not ship extra files next to a function, so the production build downloads the databases into pkg/geoip/embedded/ and compiles with -tags geoembed, which activates embed_on.go and its //go:embed directives. Without the tag, embed_off.go is used and app.openGeo searches GEOIP_DIR, geo/, ../geo and the executable's folder. If no database is found, the feeds still work and events simply carry no location; /api/healthz reports the reason in its geo field.

Cloudflare Radar and the arcs that were removed

pkg/feeds/radar.go reads Cloudflare Radar's Layer 7 "top attacks" endpoint, which lists origin and target country pairs with their share of mitigated application-layer attack traffic over 24 hours. It is enabled only when CLOUDFLARE_API_TOKEN is set. Each pair is placed using country label points from Natural Earth (embedded as centroids.json) and tagged geo_method = country_centroid. Severity is 3 at a 10% share or more and 2 at 3% or more.

The project's history shows the rule against overstatement tightening. Commit 48ae260 added Radar country-pair arcs to the map. Commit e2ef88d ("Draw only exact arcs") then removed them: "Country pairs from Cloudflare Radar name countries, not places, so they are listed in the feed and no longer drawn on the map." In web/src/lib/geometry.ts, mapFeatures now skips any event with a pair outright.

The honeypot sensor and Ed25519 signatures

The only data that becomes an arc on the map comes from the author's own Cowrie honeypot. Cowrie is an open-source fake SSH and Telnet server that pretends to be a vulnerable Linux box and logs everything attackers type. Because the sensor saw the connection itself, both ends of the line are known.

infra/azure/main.tf creates a resource group, a virtual network, a network security group (NSG, Azure's cloud firewall), a static public IP and a Standard_B1s Ubuntu VM, plus a budget alert. A tls_private_key resource generates an Ed25519 key pair. Ed25519 is a modern digital signature scheme: whoever holds the private key can sign data, and anyone with the public key can check the signature but cannot forge one.

On the VM, exporter.py reads Cowrie's JSON logs, groups the last 48 hours by attacker IP, protocol and hour, counts sessions, login attempts, successful logins and commands, keeps the three most common usernames, and serves it on GET /events (port 8443). Passwords attackers try are never exported. Each response is signed:

body = body_now()
stamp = str(int(time.time()))
signature = KEY.sign(stamp.encode() + b"." + body).hex()
self.send_response(200)
self.send_header("Content-Type", "application/json")
self.send_header("Content-Length", str(len(body)))
self.send_header("X-Timestamp", stamp)
self.send_header("X-Signature", signature)

On the Go side, verifySensor in pkg/feeds/sensor.go recomputes the same message (timestamp + "." + body), checks it with ed25519.Verify against a public key embedded in the binary from sensor_pubkey.pem, and then refuses any response more than 10 minutes old (or more than a minute in the future). Including the timestamp inside the signed message is what stops replay: an attacker who captured an old valid response cannot resend it later, because its signed timestamp would be stale.

parseSensor turns each group into a telemetry event: ssh_bruteforce or telnet_login, severity 3 if the attacker got into the fake shell or ran commands, 2 at 20 or more login attempts, else 1. The destination is set to the published centre of the Azure East US region, with attrs.sensor = "configured · Azure East US", so the UI says the target position is configured, not geolocated.

In this checkout sensor_pubkey.pem is empty and sensorDefaultURL is "", so the sensor source stays switched off until the author runs Terraform and commits the two public values (or sets SENSOR_URL for testing). The design means no secret ever has to be stored in Vercel.

HTTP API

pkg/httpapi/router.go defines five routes under /api:

Route Purpose
GET /api/live Merged feed snapshot, CDN-cacheable, gzip, ETag
GET /api/healthz Always 200 with status, db, geo, version
GET /api/events Cursor-paged events from Postgres, with filters
GET /api/stream Server-sent events with resume
GET /api/sse-test One tick a second, no database, for streaming proofs

Middleware assigns every request an ID (chi/middleware.RequestID), copies it into an X-Request-ID response header, and recovers from panics. Every error is JSON of the form {"error": "...", "request_id": "..."}, including the 404 for unknown routes. The front end shows that ID in its error banner, so a user can quote it and the author can find the exact log line.

/api/healthz always returns 200 on purpose, so an uptime checker can tell "API up, database down" apart from "API down". It pings the database with a 5-second timeout, long enough for Neon (a serverless Postgres host) to wake from autosuspend.

/api/events parses after, limit (1 to 1000, default 200), class (comma list), min_severity, country and asn (64500 or AS64500). parseFilter rejects malformed numbers, and Filter.Validate checks every value against fixed rules before SQL ever sees it.

Database schema

pkg/db/migrations/0001_init.sql defines the schema planned for the full product. The core tables are:

  • source: one row per feed, with data_class (CHECK-constrained), licence, attribution, min_interval, provides_pairs and freshness columns.
  • category: a small lookup table seeded with labels such as ssh_bruteforce, c2_server, known_exploited_vuln and breach_disclosure.
  • event: one observation. seq is a bigint GENERATED ALWAYS AS IDENTITY primary key used as the stream cursor. event_uid is uuid UNIQUE. There are columns for severity (CHECK 0 to 4), confidence (0 to 100) with a required confidence_basis, three timestamps (observed_at, reported_at, ingested_at) plus valid_until, source and destination location, geo_method, geo_accuracy_km, an h3_r3 cell (H3 is Uber's hexagonal grid; resolution 3 cells are roughly 12,000 square kilometres) and a jsonb attributes column. Two CHECK constraints refuse half a coordinate: (src_lat IS NULL) = (src_lon IS NULL) and the same for the destination.
  • rollup_hourly: hourly counts kept after raw events are pruned, with UNIQUE NULLS NOT DISTINCT so a NULL country is treated as one value and upserts work.
  • app_user, user_role, investigation, investigation_event, investigation_share: identity, role-based access and saved investigations. investigation_event stores a JSON snapshot of each pinned event so pruning never breaks an investigation.
  • anomaly: robust z-score results with every input number stored, so the UI can show its working.
  • ingest_nonce: one-time values for replay protection on pushed batches.

Four indexes back the expected queries: observed_at DESC for the newest-first feed; (category, severity, src_country, observed_at DESC) for the common filter; (src_asn, observed_at DESC) for "everything from this network"; and a GiST index on src_ip inet_ops. GiST is a Postgres index type for non-scalar data, and with inet_ops it lets a query like src_ip << '198.51.100.0/24' ("inside this subnet") use the index.

The identity, investigation and anomaly tables exist in the migration but no Go code uses them yet. CLAUDE.md and plan.md describe Auth0 OIDC with PKCE, JWT checks, per-object authorization and a robust-z anomaly job as later milestones.

Hand-written SQL and cursor paging

pkg/store/events.go reads events with one query:

SELECT e.seq, e.event_uid::text, s.name, s.data_class, ...
       abbrev(e.src_ip), e.src_asn, e.src_country, ...
FROM event e
JOIN source s   ON s.id = e.source_id
JOIN category c ON c.id = e.category
WHERE e.seq > $1
  AND (cardinality($2::text[]) = 0 OR s.data_class = ANY($2))
  AND e.severity >= $3
  AND ($4 = '' OR e.src_country = $4)
  AND ($5 = 0 OR e.src_asn = $5)
ORDER BY e.seq
LIMIT $6

This is cursor paging (also called keyset pagination): instead of OFFSET 400, which makes Postgres scan and discard 400 rows and shifts when new rows arrive, the client passes back the last seq it saw. The ($4 = '' OR ...) pattern lets one statement shape serve every combination of filters: an empty value switches that filter off. All values are bind parameters, so there is no string-built SQL and no injection path. abbrev(src_ip) prints a single host as 198.51.100.23 instead of 198.51.100.23/32. Nullable columns scan into Go pointers and are omitted from JSON when NULL, because "unknown" and "zero" are different facts.

The ordering problem and the advisory lock

InsertEvents in pkg/store/write.go solves a subtle bug that breaks most naive "poll for id > last" designs:

// Why the advisory lock: seq comes from an identity
// column, so two writers can take seq 104 and 105 and
// commit 105 first. A stream reader polling "seq > 103"
// would then see 105, move its cursor past 104, and
// never see 104. Holding one transaction-scoped lock for
// every writer makes commit order equal seq order.
err := pgx.BeginFunc(ctx, s.pool, func(tx pgx.Tx) error {
    _, err := tx.Exec(ctx,
        `SELECT pg_advisory_xact_lock($1)`, writerLockKey)
    if err != nil {
        return fmt.Errorf("take writer lock: %w", err)
    }
    for _, e := range evs {
        // INSERT ... ON CONFLICT (event_uid) DO NOTHING
    }
    return nil
})

An advisory lock is a named mutex that lives inside Postgres; pg_advisory_xact_lock holds it until the transaction ends. Every writer takes the same key, so writers commit one at a time and a reader can never see a later seq before an earlier one. ON CONFLICT (event_uid) DO NOTHING makes ingest idempotent (running it twice has the same effect as once). It also consumes seq values, so seq has gaps and is only ever used as a cursor, never as a count.

pkg/db/db.go adds serverless-specific tuning. The pool keeps at most 4 connections and drops idle ones after 30 seconds, because a frozen function instance would otherwise hold Neon connections. It uses QueryExecModeExec, because Neon's pooled URL goes through PgBouncer in transaction mode, where a server-side prepared statement created on one backend connection may not exist on the next. Migrations take a session advisory lock (pg_advisory_lock) so two deploys starting together run one at a time, which is why cmd/migrate prefers the unpooled URL.

The resumable SSE stream

pkg/stream/stream.go implements server-sent events (SSE): a normal HTTP response with Content-Type: text/event-stream that stays open while the server writes small text messages. Each message has id:, event: and data: lines and a blank line. The browser's built-in EventSource remembers the last id and, when the connection drops, reconnects automatically with a Last-Event-ID header.

The handler picks a starting cursor (Last-Event-ID wins over ?after=; with neither it starts at max(seq) so a new client only gets new events), sends retry: 1000, then loops. Every second it asks Postgres for seq > cursor. If a full batch of 500 comes back it asks again immediately, so a client that reconnects far behind catches up quickly. Each batch is sent with id: <last seq in batch>. An idle connection gets a : ping comment every 15 seconds so proxies do not drop it. At 280 seconds the context deadline fires, the handler sends event: close with {"reason":"max_duration"}, and returns. Vercel's Hobby plan kills functions at 300 seconds, so a planned close at 280 leaves 20 seconds of headroom. The server keeps no state between connections, so any instance can serve the reconnect.

reconnect_integration_test.go is the proof. It starts a real Postgres 16 in Docker with Testcontainers, runs four writers inserting 1,200 events (half the batches sent twice to exercise idempotency), and has a client drop its connection at random points and reconnect with Last-Event-ID. It then compares the set of event_uid values the client received with the set in the database and passes only with zero missing and zero duplicates. It compares sets, not seq numbers, because seq has holes.

/api/sse-test and cmd/ssecheck exist to prove one risky assumption from the plan: that a Go function on Vercel can hold an SSE connection for the full 280 seconds. ssecheck reconnects for an hour and reports connection lengths and missing ticks.

Front end: data flow

The React app polls rather than streams for now. web/src/lib/useLiveFeed.ts calls getLive (in lib/api.ts) every 60 seconds with a 20-second abort timeout. On failure it backs off to 5, 15 and then 60 seconds. It pauses entirely while the tab is hidden (visibilitychange), aborting any request in flight, and polls again when the tab returns. getLive validates the response shape before trusting it: arrays present, generated_at parseable, every event with a string event_uid, a known data_class and an integer severity 0 to 4. A bad response becomes a LiveError carrying the request ID.

mergeEvents in lib/live.ts unions the previous and incoming events by event_uid with a Map, sorts newest first and caps at 3,000. It also returns newIds, the set of IDs not seen before, which drives arrival ripples on the map and the arrival toast. On the very first load newIds is empty, so the page does not "arrive" all 3,000 events at once.

toObservation in data/live.ts converts the wire format to the UI model. It sets coordinates only when the event is not a KEV or breach, the method is dbip_city_lite and both numbers are finite. It sets pair only for country_centroid events. isStale marks a source stale when its last success is older than max(24 h, 2 x min_interval), the same freshness rule plan.md defines.

Front end: the map

web/src/map/MapCanvas.tsx creates a single MapLibre GL map. MapLibre is an open-source WebGL map renderer. The flat/globe toggle calls map.setProjection({ type: 'mercator' | 'globe' }) on the same map, so the centre, zoom, filters and selection survive the switch. The base map at low zoom is Natural Earth land, country and label GeoJSON served from the site itself (built by web/scripts/build-geo.mjs); from zoom 4 OpenFreeMap vector tiles fade in for street-level detail (map/detail.ts). A MapErrorBoundary and commit c3ea6fa keep the map up when a tile fails to download.

lib/geometry.ts builds the GeoJSON layers. mapFeatures emits a point per located event, an accuracy circle when geo_accuracy_km is set, and an arc only for TEL events whose destination is the sensor. greatCircle computes the shortest path on a sphere by converting both ends to 3D unit vectors, finding the angle between them, building an orthogonal tangent (with a fallback for antipodal points, where the shortest path is not unique), and stepping along the circle in 96 steps. splitAntimeridian then cuts the line where longitude jumps across 180 degrees, otherwise MapLibre would draw the segment the long way around the world.

On the globe, arcs are clipped to the visible hemisphere (clipToHemisphere) and re-clipped as the globe turns, at most once per frame. map/arcFlow.ts animates a short bright "head" moving from source to target every 4.2 seconds so the direction is readable. Each arc gets a stable phase from an FNV-1a hash of its ID so they do not pulse together, and the animation stops entirely under prefers-reduced-motion or while the tab is hidden.

Leaving Earth is intentionally hard. The wheel handler in MapCanvas.tsx only hands over to the space view after the globe has sat at minimum zoom for 400 ms and enough further wheel distance and steps have accumulated, so a single fast flick never jumps (commit dfc0da1, "Make leaving Earth deliberate").

Front end: the space view

web/src/space is a three.js scene that continues the zoom from 10 km out to 10^27 metres: Earth and Moon, real planet positions from JPL orbital elements solved with Kepler's equation (astro.ts), nearby stars and galaxies at their J2000 sky coordinates. It is loaded with React.lazy and preloaded in requestIdleCallback so it costs nothing on first paint.

The interesting engineering problem is precision. GPUs use 32-bit floats, which keep about 7 significant digits, which is useless across a 10^23 range. The engine computes positions in 64-bit JavaScript numbers relative to the camera's target, divides by the camera distance, and hands the GPU only numbers near 1. Textures are drawn procedurally on an OffscreenCanvas in a Web Worker and swapped in nearest first; space/NOTES.md records that opening the view went from a 649 ms main-thread freeze to 83 ms. Every textured material starts with a 1x1 blank texture so swapping in the real one reuses the already-compiled shader.

Front end: guide, pages and accessibility

components/Onboarding.tsx shows a welcome card and an optional six-step tour. Tour targets are found by data-tour attributes that sit on different elements at each screen size, and steps whose target is not on screen are dropped, so one list works on desktop, tablet and phone. The "seen" flag lives in localStorage wrapped in try, because private windows can block storage. A deep link /?event=<uid> skips the welcome. Routes are / (Console), /reports, /status, /about and /space.

Build, packaging and deployment

vercel.json is the whole deployment description. The install step is npm ci --prefix web. The build step runs scripts/fetch-geo.sh pkg/geoip/embedded (download this month's DB-IP files, falling back to last month early in a month) and then npm run build --prefix web. GO_BUILD_FLAGS sets -ldflags '-s -w' -tags geoembed, which strips debug symbols and compiles in the databases. Rewrites send /api/(.*) to the Go function and every other path to index.html for client-side routing. maxDuration is 300 seconds for the stream.

The Dockerfile is a two-stage build: golang alpine to compile static (CGO_ENABLED=0) apiserver and migrate binaries, then gcr.io/distroless/static-debian12:nonroot, an image with no shell or package manager, running as a non-root user. compose.yaml runs Postgres 16 and the API for local work; Vite's dev server proxies /api to port 8080.

Two path names are deliberate workarounds recorded in api/NOTES.md. Shared code lives in pkg/, not internal/, because Vercel compiles index.go inside a generated wrapper module and Go forbids importing another module's internal/ packages. The local server is cmd/apiserver, not cmd/api, because Vercel treats cmd/api/main.go as a signal to deploy the whole project as a Go server, which would replace the static site.

CI (.github/workflows/ci.yml) runs two jobs. The Go job runs go vet, staticcheck, govulncheck (known-vulnerability scan of dependencies), go test -race with Testcontainers Postgres, and a Docker build. The web job runs type checking, ESLint, Vitest, a production build and the Playwright suites, uploading screenshots on failure. Workflow permissions are contents: read.

Key Design Decisions and Trade-offs

  • Go for the backend. plan.md justifies Go by job-description analysis (the most requested language the author did not yet have, stronger at security companies), its fit for concurrent polling and streaming, and the fact that one binary runs on Vercel and in a container unchanged. C++ was explicitly rejected with a table showing that load time, latency and frame time are dominated by bytes, Postgres and draw calls, not CPU.
  • A snapshot in memory before a database. The planned architecture was Postgres plus SSE from day one. What shipped first is a database-free /api/live snapshot. The trade-off: no history or replay yet, but zero database cost, no cold starts from Neon, and the CDN can cache the whole response. The database tier is built and tested so the next stage can swap in without redesign.
  • CDN caching instead of a scheduler. Vercel Hobby cron runs at most daily, and the plan notes that GitHub Actions' terms forbid using it as part of a serverless app. Refreshing lazily on request, combined with s-maxage and stale-while-revalidate, gives near-live data without any scheduler.
  • Polling at 60 s instead of SSE in the browser. The feeds themselves update every 5 to 60 minutes, so a 60-second ETag poll is effectively free (usually a 304 from the CDN). SSE is reserved for the database stage, where honeypot events can arrive in real time.
  • SSE instead of WebSocket. The data flows one way, SSE is plain HTTP, has built-in resume through Last-Event-ID, and fits Vercel's 300-second limit with a planned reconnect. WebSocket support on Vercel was beta and two-way messaging was unnecessary.
  • DB-IP Lite instead of MaxMind GeoLite2. The plan preferred GeoLite2 because it publishes an accuracy radius, but GeoLite2 requires an account and licence key, and shipping it to Vercel needed blob storage. DB-IP Lite needs no account and could be compiled in. The cost is no accuracy radius, which the UI states honestly rather than inventing one.
  • Plain MapLibre instead of deck.gl. The plan called for a deck.gl overlay and flagged a known globe distortion bug (#9466). The shipped code uses MapLibre's own GeoJSON layers and computes great circles itself, which avoids the bug and a large dependency.
  • Ed25519 instead of HMAC for the sensor. The plan specified HMAC-SHA256 pushes with a nonce table. Commit 54e87ec switched to Ed25519-signed pulls. HMAC uses one shared secret, so Vercel would have had to store it, and anyone who read it could forge data. With Ed25519 the website holds only a public key, which can be committed to Git.
  • Hand-written SQL with pgx instead of an ORM. The plan lists this as a learning goal, and it allows the advisory-lock ordering, abbrev(inet) and the optional-filter pattern, which ORMs make awkward.

Challenges and How They Were Solved

  • internal/ packages broke the Vercel build. The first deploy failed with "use of internal package not allowed". Commit e02e63c moved everything to pkg/.
  • Vercel does not ship data files with Go functions. Commit 35f1a78 compiled the DB-IP databases into the binary with go:embed behind a build tag, so local and Docker builds still read from disk.
  • JSON encoding was the throughput limit. Commit b8e2cbb ("serve the live snapshot pre-encoded") introduced the version counter and cached JSON plus gzip. The README reports a local load test of 20,000 requests at 200 concurrent with zero errors and zero data races.
  • Fake precision from country centroids. DB-IP returns country-centre coordinates for coarse records. Lookup now requires a city name before treating coordinates as a point, and the map shades the country instead.
  • Arcs that implied knowledge the data did not have. Radar country-pair arcs were added and then removed in favour of a list, leaving only sensor arcs (commit e2ef88d).
  • Arcs drawn the wrong way round the planet. Great circles that cross the 180 degree meridian were split with interpolated boundary points, and the animated heads use a second split in arcFlow.ts. Arcs on the far side of the globe are clipped to the visible hemisphere.
  • Lost events on reconnect. The concurrent-writer race (seq 105 visible before 104) was solved with a transaction-scoped advisory lock and proven with a randomised forced-reconnect test.
  • PgBouncer and prepared statements. Solved with QueryExecModeExec and a small pool with a short idle timeout.
  • Space view jank. Textures moved into a Web Worker, shaders pre-compiled with blank textures, and the render loop stops when nothing changes, cutting the first-open freeze from 649 ms to 83 ms.
  • Azure CLI blocked by a school sign-in policy. Commit f68c512 added cloudshell-deploy.sh, which runs the Terraform from Azure Cloud Shell where az and terraform are already signed in.
  • Browser stability under constant updates. web/e2e/stress.spec.ts runs 30 polls of 250 new events each while switching projection, opening records and resizing across all four breakpoints, and fails on any page error, a map that stops being ready, or climbing memory.

Security and Performance Notes

Treating feed data as hostile. Everything from a feed is attacker-influenced. The backend caps response size at 64 MB, parses with strict typed structs, defangs URLs and domains, never resolves attacker domains, and never geolocates private addresses. The front end validates the snapshot's shape before using it.

Signed telemetry. Sensor data is accepted only if its Ed25519 signature over timestamp.body verifies against an embedded public key and the timestamp is within 10 minutes. Unsigned, altered or replayed responses are rejected before parsing, and the reason appears in the source's last_error on the Status page.

Honeypot containment. The NSG allows inbound 22 and 23 from the internet (redirected by iptables to Cowrie on 2222 and 2223), real SSH on 22222 only from the admin's /32, and the exporter on 8443. Outbound traffic is limited to web and DNS for updates, with a deny-all rule after that. On the host, an iptables owner match rejects every new outbound connection from the cowrie user while still allowing replies, so an attacker who types wget inside the fake shell cannot fetch anything. The admin account uses SSH keys only (disable_password_authentication = true). The exporter rate-limits to 30 requests a minute per address and caches for 30 seconds. Usernames are published; passwords are not.

Secrets. .env.example lists placeholders only, and CLAUDE.md forbids echoing secrets. The Radar token is read from the environment and only sent as a header. The sensor's private key lives on the VM and in local Terraform state, never in the repo.

HTTP hardening. vercel.json adds X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin and X-Frame-Options: DENY to every response. The API container runs as non-root on distroless. CI runs govulncheck.

SQL safety. All queries use bind parameters; filters are validated against allow-lists and ranges before reaching SQL.

Performance. One upstream fetch per source interval regardless of traffic; one JSON and gzip encode per data change; CDN caching with stale-while-revalidate; 304 responses for unchanged snapshots; client polling paused in hidden tabs; three.js and its textures loaded lazily and in idle time; the arc animation stops under reduced motion. The plan sets targets (shell JS under 120 KB gzip, LCP under 2.5 s) that are stated as targets, not measured results.

Legal and ethics. Every record carries its licence. DShield, Radar and Vercel Hobby require non-commercial use, which the README states. The About text notes that IP location identifies a network, not a person.
