6 AI Video, Manga Recap, and Story Tools

This chapter covers eight projects that share one goal: turning static material (a manga chapter, a still painting, a narration track, a raw video) into watchable, narrated, or subtitled media with the help of AI models. They span local-first browser apps, Python desktop tools, hosted SaaS on Supabase, and a live commercial product, and many of them are successive attempts at the same problem, so the design lessons build on each other. Cutmox: Local-First AI Subtitles in the Browser

At a Glance

Cutmox is a browser-based subtitle generator for short-form video creators. You drop a video onto the page, and the app transcribes the speech with OpenAI's Whisper model and shows a word-by-word transcript you can edit, all without uploading the video to any server. The pitch is privacy and zero cost: the heavy lifting (audio extraction and speech recognition) happens inside the user's own browser tab using WebAssembly and, when available, the GPU. The UI shell was generated with Lovable, and the real engine was then built by hand in numbered phases.

How It Works (Simple Version)

Imagine a tiny recording studio that lives inside your web browser. When you hand it a video:

  1. The studio puts the video in a private locker (IndexedDB, the browser's built-in database), so a page refresh does not lose it.
  2. A sound engineer (ffmpeg compiled to WebAssembly) strips the picture away and keeps only the voice, converted to the exact format a speech model likes: one channel, 16,000 samples per second.
  3. A stenographer (Whisper, running in a background thread) listens and writes down every word with a start and end time.
  4. The words are grouped into sentences and shown next to the video. As the video plays, the word being spoken lights up. Click a word to fix a typo, and the fix is saved to the locker.

Nothing leaves the computer except the one-time download of the model and the ffmpeg engine.

Deep Dive

Framework and routing. TanStack Start is a full-stack React framework that renders pages on the server (SSR, server-side rendering: the server sends ready-made HTML so the first paint is fast and crawlable). Routes are files in src/routes/: index.tsx (landing), editor.tsx (577 lines, the main app), settings.tsx (stored videos and storage usage), and a test.tsx viability page from Phase 1. Because Whisper, ffmpeg, and IndexedDB only exist in browsers, every media module guards itself with checks such as typeof indexedDB === "undefined" and is imported only inside client code.

Cross-origin isolation. Multi-threaded ffmpeg.wasm needs SharedArrayBuffer (memory that several threads can read and write at once). Browsers only allow that on pages that are "cross-origin isolated", which requires two response headers: COOP (Cross-Origin-Opener-Policy) and COEP (Cross-Origin-Embedder-Policy). Cutmox sets them in three places: a custom Vite middleware for dev, public/_headers for static assets on Cloudflare, and the Worker for SSR responses. The comment in vite.config.ts explains why plain server.headers was not enough:

// Vite's `server.headers` doesn't reliably land on module-worker
// responses (`?worker_file&type=module`), which Chrome then blocks
// under COEP. Setting headers via middleware guarantees every
// response gets them, including the worker chunk that boots Whisper.
function crossOriginIsolationDev(): Plugin {
  const apply = (_req: unknown, res: ..., next: () => void) => {
    for (const [name, value] of Object.entries(CROSS_ORIGIN_HEADERS)) {
      res.setHeader(name, value);
    }
    next();
  };
  return {
    name: "cutmox:cross-origin-isolation-dev",
    configureServer(server) { server.middlewares.use(apply); },
    configurePreviewServer(server) { server.middlewares.use(apply); },
  };
}

Storage (src/lib/storage/video-store.ts). The app uses the idb wrapper around IndexedDB. There is one database, cutmox-videos, with one object store videos keyed by id and an index by-createdAt. A VideoRecord holds the raw videoBlob, filename, MIME type, size, duration, a JPEG thumbnail as a data URL, and an optional transcript. The schema is at version 2: v1 created the store, and v2 added transcript without a data migration because a missing field is read back as null. IDs are "ULID-ish": eight base-36 characters of timestamp (so they sort by time) followed by eight random characters. isQuotaExceededError detects when the browser refuses to store a large Blob so the UI can show a friendly message.

Thumbnails (src/lib/video/thumbnail.ts). A hidden <video> element loads the file through an object URL, seeks to about one second, draws that frame to a canvas capped at 640 px wide, and exports a JPEG at quality 0.7. Failures return nulls instead of throwing, so an exotic codec still saves, just without a preview.

Audio extraction (src/lib/ffmpeg-client.ts). The ffmpeg core (about 32 MiB of wasm) is fetched from jsdelivr and turned into same-origin blob: URLs with toBlobURL. That trick solves two problems at once: COEP would block a cross-origin worker script, and Cloudflare Workers refuses static assets larger than 25 MiB. The load is memoised in a module-level promise and reset on failure so the user can retry. The extraction itself is a single ffmpeg command:

await ff.writeFile(inputName, await fetchFile(blob));
// -vn: drop video. -ac 1: mono. -ar 16000: 16 kHz.
// -f f32le: raw 32-bit float little-endian (Whisper's input).
await ff.exec(["-i", inputName, "-vn", "-ac", "1", "-ar",
  "16000", "-f", "f32le", "-y", outputName]);
const data = await ff.readFile(outputName);
const bytes = data instanceof Uint8Array ? data : ...;
// Float32Array needs a 4-byte-aligned buffer; copy to be safe.
const aligned = new ArrayBuffer(bytes.byteLength);
new Uint8Array(aligned).set(bytes);
const samples = new Float32Array(aligned);
if (samples.length < MIN_AUDIO_SAMPLES) {
  throw new NoAudioTrackError();
}

Writing raw f32le (no WAV header) means the bytes can be reinterpreted directly as a Float32Array with zero decoding. The alignment copy matters because a typed array view over a buffer must start at a multiple of its element size (4 bytes for floats). MIN_AUDIO_SAMPLES is about 60 ms; anything shorter is treated as "no audio" and gets its own UI state.

Speech recognition (src/workers/whisper.worker.ts). A Web Worker is a background JavaScript thread; running Whisper there keeps the page from freezing. The worker loads Xenova/whisper-base through transformers.js (Hugging Face's JavaScript port of their model library, which runs ONNX models in the browser). It tries WebGPU first and falls back to WASM:

try {
  const p = await pipeline("automatic-speech-recognition",
    "Xenova/whisper-base", {
      device: "webgpu",
      progress_callback: progressCallback(id),
    });
  return { pipeline: p, device: "webgpu" };
} catch (err) {
  console.warn("[whisper.worker] WebGPU init failed, ...", err);
  const p = await pipeline("automatic-speech-recognition",
    "Xenova/whisper-base",
    { progress_callback: progressCallback(id) });
  return { pipeline: p, device: "wasm" };
}

The pipeline is called with return_timestamps: "word", chunk_length_s: 30, and stride_length_s: 5. Whisper only sees 30 seconds at a time, so long audio is cut into overlapping 30 s windows (5 s overlap on each side) and the results are stitched. The worker speaks a small typed protocol: progress, device-info, result, or error messages, each tagged with a request id (a crypto.randomUUID()) so concurrent calls cannot be confused. env.useBrowserCache = true makes transformers.js cache the model files in the browser's Cache Storage after the first download.

Segmentation (src/lib/whisper/segment.ts). Whisper returns a flat list of words. groupWordsIntoSegments walks the list and closes a segment when a word ends in ., !, or ?, or when the bucket hits 30 words, which prevents a run-on monologue from becoming one giant paragraph.

Orchestration and cancellation. transcribe-pipeline.ts chains extract, transcribe, and group, reporting a stage plus progress value. It accepts an AbortSignal. Cancellation is "soft": the worker cannot be interrupted mid-inference, so the pipeline simply stops forwarding progress and throws an AbortError between stages. The model stays warm for the next attempt. In editor.tsx the transcription UI is a discriminated union state machine: awaiting-confirmation, running, ready, error, or no-audio. Videos over five minutes (LONG_VIDEO_THRESHOLD_SEC = 300) wait for the user to opt in, because local transcription can take several minutes.

Active-word highlighting. Instead of the coarse timeupdate event (about 4 times a second), the editor polls video.currentTime on every animation frame while playing, and does a linear scan over a flattened word list. It only calls setActive when the active word changes, so React re-renders once per word rather than 60 times a second:

function tick() {
  if (!running) return;
  const t = video!.currentTime;
  let hit: ActiveWord | null = null;
  for (const w of flat) {
    if (w.startSec <= t && t < w.endSec) {
      hit = { segmentId: w.segmentId, wordIndex: w.wordIndex };
      break;
    }
    if (w.startSec > t) break;
  }
  const key = hit ? `${hit.segmentId}:${hit.wordIndex}` : null;
  if (key !== lastKey) { lastKey = key; setActive(hit); }
  raf = requestAnimationFrame(tick);
}

A separate seeked listener runs the same lookup once while paused, so scrubbing still moves the highlight. Word edits call updateTranscriptWord, which rewrites one word and the segment's text, then puts the whole record back (IndexedDB stores values whole).

Deploy pruning. scripts/prune-server-bundle.mjs deletes the Whisper worker chunk, ONNX runtime wasm, and client-only chunks from dist/server/assets before wrangler deploy. Vite emits them into both client and server bundles, and the server copies pushed the Worker past Cloudflare's 3 MiB free-tier limit.

Key Design Decisions and Trade-offs

  • Local-first over cloud APIs. Running Whisper in the browser means no server cost and no privacy risk, but transcription is slower than a hosted API and quality is capped by the small whisper-base model that fits in a browser.
  • Keep Cloudflare Workers instead of Vercel. BUILD_PLAN.md notes that the original brief said "static deploy on Vercel", but the Lovable scaffold targeted Workers. Since the Worker only renders HTML and adds headers, switching would have been a rewrite for no gain.
  • React Context, not Zustand. project-context.tsx shares the current project via Context. The plan judged about five consumers too few to justify a store library.
  • Build the editor in vertical slices (option C in the plan). Each engine phase ships its own UI slice (upload, then transcript panel), avoiding "dead UI" that would be reworked once real data arrived.
  • ffmpeg for audio instead of WebAudio. The plan discussed decodeAudioData as a faster path, but ffmpeg handles every container uniformly and is needed later for burning subtitles anyway.
  • Export rendering is still open. The plan flags that ffmpeg's subtitles filter cannot do per-word highlight styles (Word-pop, Hormozi). Options are per-frame drawtext filter graphs or compositing frames on a canvas and piping raw video back into ffmpeg. burnSingleSubtitle is a Phase 1 proof using drawtext.

Challenges and How They Were Solved

  • COEP blocking the worker in dev. Solved with the middleware plugin shown above.
  • Assets bypassing the Worker in production. Static JS and wasm are served by Cloudflare's asset binding, not src/server.ts, so they shipped without COEP and broke Whisper. The _headers file fixes this at the asset layer.
  • Vite pre-bundling transformers.js. The dep optimizer tried to pre-bundle the library's internal worker into a file that never existed, causing a 404 on every load. The fix is optimizeDeps.exclude: ["@huggingface/transformers"].
  • The 25 MiB asset cap and 3 MiB Worker cap. Solved by loading ffmpeg core from a CDN as blob URLs and by the prune script.
  • Unaligned PCM buffers. Solved by copying into a fresh ArrayBuffer.
  • The git history shows the work in three merged pull requests: phase-1-viability (test page, headers, clients), phase-2-upload (IndexedDB, DropZone, settings), and Phase 3 commits (audio extraction, worker pipeline, TranscriptPanel, long-video gate).

Security and Performance Notes

  • No user media is uploaded. The only network traffic is fetching the ffmpeg core and model weights.
  • Cross-Origin-Resource-Policy: same-origin plus COEP means the page cannot embed arbitrary third-party resources, which also narrows the attack surface.
  • ffmpeg.wasm is 32-bit, so its heap tops out around 2 GB. The DropZone caps files at 500 MB and accepts MP4, MOV, and WebM only.
  • WebGPU is described in the code as roughly 5 to 10 times faster for long videos than the WASM backend.

Recap Verse: The Production Manga Recap Platform

At a Glance

Recap Verse (repository manga-recap-app, local folder V12.0) is the flagship of this chapter: a live, commercial web app that turns a folder of manga or manhwa page images into a narrated recap video. It targets YouTube and Shorts creators who make "manga recap" channels, where a narrator retells a chapter over its panels. The app cuts pages into panels, uses a vision model to find the recurring characters, lets the human confirm the cast, writes narration that is only allowed to name that confirmed cast, speaks it with text-to-speech, and renders the final video inside the user's browser. It began life as a Tkinter desktop app and grew, over 413 commits, into a FastAPI and Next.js product with billing, an admin console, and about 2,000 automated tests.

How It Works (Simple Version)

Picture a small film crew working on a comic book:

  1. The cutter lays every page end to end on one long table and slices out each panel, in reading order.
  2. The casting director looks at every panel and makes a list of faces that keep showing up. You, the producer, review the list: "that is Naruto, that is Sasuke, that blob is just a sword."
  3. The writer goes panel by panel and writes one or two spoken sentences, remembering what happened in the last few panels. The writer is forbidden from inventing names that are not on your approved cast list.
  4. The voice actor reads each line aloud, and a stopwatch measures exactly how long each line takes.
  5. The editor (your own browser) shows each panel for exactly as long as its line lasts, slowly zooming toward the character's face, adds captions, and records the result as a video file.

The AI suggests at every step, and a human confirms. That rule is the product's core idea.

Deep Dive

The proxy and auth model. Every browser request goes to /api/v1/... on the same origin as the web app. web/app/api/v1/[...path]/route.ts looks up the NextAuth session, swaps the session cookie for a backend bearer "bridge token" that never reaches JavaScript in the page, enforces a same-origin CSRF check on writes, and strips hop-by-hop headers. CSRF (cross-site request forgery) is an attack where another site tricks your browser into sending an authenticated request; checking the Origin header blocks it. Only login, register, and Google OAuth are public paths.

Uploads and image safety. Panels go straight from the browser to Cloudflare R2 (an S3-compatible object store) with presigned PUT URLs, short-lived signed links that let the browser upload one object without holding storage credentials. core/image_security.py decodes the actual bytes with Pillow rather than trusting the declared MIME type and rejects decompression bombs (tiny files that expand to billions of pixels) with limits of 80 million pixels and a 60,000 px long edge.

Panel Cutter (services/panel_cutter.py, about 1,400 lines). All uploaded pages are stitched into one vertical strip at a canonical width of 1000 px, with a _PanelLayout NamedTuple mapping strip Y ranges back to source images so manual crops are cut from the full-resolution originals. Auto-cutting is classical computer vision, not machine learning:

gray = img if len(img.shape) == 2 else cv2.cvtColor(
    img, cv2.COLOR_BGR2GRAY)
blurred = cv2.GaussianBlur(gray, (5, 5), 0)
_, binary = cv2.threshold(blurred, cfg.bg_threshold, 255,
                          cv2.THRESH_BINARY_INV)
kernel = cv2.getStructuringElement(
    cv2.MORPH_RECT, (kernel_size, kernel_size))
dilated = cv2.dilate(binary, kernel, ...)
closed = cv2.morphologyEx(dilated, cv2.MORPH_CLOSE, kernel)
num_labels, _, stats, _ = cv2.connectedComponentsWithStats(
    closed, connectivity=8)
...
boxes = _remove_nearly_nested_boxes(boxes)
if cfg.merge_distance > 0:
    boxes = _merge_nearby_boxes(boxes, cfg.merge_distance)
return _sort_reading_order(boxes, cfg.same_row_threshold)

The idea: manga gutters are white, so an inverted threshold turns ink into white blobs on black. Dilation and morphological closing (grow then shrink) glue the strokes inside one panel into a single blob. Connected-components labelling then returns one bounding box per blob. Boxes that are at least 92% inside another are dropped, close neighbours are merged, and the remainder is sorted into reading order by grouping boxes into rows. Detection runs on a copy downscaled to at most 12 megapixels and the boxes are scaled back, which bounds memory. Previews are capped at 65,500 px tall because that is the JPEG format's maximum dimension (bug BUG-025 in the project's tracker).

Cast scan and the cast bank (services/cast.py, cast_crops.py, cast_bank.py). A vision model observes each panel in parallel chunks on a ThreadPoolExecutor. Each character crop gets a perceptual fingerprint, a 64-bit difference hash (dHash):

def _difference_hash(image: Image.Image) -> str:
    tiny = image.convert("L").resize((9, 8))
    pixels = list(tiny.tobytes())
    bits = []
    for row in range(8):
        for col in range(8):
            left = pixels[(row * 9) + col]
            right = pixels[(row * 9) + col + 1]
            bits.append("1" if left > right else "0")
    value = int("".join(bits), 2)
    return f"{value:016x}"

Shrinking to 9 by 8 grayscale throws away detail, and comparing each pixel to its right neighbour records only the brightness gradient. Two crops of the same character in similar poses tend to produce similar bit patterns even at different sizes. The cast bank is versioned with a blake2b hash of its fields so stale matches can be detected. The user then reviews the proposed cast in a group-first builder and confirms names.

Narration (services/generation.py, ai.py). process_generation_job loads the job and processes panels in chunks of 32. Observations (what the vision model sees in each panel, including speech-bubble text, since there is no separate OCR stage) run four at a time in parallel. Narration then proceeds strictly in order, carrying chapter context: a deque of the last six narrations, a running compressed summary, and a window of recent scene references. AI providers are called over raw REST with httpx (OpenAI Responses API, Gemini generateContent, Anthropic Messages), using the user's own encrypted key.

The deterministic resolver (services/panel_cast_resolver.py, about 1,500 lines). This is the answer to the hardest problem: each vision call has no memory of other panels, so the same character might be "a spiky-haired boy" in one panel and "the hero" in the next. The resolver decides identity with code, not another LLM call, in five stages:

  1. A prop safety net with 118 known prop labels (a sword is never a cast member).
  2. Matching to the cast bank by traits plus visual hash.
  3. Scene continuity, carrying identity across recent panels.
  4. Distinct identity, so one character cannot fill two slots in one panel.
  5. Geometric speaker association: the tail of a speech bubble is matched to the nearest character's "head anchor", with fallbacks for edge distance and centre distance, and a right-to-left or left-to-right tiebreak depending on the comic's reading direction.

Each assignment is labelled clear, ambiguous, or none, and uncertain matches stay separate rather than being force-merged. The narration prompt then combines a tone preset (cinematic, Gen Z, serious, dark, funny, neutral), a word budget clamped to 20 to 200, one of 15 output languages, and guardrails against contamination. Post-processing rejects near-duplicates (similarity over 0.82 against the last four lines), wrong-script output (for example Latin text when Hindi was requested), verbal tics, and leaked prompt context.

Optimistic concurrency. If the user edits a panel while a generation job runs, the user's edit must win. Each write is conditional on the updated_at value read earlier:

def build_panel_write(snapshot, update) -> UpdateOne:
    """Build a panel write that only lands if the panel
    has not moved since *snapshot*.
    ...
    """
    predicate = {"_id": snapshot["_id"]}
    snapshot_version = snapshot.get("updated_at")
    if snapshot_version is not None:
        predicate["updated_at"] = snapshot_version
    return UpdateOne(predicate, update, upsert=False)

If the timestamp changed, the filter matches nothing, the AI's text is silently dropped, and the job log says it "kept your edit made while this run was in progress". This is optimistic concurrency control: assume no conflict, but verify at write time.

Text-to-speech and timing (services/tts_engine.py). Edge TTS (free) is the default, with ElevenLabs eleven_multilingual_v2 for users who bring a key. Calls run under asyncio.Semaphore(4) with a 30 second timeout and one retry. Durations are measured by walking the MP3's own frame headers:

def measure_mp3_duration(data: bytes) -> float:
    if not data:
        return 0.0
    offset = _skip_id3v2(data)
    total_seconds = 0.0
    limit = len(data)
    while offset < limit - 3:
        frame = _parse_mp3_frame(data, offset)
        if frame is None:
            offset += 1  # resync: step a byte ...
            continue
        frame_length, seconds = frame
        total_seconds += seconds
        offset += frame_length
    return total_seconds

An MP3 file is a sequence of independent frames, each with a 4-byte header giving bitrate and sample rate, which fixes the frame's length and play time. Summing frames gives the true duration. This replaced trusting edge-tts metadata after the library silently switched from word to sentence boundary events (BUG-018) and every duration became an estimate. Silence padding is a hand-built 417-byte all-zero MPEG-1 Layer III frame. A SHA-256 fingerprint over voice, provider, rate, pitch, and every panel's narration lets a re-render reuse an existing audio job instead of paying for TTS again.

Rendering in the browser. The server only builds a render plan (timeline_builder.py, animation_engine.py, video_generator.py): panel types, presets such as cinematic, fast_recap, dramatic_focus, and shorts, transitions, and a focus point equal to the average centre of the characters' bounding boxes. The browser (web/lib/video/video-generator.ts) draws each frame on a canvas with a Ken Burns move (a slow zoom and pan, named after the documentary maker) eased with easeInOutCubic toward that focus point, then records canvas.captureStream(fps) plus a Web Audio stream with MediaRecorder:

export function chooseRecorderMimeType(): string {
  const candidates = [
    "video/mp4;codecs=avc1.42E01E,mp4a.40.2",
    "video/mp4",
    "video/webm;codecs=vp9,opus",
    "video/webm;codecs=vp8,opus",
    "video/webm",
  ];
  for (const candidate of candidates) {
    if (typeof MediaRecorder !== "undefined" &&
        MediaRecorder.isTypeSupported(candidate)) {
      return candidate;
    }
  }
  return "video/webm";
}

The decoded audio is the ground truth for timing; the server's duration is only a cross-check with a 0.35 s tolerance, because capping by it used to cut off speech. There is no ffmpeg anywhere in the product.

Jobs and the database. Production runs jobs inline in the API process (INLINE_JOB_EXECUTION=true), while an optional mode uses Redis and RQ (a simple Python job queue) with worker/worker.py. MongoDB collections include users, api_keys, projects, panels, characters, jobs, narrations, and billing_events. Races are prevented with database constraints rather than check-then-act code:

db["jobs"].create_index(

Key Design Decisions and Trade-offs

  • Deterministic identity over LLM judgement. Reproducible and unit-testable, at the cost of a 1,500-line resolver full of heuristics.
  • Browser rendering instead of a render farm. Zero server CPU and storage per video, and the output never leaves the user's machine. The trade-off is dependence on browser codec support (iOS Safari before 17 lacks captureStream, which the app reports explicitly).
  • Inline jobs in production. No Redis to operate, accepting longer requests within Cloud Run's 300 s timeout.
  • Bring your own AI key. Users pay their own model costs; keys are encrypted with AES-GCM.
  • Feature flags for big rewrites. USE_UNIFIED_OBSERVATION_PROMPT and USE_PANEL_CAST_RESOLVER let the "Phase 4" pipeline replace the old one gradually, with explicit overrides to roll back.
  • Exact dependency pinning plus a constraints file, after a transitive upgrade broke production (BUG-003).
  • Fail closed on config. A missing base URL makes /health return 503 rather than assuming localhost.

Deep Dive

Two resolutions per page. manga_extraction.py renders each PDF page with PyMuPDF and keeps two base64 arrays: a copy scaled into a 512 by 512 box (sent to GPT in "low detail" mode, which is cheap) and the full-resolution page (used for cropping panels and video). split_volume_into_parts divides the volume into seven jobs and snaps each boundary to the nearest chapter-start page so no chapter is split.

Few-shot page classification. vision_analysis.detect_important_pages shows the model example character-profile pages and chapter-start pages from two reference PDFs the user provides, then 20 unknown pages, and asks for JSON listing which are which. Few-shot prompting means teaching by example inside the prompt instead of training a model. If json.loads fails, the raw text is sent to gpt-3.5-turbo in JSON mode to be repaired, a common 2024 pattern before strict structured outputs existed.

Citations as the bridge between text and pictures. The summary prompt demands an inline citation [^{image_index}] after every claim. Models often mangle the format, so citation_processing.py normalizes it first:

def clean_and_relocate_citations_sequence(text):
    cleaned_text = (
        text.replace(" ^[", "[^")
        .replace("^[", "[^")
        .replace(" [^", "[^")
        .replace("[^^", "[^")
    )
    pattern = re.compile(r"((?:\[\^\{\d+\}\])+)(\.)")
    relocated_text = re.sub(pattern, r"\2\1", cleaned_text)
    return relocated_text

The regex finds a run of citations immediately before a period and swaps them so the period comes first. The text is then split on citation markers into blocks of {text, citations}, out-of-range indices are dropped, and uncited blocks are merged into a neighbour so every narration segment has an image.

Panel extraction by gutters. The vendored panel_extractor assumes panels are separated by white gutters:

                  (0, 0, 0), 10)

    ...

Thresholding at 230 makes near-white pixels foreground. A black border is drawn so the outer margin does not connect everything. The connected components are sorted by area; the largest is the background, so the second largest is the gutter network. Contours of the remaining holes become panels, filtered to between 2% and 90% of the page area. A histogram check first skips "paper-texture" pages (at least 35% mid-tones) that have no clean gutters. Video assembly. movie_director.py calls ElevenLabs asynchronously under asyncio.Semaphore(5) (at most five requests in flight), divides each sentence's audio duration evenly across its chosen panels, letterboxes them on a 1280 by 720 canvas, and writes H.264 and AAC at 24 fps with MoviePy.

Per-panel narration with a language lock (panel_narrate.py). Each image becomes one OpenAI Responses API call (default gpt-4.1-mini). Vision models tend to drift back to English, so the code states an "OUTPUT LANGUAGE LOCK" in both the system instructions and the user prompt, then verifies the script:

Devanagari, the Hindi script, occupies the Unicode block U+0900 to U+097F, so one regex is a cheap validator. A failure triggers a single "STRICT RETRY".

Casting (cast_builder.py). Five to fifteen clear-face panels go to the model with a strict JSON schema: cast[{id, name, appearance[], notes[], aliases[], confidence}]. Unknown characters become Unknown_1, Unknown_2. IDs are deterministic so casts merge across runs without a database:

def _stable_id(name, appearance):
    seed = (name or "").strip().lower() + "||" + " ".join(
        [a.strip().lower() for a in (appearance or [])])
    h = hashlib.sha1(seed.encode("utf-8")).hexdigest()[:10]
    return f"char_{h}"

_merge_cast prefers a real name over "Unknown", unions appearance lists case-insensitively, turns a conflicting new name into an alias, and keeps the higher confidence. panel_narrate_casted.py injects the cast into the prompt with the rule "never create a brand-new name", and writes narration.json after every panel so a crash loses nothing. These casting modules are CLI tools for now; the GUI uses the plain narrator.

Streamlit state. Streamlit reruns the whole script on every click, so durable state lives on disk in panel_runs/<project>/project.json (panels[{filename, status}], selected panel, auto-advance flag), reconciled against the panels folder on every run. Status flows new, narrated, done. launcher.py creates .venv and reinstalls requirements only when their SHA-256 hash changes.

Key Design Decisions and Trade-offs

  • Low-detail images for the model, full-res for output: cheap tokens, but small dialogue text can be misread.
  • Classical gutter detection: fast and training-free, but dark or borderless pages fall back to whole pages.
  • The pivot to per-panel narration: drops PDF parsing, ElevenLabs, and video from the default install, and puts a human in the loop for every line.
  • JSON files instead of a database: zero setup, but no locking.

Challenges and How They Were Solved

  • History shows the original author moving from full pages to panels in the video ("showing panels in video instead of full pages"), then gpt-4-vision-preview to gpt-4o, then community fixes for MoviePy v2 (with_duration, with_audio) and the citation format change from [^n] to [^{n}].

Bring-your-own-key encryption. manage-api-key encrypts keys with AES-GCM via the WebCrypto API built into Deno:

async function encryptKey(key: string, secret: string) {
  const enc = new TextEncoder();
  const keyMaterial = await crypto.subtle.importKey("raw",
    enc.encode(secret.padEnd(32).slice(0, 32)),
    "AES-GCM", false, ["encrypt"]);
  const iv = crypto.getRandomValues(new Uint8Array(12));
  const encrypted = await crypto.subtle.encrypt(
    { name: "AES-GCM", iv }, keyMaterial, enc.encode(key));
  const combined = new Uint8Array(
    iv.length + new Uint8Array(encrypted).length);
  combined.set(iv);
  combined.set(new Uint8Array(encrypted), iv.length);
  return btoa(String.fromCharCode(...combined));
}

AES-GCM is authenticated encryption: it hides the data and detects tampering. A fresh random 12-byte IV (initialization vector) per encryption is required for GCM's security, and storing it in front of the ciphertext is the standard layout. The weak spot is key derivation: the server secret is padded or sliced to 32 bytes instead of going through a KDF (key derivation function) such as HKDF or PBKDF2. Only masked_key (first four and last four characters) ever returns to the browser. The test action decrypts the key and calls the provider's model list endpoint to prove it works.

  • Bring your own key: the platform pays nothing for AI, at the cost of holding a server secret that can decrypt every stored key.
  • Observe, then narrate: fewer hallucinations and an audit trail in observation_data, but two calls per panel.
  • Style as JSONB: prompt rules evolve without migrations.
  • Edge functions use the service role for cross-table work and filter by user_id manually, which bypasses RLS and therefore needs care.

RLS (Row Level Security) is a Postgres feature where each table has policies, small boolean SQL expressions evaluated per row, that decide who may select, insert, update, or delete. Every admin policy reuses one helper:

export function rateLimit(key: string, limit: number,
                          windowMs: number): RateResult {
  const now = Date.now();
  if (buckets.size > 5000) {
    for (const [k, b] of buckets) {
      if (b.resetAt <= now) buckets.delete(k);
    }
  }
  const b = buckets.get(key);
  if (!b || b.resetAt <= now) {
    buckets.set(key, { count: 1, resetAt: now + windowMs });
    return { ok: true, retryAfterMs: 0 };
  }
  if (b.count >= limit) {
    return { ok: false, retryAfterMs: b.resetAt - now };
  }
  b.count += 1;
  return { ok: true, retryAfterMs: 0 };
}

Key Design Decisions and Trade-offs

  • RLS-first authorization. The database is the real security boundary; server checks are defence in depth. The price is a lot of policy SQL, including EXISTS joins that check novel ownership for chapters and tags.
  • Idempotent, additive migrations. Every migration uses if not exists and drop policy if exists, so it can be re-applied to a live database that drifted.
  • force-dynamic route groups. This fixed Vercel prerender crashes when Supabase env vars were missing at build time, but it gives up static caching for public pages (except the hourly sitemap).
  • Separate tables for separate intents. Likes, bookmarks, author follows, and novel subscriptions are four tables, which keeps each feature's semantics and policies simple.
  • cacheComponents disabled. The config comment says the auth-plus-data dashboard pattern kept triggering "Server could not finish this Suspense boundary" errors.

  • Strong points: server-only imports, zod on every input, folder-scoped storage policies, 404 for hidden admin routes, a last-admin guard, an audit log, and DB-level length checks (comments up to 4000 characters).

At a Glance

How It Works (Simple Version)

Deep Dive

The fal.ai call. fal.ai hosts generative models behind a queue API. fal_client.upload_file(path) returns a hosted URL for the image, then fal_client.subscribe("fal-ai/wan-25-preview/image-to-video", arguments={...}) submits the job and blocks until it finishes, passing the prompt, negative prompt (things to avoid, defaulting to "flicker, jitter, warping"), duration "5" or "10", and resolution "480p" or "1080p" (a constants comment notes 720p is often unsupported). The result's video URL is parsed from video.url, with fallbacks for other response shapes. A negative prompt is a second text input that steers the diffusion model away from listed features.

Job folders and selective work. Each job gets a timestamped folder containing a copy of the source image, request.json for reproducibility, and a _work/ folder for intermediates. The user picks export targets (raw, post, loop, combined), and the pipeline computes needs_post, needs_loop, and needs_extend so a raw-only export never touches ffmpeg. At the end _export_selected moves the requested outputs up and deletes the rest.

ffmpeg processing. All calls use argument lists via subprocess.run, never a shell string, so file names cannot inject commands. Post-processing scales with force_original_aspect_ratio=increase and then crops to exactly 1920 by 1080 (fill the frame, trim the overflow), sets the frame rate, and encodes libx264 -crf 18 -preset medium -movflags +faststart. CRF (constant rate factor) is x264's quality knob, where lower is better and 18 is visually near lossless; faststart moves the index to the front of the file so playback can start before the download finishes. The loop and extension:

        "ffmpeg", "-y", "-i", str(in_mp4),
        "-filter_complex",

        "format=yuv420p",
        "-an", "-c:v", "libx264", "-crf", "18", ...
    ]
    _run(cmd)

def _extend_by_repeat(in_mp4, out_mp4, *, total_seconds: int):
    ...
    cmd = ["ffmpeg", "-y", "-stream_loop", "-1",
           "-i", str(in_mp4), "-t", str(int(total_seconds)),
           "-c", "copy", str(out_mp4)]
    _run(cmd)

The filter graph splits the input, reverses one copy, and concatenates forward plus reverse, so the loop point is seamless by construction. -stream_loop -1 repeats the input forever, -t cuts it at the target length, and -c copy copies packets without decoding, so an hour of output takes seconds and loses no quality. LoopExtendService also implements a crossfade loop with ffmpeg's xfade filter and a re-encode fallback when timestamp issues break stream copy, but the live pipeline maps crossfade to boomerang "for now".

export function usePolling(cb: () => void | Promise<void>,
                           intervalMs: number, enabled = true) {
  const callbackRef = useRef(cb);
  useEffect(() => { callbackRef.current = cb; }, [cb]);
  useEffect(() => {
    if (!enabled) { return; }
    const invoke = () => void callbackRef.current();
    invoke();
    const timer = window.setInterval(invoke, intervalMs);
    return () => window.clearInterval(timer);
  }, [enabled, intervalMs]);
}

How It Works (Simple Version)

Think of making a picture book for an audiobook. First you write down every word the narrator says and when they say it. Then you cut the recording into ten-second pages. For each page you write a short description for an illustrator, always reminding them "the hero has short black hair and a red scarf" so the hero looks the same on every page. When the pictures are ready, you flip through them in time with the audio and print the words along the bottom, highlighting each word as it is spoken.

Deep Dive

Layout reality. The repository has files named transcriber.py, scene_splitter.py, prompt_engine.py, renderer.py, subtitle_manager.py, and job_manager.py, but they are empty. Nearly all backend logic lives in backend/main.py, with real code only in providers/ and system_detector.py. The root main.py re-exports the app and runs Uvicorn on port 8000.

Transcription. faster-whisper is a reimplementation of Whisper on CTranslate2, a fast inference engine. The model is loaded lazily into a module-level singleton:

def _load_faster_whisper_model():
    global _FASTER_WHISPER_MODEL
    if _FASTER_WHISPER_MODEL is not None:
        return _FASTER_WHISPER_MODEL
    try:
        from faster_whisper import WhisperModel
    except ImportError as exc:
        raise ProviderError(
            "faster_whisper is not installed. ...") from exc
    _FASTER_WHISPER_MODEL = WhisperModel(
        "small", device="cpu", compute_type="int8")
    return _FASTER_WHISPER_MODEL

int8 quantization stores weights as 8-bit integers, which is roughly four times smaller than 32-bit floats and fast on CPUs. Transcription uses vad_filter=True (voice activity detection skips silence), beam_size=5, and word_timestamps=True. Audio length is checked with ffprobe (falling back to pydub) against a default two-hour limit. It always runs on CPU, even when system_detector.py (which parses system_profiler on macOS and nvidia-smi on NVIDIA machines) finds a GPU, favouring portability over speed.

Scene splitting. Two deliberately simple algorithms. For audio, the timeline is cut into fixed windows (default 10 s) and each window collects every Whisper segment that overlaps it:

The overlap test end > start and start < end is the standard interval intersection check. An empty window borrows its nearest segment's text so no scene is blank. For text input, the story is split on blank-line paragraphs, or on sentences if there are too few paragraphs, and each chunk gets synthetic 10 s timings.

Prompt pipeline and the Visual Bible. Each scene prompt passes through layers: strip old character text, apply a style preset, apply image-type rules (character scene versus background_only, with "auto" inferred from the scene), insert a character block, then apply quality wording. build_character_consistency_block writes each character's appearance, hair, eyes, and outfit into the prompt, with stronger or softer wording depending on a 0 to 100 strength slider, and adds "keep X visually distinct" when several characters share a scene. A settings hash stamped on each scene lets the UI mark prompts fresh, outdated, or missing.

The Visual Bible auto-build extracts characters, locations, and props as JSON, trying Gemini (responseMimeType: application/json, temperature 0.2), then OpenAI, then a keyword heuristic when no keys exist. detect_scene_assets matches names and aliases in each scene's text, and build_world_memory_block adds location and prop "memory" to the prompt. These extraction calls are the only live LLM network calls in the codebase.

Providers. providers/base.py defines two abstract base classes (ABCs, Python's way to declare an interface): PromptProvider.generate_scene_prompt(...) and ImageProvider.generate_image(prompt, negative_prompt, output_path, settings), each with test_connection(). A registry maps names (gemini, openai, claude, custom; manual, openai, gemini, stability, leonardo) to classes. Today every prompt provider uses the same deterministic template, and every remote image provider raises a clear "not available in this MVP" error. The working path is "manual": the user uploads an image per scene.

Rendering. For each scene, _compose_render_frame uses Pillow to build a "blurred-fill letterbox": a cover-fit copy of the image is Gaussian-blurred (radius 28) and dimmed as the background, and a contain-fit copy sits on top. This avoids black bars when a 1:1 image goes into a 9:16 video. Each frame becomes a still-image clip (ffmpeg -loop 1 -t <dur> ... libx264 yuv420p), the clips are joined with the concat demuxer using -c copy (no re-encode), and a final pass adds narration as AAC 192k with -shortest and burns subtitles with the ass= filter. Motion presets (slow zoom, pan, parallax) and transitions are stored and logged per scene but not yet applied as filters.

Subtitles. ASS (Advanced SubStation Alpha) is a subtitle format with styles, positions, and per-event colours. The backend writes an ASS file whose PlayResX/Y equal the output size and whose font size is clamp(height * 0.056, 42, 72). Three modes exist: one line per scene, word by word (one event per word in yellow), and karaoke. Karaoke chunks words into readable lines:

def _subtitle_word_chunks(words, max_words=8, max_chars=42):
    chunks, current, char_count = [], [], 0
    for word in words:
        word_text = str(word.get("word") or "")
        next_chars = (char_count + len(word_text)
                      + (1 if current else 0))
        gap = (_safe_float(word.get("start"), 0)
               - _safe_float(current[-1].get("end"), 0)
               ) if current else 0
        if current and (len(current) >= max_words
                        or next_chars > max_chars
                        or gap > 0.75):
            chunks.append(current)
            current, char_count = [], 0
        current.append(word)
        char_count += len(word_text) + (1 if char_count else 0)

A line breaks at 8 words, 42 characters, or a pause longer than 0.75 s, and is then re-emitted once per word with the active word highlighted. If the local ffmpeg lacks the ass filter, a fallback draws subtitles into frames with Pillow.

Jobs and concurrency. There is no database. Each job is a folder under OUTPUT_DIR/users/<session>/ holding meta.json, status.json, scenes, transcript, prompts, images, logs, subtitle files, and the final MP4. Long tasks run on daemon threads that copy request context variables (contextvars) into the thread. Cancellation is cooperative: a stop file is checked between steps and live ffmpeg processes are terminated. Renders are guarded by a lock:

def acquire_render_slot(job_id: str) -> None:
    global ACTIVE_RENDER_COUNT
    render_key = f"{current_user_id()}:{job_id}"
    with RENDER_LOCK:
        if render_key in ACTIVE_RENDER_JOBS:
            raise ProviderError(
                "Render already in progress for this job")
        if ACTIVE_RENDER_COUNT >= MAX_CONCURRENT_RENDERS:
            raise ProviderError("Render queue is full. ...")
        ACTIVE_RENDER_JOBS.add(render_key)
        ACTIVE_RENDER_COUNT += 1

With the default limit of 1, a second render is rejected rather than queued, which protects a laptop from running two heavy ffmpeg encodes at once.

Frontend. story-studio/page.tsx (about 6,000 lines) is the main workspace. TimelineEditor.tsx edits scene order, duration overrides, motion, transition, subtitle overrides, and approval, saving through /api/story/save-timeline. The backend "AI Director" is rule-based: it scores mood keywords (action, horror, romance and others), picks motion along a ladder, rotates shot types, and scales durations for pacing. frontend/lib/browserRender.ts offers a backend-free export: canvas frames, canvas.captureStream(fps), Web Audio routed into the stream, and MediaRecorder producing WebM in real time.

Key Design Decisions and Trade-offs

  • Split deployment. Vercel cannot run ffmpeg, Whisper, or long jobs, so the backend runs locally while the UI can live on Vercel.
  • Filesystem as database. Easy to inspect, duplicate, and zip-export, but no transactions.
  • Threads, not a queue. No Celery or Redis to install; tasks are lost on restart, partly repaired by reconcile_story_job_runtime_state.
  • Deterministic heuristics first. Time-window scenes, template prompts, and a keyword director work offline without keys; AI is an optional layer.
  • Text-based character consistency rather than IP-Adapter or LoRA, which became necessary after the local Forge engine was removed.

Challenges and How They Were Solved

  • ffmpeg filtergraph parsing of absolute paths (Windows drive colons broke ass=): ffmpeg now runs with cwd=job_dir and relative paths.
  • A previous final_video.mp4 picked up as narration input: an explicit input/output collision guard.
  • "Face leakage" into manual prompts: reusing the previous scene's reference image is allowed only for fully automatic character scenes.
  • Reordered timelines breaking scene_NNN.png lookups: the stored image_path is now preferred.

Security and Performance Notes

  • /api/media and /api/system/open-path resolve paths and refuse anything outside allowed roots (403). Session ids are sanitized to [a-zA-Z0-9_-] up to 80 characters. API keys are masked when returned to the browser, and masked values are preserved on save so they are never overwritten with asterisks.
  • There is no real authentication: the session id is chosen by the client. CORS allows credentials and any *.vercel.app origin, which is broad. Uploads are read into memory before the size check. These are acceptable for a local tool but not for a public server.
  • backend/image_settings.py imports a model_manager module that no longer exists, likely a leftover of the Forge removal.
  • Performance: one libx264 encode per scene, a stream-copy concat, then one final encode. Browser rendering runs at exactly real time.

python -m venv .venv && source .venv/bin/activate
pip install fastapi uvicorn pydantic pillow python-multipart \
  faster-whisper pydub          # no requirements.txt in repo

cd ../frontend && npm install && npm run dev
# or both at once from the repo root:
./run-dev.sh
./scripts/check-health.sh
