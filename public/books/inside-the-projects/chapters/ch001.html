1 How to Use This Book

This book explains every software project in Vijaysingh Puwar's GitHub account and local workspace. Each chapter was written by reading the real source code, commit history, and design notes, so the explanations match how the code actually works today, including where the code and the README disagree. Every chapter ends with reference material and verified YouTube videos, so a reader can go from "what is this?" to "I can build this" without hunting for resources.

  • Interested in systems and performance: Chapter 2 (spoonstill, Rust and FFmpeg), then the SetupTTS section in Chapter 5, then TOC Extractor in Chapter 8.
  • Interested in full-stack web: Chapter 3 (Web Audio TV), Chapter 4 (BreachScope), Recap Verse in Chapter 6, and TrustKart in Chapter 7.
  • Interested in security: Chapter 9 and Chapter 11, then the "Security and Performance Notes" of every other chapter. Several projects document real issues found in the code, which make good case studies.

Ideas That Appear Across Many Projects

Some techniques show up again and again. Learning them once makes every chapter easier.

FFmpeg as a Media Engine

FFmpeg is a command line program that can read, convert, cut, join, and filter almost any audio or video file. spoonstill, LocalTTSVideoStudio, Audio-Video-Studio, Image to Video, Cutmox (through its WebAssembly build), and the FFmpeg Web GUI all drive it. The safe pattern used throughout is to build the command as a list of arguments and never as one shell string, which prevents a file name from being interpreted as a command.

Row Level Security in Postgres

Supabase projects (Web Audio TV, Novelsin, the Portfolio Website, panel-narrate-ai) rely on Postgres Row Level Security (RLS). RLS means the database itself checks every query against a policy such as "a user may only read their own rows", so a bug in the front end cannot leak another user's data. Several chapters show both correct policies and policies that are too open, which is the most common mistake with this tool.

Bring Your Own Key (BYOK)

Many AI tools here let users paste their own API key instead of paying for a shared one. The key is encrypted with AES-256-GCM before storage. AES-GCM is an encryption mode that also detects tampering, so a modified ciphertext fails to decrypt instead of producing garbage.

Work Off the Main Thread

Desktop and browser apps stay responsive by moving heavy work elsewhere: Web Workers in the browser (Cutmox, SplitForge), worker threads in Qt (SetupTTS), and bounded thread pools in Rust (spoonstill). The user interface thread only draws and reacts to clicks.

Honest Engineering Notes

Many repositories contain decision logs, findings files, and audits. The chapters quote them where useful. Where a README claims more than the code does, the chapter says so, because knowing the real state of a system is part of understanding it.
