17 Testing Strategy

17.1 The suite at a glance

The suite runs with QT_QPA_PLATFORM=offscreen pytest -q. On the analysis machine all 383 tests passed in about 2 minutes. tests/conftest.py puts the repository on sys.path and points SETUPTTS_DATA_DIR at a temporary folder, so tests never touch real settings, history or staging.

17.2 Techniques worth copying

Stub the network at the narrowest seam. Worker tests replace tts_worker.build_communicate with a fake whose stream() yields scripted events: audio bytes sized at the real 6,000 bytes per second, sentence boundaries with real 100-nanosecond offsets, exceptions at chosen moments, or an early silent end. The rest of the worker, including chunking, retries, recovery, staging and assembly, runs for real. list_voices and, where needed, _chunk_plan_for are monkeypatched too; a tiny plan of 160 characters makes multi-chunk behaviour fast to exercise.

Make the output a transcript. The long-form tests echo each chunk’s text back as its “audio”. The assembled file must then equal the source text exactly, which turns “is anything missing or duplicated?” into a string comparison.

Regression tests that fail on the old code. Names describe the behaviour, not the function: test_mid_chunk_disconnect_is_retried_not_saved, test_paragraph_break_on_the_warmup_boundary_still_completes, test_resume_reuses_saved_chunks_even_when_cleanup_is_not_idempotent. The README states these “fail on the pre-fix code”.

UI tests across geometry and fonts. pytest-qt creates real widgets offscreen; layout tests are parametrised over window sizes and enlarged system fonts, because Windows’ default UI font is wider than macOS’s and most UI regressions in August 2026 were clipping under wider fonts.

Measure memory directly. tracemalloc bounds peak allocation during a simulated 12-hour job.

17.3 Packaging and platform tests

Unit tests cannot see a missing Qt plugin or an unbundled module. Those are caught by the CI self-tests, run against six artifacts across two operating systems, four of them with live network synthesis (Chapter 16). Platform-specific code (Windows proxy reading, the Proactor loop, Windows file-lock retries) runs for real only on the Windows runner.

17.4 What the automated suite does not cover

  • Real multi-hour synthesis against the live service. That is scripts/stress_longform.py, run manually.
  • Playback in the Preview feature (it shells out to afplay or Windows MCI).
  • Code signing and Gatekeeper behaviour, since builds are unsigned.
  • Intel Macs and macOS versions below 15, which are unsupported.

17.5 Before every release

A practical checklist, assembled from the workflow and the project’s own release notes:

  1. QT_QPA_PLATFORM=offscreen pytest -q passes locally on macOS, and on Windows if any platform code changed.
  2. APP_VERSION and pyproject.toml agree; release_notes/vX.Y.Z.md exists.
  3. If dependencies changed: the pins in requirements.txt were updated deliberately, and the minimum-macOS check still passes.
  4. For pipeline changes: a manual workflow_dispatch run is green before tagging.
  5. For reliability changes: a live run of scripts/stress_longform.py for at least an hour of audio with a slow voice such as Andrew.
  6. Tag and push; confirm all four artifacts and the notes appear on the release page.
