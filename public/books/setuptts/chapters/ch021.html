15 Packaging and Distribution

15.1 The problem packaging solves

On the developer’s machine SetupTTS runs as python main.py inside a virtual environment containing PySide6, edge-tts, aiohttp and their native libraries. The end user has none of that, often not even Python. Packaging turns the project into something that starts with a double-click.

15.2 What PyInstaller does

PyInstaller starts at main.py, follows every import it can see, and collects:

  • the Python interpreter as a shared library, and a small native bootloader executable that starts it;
  • the standard library modules and every third-party package that was imported, compiled to bytecode;
  • native libraries: Qt’s frameworks, Qt plugins (platform, image formats, styles), aiohttp’s C accelerators, OpenSSL;
  • data files declared in the spec: the app’s stylesheet and icons, certifi’s CA bundle, edge-tts’s data.

At run time the bootloader sets up the embedded interpreter and runs main.py. Two attributes tell the app it is frozen: sys.frozen, used by diagnostics.build_kind, and sys._MEIPASS, the folder holding the bundled files, used by resource_path:

def resource_path(relative: str) -> Path:
    if hasattr(sys, "_MEIPASS"):
        return Path(sys._MEIPASS) / relative
    return Path(__file__).parent.parent.parent / relative

That is why the end user needs no Python: the interpreter and every dependency are inside the app.

15.3 The spec file

setuptts.spec is Python executed by PyInstaller. The important parts:

  • Version. Read from app/__init__.py with a regular expression, so “nothing here needs editing on a bump”.
  • Data. app/assets as app/assets; collect_data_files("edge_tts") and collect_data_files("certifi").
  • aiohttp and friends. collect_all for aiohttp, aiosignal, frozenlist, multidict and yarl. Several of these have optional C accelerators that static analysis can miss, which used to produce “ModuleNotFoundError: No module named ‘aiosignal’” only in the packaged build.
  • Hidden imports. All edge-tts submodules, the Qt modules used, certifi, platformdirs, and on Windows asyncio.proactor_events and asyncio.windows_events.
  • Excludes. Qt modules the app never uses (WebEngine, 3D, Charts, Multimedia, Bluetooth and others) and large scientific packages, to keep the bundle small.
  • No UPX, no console. UPX compression is off so CI does not need it installed; console=False makes a windowed app with no terminal.

15.3.1 macOS: an .app bundle

On macOS the spec’s BUNDLE step produces dist/SetupTTS.app with bundle id com.setuptts.setuptts and an Info.plist whose key line is:

"LSMinimumSystemVersion": "15.0",   # PySide6 6.10+ (shiboken) needs macOS 15

v1.5.8 declared macOS 12, but its bundled Qt libraries already required 15, so it failed on older systems with no useful message. The release notes now state the real requirement, and CI checks it against every binary (Chapter 16).

The bundle is shipped two ways. create-dmg builds a disk image with the drag-to-Applications layout. ditto -c -k --keepParent builds a zip; build_macos.sh explains why not plain zip: ditto “preserves symlinks, resource forks, and extended attributes”, and plain zip “can corrupt the bundle”.

15.3.2 Windows: two builds for two situations

Build Spec Shape Shipped as Why
Installer setuptts.spec onedir: SetupTTS.exe + _internal\ folder SetupTTS-Windows-Installer.exe starts instantly; the installer keeps the folder together
Portable setuptts_portable.spec onefile: a single SetupTTS.exe SetupTTS-Windows-Portable.zip runs from anywhere, even directly from the zip

Historical. Both shapes were learned from user-visible failures in March 2026:

  • Commit 7bd5fb1 moved the main Windows build from onefile to onedir. A onefile EXE extracts its roughly 100 MB runtime to %TEMP% on every launch, and Windows Defender scans those files, which produced “a 5-30 s cold-start delay”.
  • Commit c50a0df reintroduced onefile for the portable download only. A onedir build in a zip fails when the user double-clicks the EXE inside the zip without extracting: the _internal folder stays in the archive and Windows reports “Failed to load Python DLL … python312.dll”.

The Windows EXE also gets a VERSIONINFO resource generated by the spec, so Explorer’s Properties ▸ Details shows the version: “otherwise every SetupTTS.exe looks identical, and an old copy launched from a stale shortcut can’t be told apart”. The window title shows the version for the same reason.

15.3.3 The Inno Setup installer

installers/windows.iss installs the onedir folder:

  • PrivilegesRequired=lowest: installs per user without administrator rights; {autopf} then resolves to %LOCALAPPDATA%\Programs, which is exactly where CI looks for the installed EXE.
  • [InstallDelete] removes the previous _internal folder on upgrade, so a stale python3xx.dll or Qt plugin from an older build can never be loaded by the new one.
  • A fixed AppId GUID makes upgrades replace the existing installation.
  • User data (settings, history, unfinished jobs) is left in place on uninstall; the line to remove it is present but commented out.

15.4 Making the frozen app work like the source app

Three problems appear only after freezing, and each has a fix in the code:

  1. Certificates. A frozen Python cannot locate a CA bundle, so app/main.py sets SSL_CERT_FILE to certifi’s bundled file before anything else.
  2. Stylesheet assets. Qt resolves stylesheet url()s against the working directory, so style.py rewrites them to absolute paths inside the bundle.
  3. SVG support. The dropdown chevrons are SVG and need Qt’s SVG image-format plugin. Without it they “silently vanish”. The self-test checks for exactly this.

15.5 The packaged self-test

app/selftest.py is a mode of the real app: SetupTTS --selftest result.json [--network]. Because a windowed Windows build has no console, it writes its results to a JSON file. Its checks:

Check Verifies
assets the stylesheet, icon and chevron SVG are present in the bundle
imports aiohttp, edge-tts, sqlite3 and QtNetwork import
tls edge-tts’s voice and synthesis code share SetupTTS’s TLS context, and it trusts at least as many CAs as certifi alone
qt_gui a QApplication starts, the stylesheet loads, the SVG chevron and PNG icon render, and the whole UI module imports
voices (network) the live voice list contains en-US-AndrewNeural and en-US-AvaNeural
synthesis (network) a test sentence streams completely by the same _stream_incomplete_reason check, with a plausible duration

Verified by runtime experiment. Run from source on the analysis machine, the self-test passed every check: 137 CA certificates via certifi and 137 with the system store, Qt 6.11.0, 322 voices, and a synthesis of 33,264 bytes (5.5 s).

15.6 Local builds

build_macos.sh cleans, runs PyInstaller, verifies that the stylesheet, icon and edge-tts are inside the bundle, zips with ditto, then extracts the zip again and checks that the binary is executable. build_windows.ps1 and build_windows.bat build the portable EXE. The installer is built only in CI, where Inno Setup is installed.
