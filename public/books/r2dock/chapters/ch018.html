12 Public URLs and Cloudflare REST API Integration

Users want links they can paste into a web page or a chat. R2 can serve objects publicly, but not through the S3 endpoint, and a bucket’s public address cannot be learned through the S3 protocol at all. This chapter covers the second credential R2Dock may hold, how it resolves a bucket’s public address, how it builds a correct link for any key, and how it avoids leaking the token, trusting hostile API data, or hammering the Cloudflare application programming interface (API). Chapter 21 (Credential Storage and Authentication) owns secret storage.

Two Doors Into the Same Bucket

All object operations go to the account’s S3 endpoint from endpoint_url in crates/r2dock-core/src/connections.rs, which always requires signed requests (PLAN.md section 8.9); a browser following a plain link there is refused. Cloudflare’s public buckets documentation describes two independent public options, both enabled in the dashboard rather than through S3 calls. A custom domain must be “added as a zone in the same account as the R2 bucket” and can use Cloudflare’s cache. A managed r2.dev subdomain is “for non-production use cases,” rate limited, and lacks caching and access controls. An object might be reachable as https://media.example.com/covers/cover%20art.webp, through r2.dev, or not at all, and PLAN.md says plainly: “The app cannot reliably know whether a bucket is public using S3 credentials.” Presigned URLs, a third kind of link, are not created in this version.

Two Credentials With Different Jobs

Cloudflare’s R2 API token page explains that the Access Key ID is the token’s id and the Secret Access Key is “the SHA-256 hash of the API token value.” The S3 secret never leaves the machine; only Signature Version 4 signatures do (Chapter 8). The optional second credential is the token value itself, which Cloudflare’s Representational State Transfer (REST) API accepts as Authorization: Bearer <token>. The connection stores it as api_token: Option<SecretLocation>, a reference into the operating system credential store or a session-memory marker, never the token, next to a per-bucket public_base_urls map. The Connect form clears it from React state after saving, and validate_api_token accepts printable ASCII up to 256 characters.

The token value is more sensitive than the S3 secret, which is only its hash. The token page states that Object permissions “work only with the S3-compatible API, not the Cloudflare REST API,” while Admin Read can “view bucket configuration.” The fetched domain endpoint references list no required permission, so a user who pastes an Object Read & Write token, the kind R2Dock’s help recommends for S3 access, should expect the domain lookup to be refused. PLAN.md marks this [Verify], and the hint in src/features/preview/publicLink.ts says “an Admin Read token can.”

Resolving a Link

Figure 12.1 shows the order in which R2Dock resolves a link.

The order lives in resolve_base in crates/r2dock-core/src/public_domain.rs, a pure function. A base URL typed in Bucket settings always wins, since the user may front the bucket with something the API knows nothing about. Next comes the first enabled custom domain whose ownership and certificate are active, else the first enabled one, and r2.dev last. The link carries a PublicLinkSource so the Details panel can label it.

resolve in src-tauri/src/public_links.rs returns a manual link without any network call, returns NotConfigured without a token, and only then looks up domains; manual_url_wins_and_needs_no_api_call asserts the mock API received nothing. Each of the six statuses maps, in publicLinkHint, to one calm sentence pointing to Bucket settings.

Building the URL From a Key

The link is the base, a slash, and the key, but the key cannot go in raw. A # would turn the rest into a fragment browsers never send, a ? would start a query, and a literal % would start an escape.

Source: crates/r2dock-core/src/keys.rs, lines 198 to 210

/// Encode a key for use in a URL path, keeping `/` separators.
pub fn percent_encode_key(key: &str) -> String {
    let mut out = String::with_capacity(key.len());
    for b in key.bytes() {
        match b {
            b'A'..=b'Z'
            | b'a'..=b'z'
            | b'0'..=b'9'
            | b'-'
            | b'_'
            | b'.'
            | b'~'
            | b'/' => {
                out.push(b as char)
            }
            _ => out.push_str(&format!("%{b:02X}")),
        }
    }
    out
}

It works on bytes, so non-ASCII characters are encoded as UTF-8. It keeps the unreserved characters of RFC 3986 section 2.3 plus /, and encodes everything else, including + (which form decoders read as a space), %, and space. The test links_encode_each_segment checks that a+b/100%.txt becomes a%2Bb/100%25.txt. The same function encodes the copy source in Chapter 11 (Object Management and Consistency).

One edge is open. R2 allows keys with . or .. segments, and validate_key does not reject them. RFC 3986 section 5.2.4 removes dot segments during resolution, and the WHATWG URL Standard treats percent-encoded forms such as %2e%2e as a double-dot path segment, so encoding would not help. A link for a/../b.txt would likely be normalized to /b.txt. This was not tested against a browser or Cloudflare and is recorded as an open question.

A manual base URL passes validate_public_base_url: it must start with https://, its host may contain only ASCII letters, digits, dots, hyphens, and colons, and it may not contain ?, #, spaces, or @. The @ rule blocks user-info tricks like https://media.example.com@evil.example.

Talking to the Cloudflare API

With no manual URL and a saved token, R2Dock calls two read-only endpoints from the Cloudflare API reference: GET /accounts/{account_id}/r2/buckets/{bucket_name}/domains/custom and .../domains/managed, which return custom domains with enabled and status fields and the r2.dev domain with its enabled flag. The client is CfApiClient in crates/r2dock-r2/src/cfapi.rs, a small reqwest wrapper independent of the AWS software development kit (SDK).

Source: crates/r2dock-r2/src/cfapi.rs, lines 79 to 92

pub fn with_base_url(
    base: &str,
    timeout: Duration
) -> Result<Self, CfApiError> {
    let http = reqwest::Client::builder()
        .https_only(base.starts_with("https://"))
        .redirect(reqwest::redirect::Policy::none())
        .user_agent(concat!("R2Dock/", env!("CARGO_PKG_VERSION")))
        .connect_timeout(timeout)
        .timeout(timeout)
        .build()
        .map_err(|_| CfApiError::Network)?;
    Ok(Self {
        http,
        base: base.trim_end_matches('/').to_string(),
    })
}

Each setting removes a way to misuse the token. The production constructor cloudflare() uses the fixed base https://api.cloudflare.com/client/v4, so https_only is on. Redirects are off, so a redirect cannot carry the Authorization header to another host. A 15 second timeout covers the whole request. This #[doc(hidden)] constructor also lets tests use an http:// loopback mock.

bucket_domains first checks the path values: the account ID may hold only ASCII letters, digits, and hyphens, the bucket name only letters, digits, hyphens, and dots (tested by unsafe_path_values_are_refused_before_any_request). Both calls run with tokio::join!; a custom domain failure fails the lookup, but a managed domain failure only omits r2.dev. Responses over 1 MiB are refused. Statuses become a typed CfApiError with fixed messages, and a test asserts the token appears in neither its display nor debug form. In fetch, permission errors become TokenDenied, NotFound becomes NoDomain, and the rest Unavailable; a credential store entry deleted outside the app becomes TokenMissing. The store read runs in spawn_blocking. The cf-r2-jurisdiction header is sent only for eu and fedramp.

Domain Names Are Untrusted Input

A returned domain ends up in a shared link, the UI, and the operating system’s browser opener. A spoofed response with markup, a port, user info, or a carriage return could attempt injection or disguise a host. validate_domain_host accepts only plain DNS names: at most 253 characters, labels of 1 to 63 lowercase letters, digits, or hyphens without a hyphen at either end, at least one dot, and a final label that is not all digits, which excludes IPv4 literals. The table test domain_validation covers the failures. parse_managed also requires the .r2.dev suffix. The scheme never comes from the API; links are always https:// plus a validated host. Refusing non-ASCII names costs internationalized domains but avoids look-alike characters.

Caching and Request Coalescing

Every file in a bucket shares its domains, and users click through files quickly. PublicLinks caches lookups per connection and bucket: found results for five minutes (FOUND_TTL), failures for 30 seconds (FAILED_TTL), at most 256 buckets. Each entry stores a connection generation that increases when the connection is saved or its credentials prove bad, so an edited token never reuses old results. Caching alone does not stop a burst of simultaneous misses, so domains coalesces them.

Source: src-tauri/src/public_links.rs, lines 113 to 127

let key: CacheKey = (id, bucket.to_string());
if let Some(hit) = self.cached(&key, connections.generation_of(id)) {
    return hit;
}
let gate = self.inflight.lock().entry(key.clone()).or_default().clone();
let _turn = gate.lock().await;
// Another request may have finished the lookup while this one waited.
let generation = connections.generation_of(id);
if let Some(hit) = self.cached(&key, generation) {
    return hit;
}
let lookup = self.fetch(connections, id, bucket).await;
self.store(key.clone(), generation, lookup.clone());
self.inflight.lock().remove(&key);
lookup

This is double-checked locking in async code. Each key gets an Arc<tokio::sync::Mutex<()>>; the first caller fetches while others wait without blocking a runtime thread, then find the fresh entry. A short parking_lot::Mutex guards the maps and is never held across an .await. Reading the generation before fetching means a connection changed mid-lookup leaves an entry the next request ignores. The frontend adds a 60 second TanStack Query cache, and nothing polls, as PLAN.md section 8.9 requires.

Security Properties and Limits

No command returns the token; the webview sees only a has_api_token boolean. In Rust it is a secrecy::SecretString, exposed only in bearer_auth and sent only to the fixed host. PLAN.md section 9.8 names the residual risk: “The token’s own permissions decide what it could do if stolen.” The object_public_url command logs status and source but “The link itself is never written to the activity log,” and open_external refuses anything not starting with https://, containing whitespace or control characters, or 4,096 bytes or longer, recording only the host.

Cloudflare’s presigned URL documentation says presigned URLs work only on the S3 endpoint and are bearer tokens: “Anyone with the URL can perform the specified operation until it expires.” PLAN.md plans them for a later version with an explicit expiry and a warning; media previews use a custom protocol instead (Chapter 24), and log redaction already strips X-Amz-Signature.

Two evidence limits remain. PLAN.md says the REST endpoints were “Confirmed against the API reference 2026-10-18; not yet tested live,” and tests use only the mock in crates/r2dock-testkit/src/cloudflare.rs. And the API reference lists us and fedramp-high jurisdictions that R2Dock’s Jurisdiction enum lacks.

Working on This Code

Pure decisions live in crates/r2dock-core/src/public_domain.rs and keys.rs; the HTTP client in crates/r2dock-r2/src/cfapi.rs; caching and status mapping in src-tauri/src/public_links.rs; the UI in src/features/preview/. A new link source means extending PublicLinkSource and resolve_base, a resolution_order test row, regenerated bindings, and a SOURCE_LABEL entry. A new endpoint should reuse CfApiClient::get to inherit the size cap, status mapping, and bearer header, and must validate every path value first. Run cargo test -p r2dock-core public_domain, cargo test -p r2dock-r2 cfapi, cargo test -p r2dock public_links, and npm test.

Never return, log, or embed the token in an error; send it only to the fixed host over HTTPS with redirects off. Validate every domain with validate_domain_host, always build https:// links, encode keys with percent_encode_key, keep lookups on demand, and never hold the parking_lot mutex across an .await.
