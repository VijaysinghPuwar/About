34 Your First Contribution

This chapter covers what to install, how to run R2Dock against a local storage server without any cloud account, the project’s rules, the checks to run before a pull request, how to add a command, how to report a security problem, and where to find a first task. Every instruction comes from files tracked in the repository: README.md, CONTRIBUTING.md, SECURITY.md, the manifests, and the continuous integration (CI) workflow.

Toolchain Prerequisites

The README’s “Build from source” section requires “Rust 1.94+, Node.js 22+, and the Tauri prerequisites for your OS”, linking to the Tauri prerequisites page. The workspace Cargo.toml enforces rust-version = "1.94" with edition = "2024". There is no rust-toolchain file, and CI installs current stable Rust with the rustfmt and clippy components, which the checks below need. package.json has no engines field; Node.js 22 is stated by the README and installed by CI. The project uses npm with a committed package-lock.json, so install with npm ci.

Per platform, the Tauri page and the CI runners agree as follows. On Linux, CI (Ubuntu 22.04) installs libwebkit2gtk-4.1-dev, libayatana-appindicator3-dev, librsvg2-dev, patchelf, libssl-dev, libxdo-dev, libdbus-1-dev, build-essential, and ffmpeg. On macOS, the Tauri page asks for Xcode or just the Xcode Command Line Tools, and CI adds FFmpeg from Homebrew. On Windows, the Tauri page asks for the Microsoft C++ Build Tools (“Desktop development with C++”) and WebView2, which current Windows includes; CI adds FFmpeg from Chocolatey and the NASM assembler, without saying which dependency needs NASM.

FFmpeg is optional; tests that need it skip themselves without it (Chapter 29, Automated Testing Strategy). One version rule is easy to break: the Rust tauri crate and the JavaScript @tauri-apps/api package must stay on the same minor version. The CHANGELOG records that release builds failed until “the Rust Tauri crate is now 2.12, matching the JavaScript API package”. If you update one, update the other.

Cloning and the First Build

Clone the public repository and install the frontend dependencies:

git clone https://github.com/VijaysinghPuwar/R2Dock.git
cd R2Dock
npm ci

npm run tauri dev builds the Rust core in debug mode, starts the Vite server (beforeDevCommand in src-tauri/tauri.conf.json, port 1420), and opens the app with frontend hot reload. npm run tauri build builds an installer, and cargo test --workspace && npm test runs the default tests. The first Rust build compiles a large dependency tree; later builds are incremental.

Chapter 3 (A Guided Tour Through the Repository) describes the layout: crates in crates/, the Tauri crate src-tauri (package r2dock), and the React frontend in src/.

Running the App Against a Local S3 Server

You do not need a Cloudflare account to work on R2Dock, and you should not use a real bucket for development. The test kit includes a small program that serves an S3-compatible API from a folder on your machine. Its source is crates/r2dock-testkit/src/bin/local-s3.rs, and its header gives the command:

cargo run -p r2dock-testkit --bin local-s3 -- 9300 media-library

The first argument is the port (9300 by default) and the rest are buckets to create. The server binds only to 127.0.0.1, keeps objects in a folder named r2dock-local-s3-<port> in the system temporary directory, and accepts the fixed test credentials ACCESS_KEY and SECRET_KEY from crates/r2dock-testkit/src/lib.rs. It is the same s3s-based S3-compatible server the integration tests start in process (Architecture Decision Record, or ADR, 0005).

To point the app at it, start the development build in a second terminal with the endpoint override:

R2DOCK_DEV_ENDPOINT=http://127.0.0.1:9300 npm run tauri dev

The override is read in src-tauri/src/lib.rs inside #[cfg(debug_assertions)], so release builds compile it out, and it is accepted only if it starts with http://127.0.0.1:. ConnectionService passes it to every client, and R2Client::new in crates/r2dock-r2/src/client.rs uses it instead of the URL built from the account identifier.

In the app, connect with the test keys. The account ID is not used for the address, but validate_account_id in crates/r2dock-core/src/connections.rs still requires letters and digits only, at most 64 characters (the form only warns when it is not the usual 32 hexadecimal characters). The optional bucket field can name the buckets you created. Uploads, downloads, moves, deletes, pauses, and restarts can then be exercised end to end; Chapter 33 (Complete End-to-End Execution Walkthrough) makes a good script for a first session.

The Project Rules

CONTRIBUTING.md asks contributors to read PLAN.md (architecture, security, testing) and DESIGN.md (interface) before changing a subsystem. Its ground rules: priorities are “secure, then stable, then easy for beginners, then fast”; Rust owns R2 communication, credentials, file system access, and transfers, while React only renders and calls the typed commands in src/ipc/commands.ts; no command returns a secret, and secrets never go to files, browser storage, frontend state, logs, or error messages; the frontend never supplies local paths, and remote content is never rendered as HTML; nothing may imply that R2 has folders, rename, atomic move, versioning, or trash; and no code is copied from GPL projects, while MIT code needs attribution in THIRD_PARTY_NOTICES.md.

Every functional change needs tests, with table or property tests for Rust edge cases; tests use the local server, never production buckets; documentation never describes planned features as done; and a new dependency must remove real complexity, be justified in the pull request, and be followed by cargo audit and npm audit. Decisions are recorded as ADRs in docs/adr/, and a change that contradicts one needs a new ADR.

SECURITY.md’s design summary lists what a contribution must preserve: the credential store with no plaintext fallback, redacted logs, no file system, shell, or HTTP access for the webview, a command allowlist, a strict Content Security Policy, opaque identifiers for local paths, and confirmation tokens for deletes (Chapters 21 to 25).

Checks Before a Pull Request

CONTRIBUTING.md gives the exact commands to run before opening a pull request:

cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
npm run lint && npm run typecheck && npm test && npm run build

They mirror the CI test job on Ubuntu 22.04, macOS, and Windows (fail-fast: false). CI also runs cargo test -p r2dock-media --test live_tools -- --ignored, which downloads and verifies the pinned FFmpeg package and needs network access; on Linux, git diff --exit-code -- src/ipc/bindings, which fails if the TypeScript bindings regenerated by cargo test were not committed; and an audit job with npm audit --omit=dev and cargo audit.

For changes to the transfer engine or the activity log, the README lists two heavier stress runs used before releases:

cargo test -p r2dock-transfer --release --test stress -- --include-ignored
cargo test -p r2dock --release --test activity_stress -- --include-ignored

Adding a New Command

A new Tauri command touches more files than a newcomer expects, because each is a separate security gate (Chapter 22, Tauri Security Architecture, and Chapter 26, React and Tauri IPC). Write the function with #[tauri::command] in the matching module under src-tauri/src/commands/, keeping it thin: validate arguments with the helpers in commands/mod.rs (such as bucket_arg, key_arg, and prefix_arg), call a service or crate function, and map errors to AppError. Register it in tauri::generate_handler! in src-tauri/src/lib.rs. Add its name to the COMMANDS list in src-tauri/build.rs, which passes the list to tauri_build::AppManifest::commands so that only listed commands exist for the webview; the build then generates src-tauri/permissions/autogenerated/<name>.toml, which is tracked and should be committed. Add allow-<name-with-dashes> to src-tauri/capabilities/main.json. Add a typed wrapper to src/ipc/commands.ts, the only module that calls invoke. Any new argument or result type derives TS with #[ts(export)], and cargo test writes it to src/ipc/bindings through the TS_RS_EXPORT_DIR setting in .cargo/config.toml. CONTRIBUTING.md asks for a reason for every new command in the pull request.

Two rules decide most reviews of a new command: it must not return a secret, and it must not accept a local path from the page. If a feature needs a local path, follow the picker pattern in src-tauri/src/dialogs.rs and the selection registry in src-tauri/src/state.rs.

Reporting a Security Issue

Do not open a public issue for a vulnerability. SECURITY.md asks reporters to use GitHub’s private reporting: open the repository’s Security tab and choose “Report a vulnerability”. A report should include the version, the operating system, steps to reproduce, and the expected impact, and must never contain real R2 credentials. Only the latest release receives fixes while the project is at version 0.x. In scope are leaks of secrets to logs, files, the webview, or error messages; path traversal or overwrite through object keys; the webview gaining access to files or commands it should not have; and unsafe rendering of object names or previews. A compromised operating system or user account, malware running as the same user, and issues in R2 itself are out of scope.

Finding a First Task

The tracked files contain no task list, so these are suggestions drawn from the book’s analysis, not assigned work; check with the maintainers before anything large.

Documentation is the gentlest start: Chapter 32 (Engineering Trade-offs and Future Improvements) lists where PLAN.md, SECURITY.md, or comments disagree with the code, such as the 0.4.0 status line, the claim that no benchmarks exist, the RAII abort guard, and the Cancelling state. Each fix is small and teaches its area.

Small code tasks with clear tests come next. The unused exports isCredentialError and isOfflineError in src/lib/errors.ts can be removed or wired up. The hardcoded row heights in src/features/browser/Explorer.tsx duplicate a design token. A redacting Debug for ConnectionInput in src-tauri/src/dto.rs would enforce a PLAN.md rule. The Jurisdiction enum lacks the US jurisdiction that Cloudflare documents, which needs care in endpoint_url and its tests.

Missing tests are valuable and low risk. The book’s authors found no test of the download MD5 mismatch path, although the test kit’s object_path allows corrupting a stored object, and none for a failed multipart job returning as Interrupted after a restart. No CI job checks the Rust 1.94 minimum, and no benchmark measures a scheduling pass or interface responsiveness (Chapter 30, Performance Benchmarking, describes the method).

Larger tasks, such as a directory sync after snapshot renames, a cleanup of orphaned multipart uploads, a move journal, or release signing, touch recovery or security and should start with a discussion and probably an ADR.

Working on This Code

Start from the chapter that owns the area and its Working on This Code section. Run the narrowest test first (for example cargo test -p r2dock-transfer --test engine), then the full checklist. Keep commits focused and report real test results. Never put real credentials, account identifiers, bucket names, or domains in code, tests, screenshots, or issues; use the test kit’s keys and fictional names such as media-library and media.example.com.
