18 Audio Compression Internals

Chapter 17 (How FFmpeg Integrates with Rust) showed how R2Dock runs FFmpeg safely. This chapter covers what it asks FFmpeg to do with audio and, just as important, when it does nothing. The rule from docs/plans/media-compression.md is that the original file is never modified and nothing is compressed unless the saving is real. A low bitrate spoken word recording can often lose half its size harmlessly; a well encoded MP3 song would only get worse. The code must tell these apart cheaply before spending minutes of CPU.

Audio Concepts You Need

The sample rate is samples per second: 44,100 Hz is CD quality and 22,050 Hz suffices for clear speech, since a signal holds frequencies up to half its sample rate. Channels are separate signals: one for mono, two for stereo, six for 5.1. The bitrate is measured in kilobits per second (kbps); uncompressed CD quality PCM (pulse code modulation) in WAV needs about 1,411 kbps.

A lossless codec such as FLAC (Free Lossless Audio Codec) returns the exact samples at roughly half the size. A lossy codec such as MP3, AAC (Advanced Audio Coding), or Opus discards what the ear is unlikely to notice, but every re-encode loses a little more, so R2Dock is reluctant to re-encode lossy files. Constant bitrate (CBR) spends the same bits every second; variable bitrate (VBR) targets a quality level, so its header bitrate can mislead and R2Dock computes the real bitrate from size and duration. Loudness is measured in dBFS, decibels relative to full scale: 0 is the loudest sample value and digital silence is negative infinity.

RFC 6716, the Opus specification, says it “scales from low bitrate narrowband speech at 6 kbit/s to very high quality stereo music at 510 kbit/s” and that its music layer “always operates internally at a sample rate of 48 kHz”, which is why R2Dock never sets an Opus sample rate.

Probing in Process with Symphonia

Starting FFmpeg per file would be slow, so probe_audio in crates/r2dock-media/src/probe.rs reads container headers in process with Symphonia, a pure Rust library (Mozilla Public License 2.0, listed in THIRD_PARTY_NOTICES.md). It blocks, so callers use spawn_blocking (Chapter 5). The codec comes from the content, never the extension: the test content_decides_not_the_name writes WAV data as really-wav.mp3, UPPER.WAV, and no-extension and expects PCM each time. The AudioProbe result also counts audio tracks, notes any video track, sums embedded picture bytes, and records R2Dock’s marker tag.

Symphonia reports no bitrate, so real_bitrate computes audio bytes times eight over duration, after subtracting cover art; a 1 MB cover would otherwise add about 7 percent to a one hour 32 kbps book.

Two plan statements disagree with the code. The plan says Symphonia “cannot read Opus” and that unreadable files “fall back to ffprobe.” In fact the ogg feature is enabled, codec_of maps CODEC_ID_OPUS, and wav_to_mp3_flac_and_opus probes Opus output with probe_audio. And pipeline::prepare reports an unreadable file as Unchanged::NotAudio unless its extension suggests video, which goes to the ffprobe video path; audio has no ffprobe fallback.

Speech or Music

Speech survives low bitrates; music does not. R2Dock guesses which it has.

Source: crates/r2dock-media/src/classify.rs, lines 27 to 50

/// Highest sample rate that still counts as speech.
const SPEECH_MAX_RATE: u32 = 24_000;
/// Highest real bitrate that still counts as speech.
const SPEECH_MAX_BPS: u64 = 64_000;

// ...
pub fn classify(probe: &AudioProbe, choice: ContentOverride) -> Content {
    match choice {
        ContentOverride::Speech => return Content::Speech,
        ContentOverride::Music => return Content::Music,
        ContentOverride::Auto => {}
    }
    let mono = probe.channels == Some(1);
    let low_rate = probe.sample_rate.is_some_and(|r| r <= SPEECH_MAX_RATE);
    let low_bitrate = !probe.codec.is_lossless()
        && probe.real_bitrate().is_some_and(|b| b <= SPEECH_MAX_BPS);
    if mono || low_rate || low_bitrate {
        Content::Speech
    } else {
        Content::Music
    }
}

This is a heuristic, not sound analysis: a file already stored in mono, at 24 kHz or less, or at 64 kbps or less has accepted speech grade quality. Lossless files skip the bitrate rule, since quiet FLAC music can have a low bitrate. Mono music is misclassified, so the user can override per upload, and the override wins first (decision_table).

The Bitrate Ladder

ladder in crates/r2dock-media/src/plan.rs picks the target from settings stored in crates/r2dock-core/src/compression.rs: Mode (KeepFormat by default, or Smallest), SpeechQuality (32 or 48 kbps, default 32), MusicQuality (Standard or Smaller), LosslessAction (MP3 by default, FLAC, or keep), a minimum saving (default 15 percent, clamped to 5 to 50), and allow_downmix (off).

Targets are defined per output layout, so stereo gets about twice the mono bitrate and keeping both channels never costs quality. Speech becomes CBR MP3 at 32 kbps mono or 64 stereo (48 or 96 at the higher setting). Music becomes VBR MP3 at LAME quality 4 or 6; the FFmpeg codecs documentation calls the libmp3lame q option the “constant quality setting for VBR”, with lower numbers meaning higher quality, and approx_kbps stores the expected average (about 165 or 115 kbps stereo) for estimates. Opus targets are 24 and 48 kbps for mono and stereo speech, 64 and 96 for music.

The second half of ladder chooses by source codec and mode, returning the encoding and a new extension, or none when the key keeps its name. In “Keep format”, an MP3 stays an MP3 and an Opus file stays Opus under the same key, so links keep working. In “Smallest”, MP3, AAC, and Opus sources become .opus, which changes the key; in R2 that is a new object, not a rename (Chapter 11). Lossless sources become MP3 (or Opus in “Smallest”), FLAC, or are kept with LosslessKept. Vorbis and unknown codecs get UnsupportedFormat. AAC stays AAC at 64 or 128 kbps only to keep the format, because the plan measured FFmpeg’s native AAC encoder as weak at low bitrates (20 percent saved at 48 kbps on speech). Opus uses -application voip for speech, which the codecs documentation says will “favor improved speech intelligibility”, and audio for music.

On a 10 minute slice of a 64 kbps mono spoken word MP3 on an Apple silicon Mac, the plan records MP3 at 32 kbps saving 50 percent in 1.2 seconds and Opus at 24 kbps saving 64 percent in 3.6 seconds (single measurements, not re-run for this book). MP3 is the default because it plays everywhere and keeps keys unchanged.

Channels: Never Lose Sound Silently

Folding stereo to mono halves the bitrate but alters or erases anything that differs between left and right. decide reduces channels only when that loses nothing or the user allows it.

Source: crates/r2dock-media/src/plan.rs, lines 236 to 256

    let source_channels = probe.channels.unwrap_or(2);
    // Channels are only reduced when that loses nothing (left and right
    // proven identical) or the user allows it: a mono mix erases sound that
    // differs between channels. With permission, speech becomes mono and
    // anything else at most stereo.
    let mono = source_channels == 1
        || (source_channels == 2 && inputs.identical_channels)
        || (s.allow_downmix && content == Content::Speech);
    let (encoding, extension) = ladder(probe, content, mono, s)?;
    let channels = match encoding {
        // Lossless output keeps every channel.
        Encoding::Flac => source_channels,
        // The veto comes before any other channel decision.
        _ if source_channels > 2 && !s.allow_downmix => {
            return Err(SkipReason::Multichannel {
                channels: source_channels,
            });
        }
        _ if mono => 1,
        _ => source_channels.min(2),
    };

A mono source stays mono. Stereo becomes mono only if identical_channels is proven or the user allows downmixing for speech. More than two channels, such as 5.1, is uploaded unchanged with SkipReason::Multichannel unless downmixing is allowed, since lossy targets hold at most two channels; FLAC keeps every channel. The comment “The veto comes before any other channel decision” records a fixed bug: the plan’s notes after 0.4.1 describe six channel 22.05 kHz audio once planned as mono because the speech rule ran first. The test multichannel_veto_comes_before_speech guards the order.

Proving Two Channels Are Identical

Many spoken word files are “fake stereo”. args::channel_difference builds an FFmpeg filter graph that splits the first audio track with asplit; one copy goes through pan to c0-c1 (left minus right), the other to the mix 0.5*c0+0.5*c1, and each ends in volumedetect, which the FFmpeg filters documentation says reports the “maximum volume (on a per-sample basis)”. Identical channels subtract to silence, a peak of negative infinity.

Lossy decoding leaves tiny differences even for identical channels, so channels_match in crates/r2dock-media/src/ffmpeg/mod.rs requires the difference to be at most IDENTICAL_CHANNELS_DB (-60 dBFS) and also at least SIGNAL_MARGIN_DB (40 dB) below the mix’s peak, unless it is exact silence. The second rule catches quiet recordings with opposite channels, whose difference can fall near -68 dBFS while the mix is almost silent because the channels cancel. A missing measurement never counts as identical. The plan’s calibration with synthetic speech found -91 dB for identical channels in WAV or 128 kbps MP3, but -31 dB for AAC at 96 kbps and -51 dB for Opus at 64 kbps, which therefore stay stereo (channel_match_rules).

The check covers the whole stream. An earlier version sampled 30 seconds from the middle and folded a file whose opposite phase introduction then vanished; the tests speech_that_only_matches_in_the_middle_stays_stereo and stereo_that_only_looks_mono_in_the_middle_stays_stereo in tests/preserve.rs reproduce that trap. Because a full decode costs time, wants_channel_check runs it only for a stereo source planned as stereo, lossy speech; music is excluded (identical_stereo_music_is_not_folded_to_mono). A check that fails for any reason except cancellation leaves the file stereo; success re-plans with identical_channels set. The plan reports 2.1 seconds per hour of 64 kbps stereo MP3. The upload review estimate skips this check, so real results can be smaller.

Sample Rates

For MP3, mp3_rate picks the highest of the nine MP3 rates (8 to 48 kHz) at or below both the wanted rate (22.05 kHz for speech, 44.1 kHz for music) and the source. A 16 kHz source therefore stays at 16 kHz instead of being upsampled, while 24 kHz drops to 22.05 kHz (audiobook_48k_24khz, never_raises_sample_rate). AAC and FLAC keep the source rate, and Opus is left to its native 48 kHz.

When Compression Is Skipped

decide starts with the cheapest facts. A video track belongs to Chapter 19 (Video). More than one audio track gets UnsupportedStreams, because the audio path maps only the first and would lose a commentary or second language. A file carrying R2Dock’s marker is never compressed again. Files under 1 MB (MIN_SIZE, 1,000,000 bytes) or 10 seconds are not worth it, and a file without a readable duration cannot be verified afterwards.

The marker is a tag R2DOCK_COMPRESSED whose value is the preset, such as mp3-32k, read by marker_of from ID3 frames, tags, or comments. MP4 based outputs get no marker, because FFmpeg writes custom MP4 tags only with -movflags use_metadata_tags, which moves title and author into a form many players ignore. For them the bitrate check below prevents a second compression, as aac_m4b_keeps_chapters confirms.

After the ladder runs, two more cheap checks in decide follow. The first never raises the bitrate: a lossy source whose real bitrate is within 3 percent of the target (headers add a little) is AlreadyCompressed (header_overhead_still_counts_as_at_target). The second estimates the output (duration times target bitrate, plus 0.5 percent overhead and the cover art, or 55 percent of PCM for FLAC) and skips with a message such as “Would save only 6%” below the user’s minimum; margin_check shows a 64 kbps book passing at the default and failing at 30 percent.

If ffprobe is available, streams::audio_only_supported also accepts only one audio track plus cover art and a few harmless data tracks such as tmcd and chapter text; anything else gives UnsupportedStreams. All reasons are in the SkipReason enum, shown on each transfer row.

The Sample Test

Real encodes differ from nominal bitrates, especially VBR music. For lossy files longer than SAMPLE_TEST_MIN_SECS (300 seconds), Ffmpeg::sample_saving encodes 30 seconds from the middle (middle_window, starting at (duration - 30) / 2 to avoid unrepresentative intros and credits), deletes the sample, and scales its size by full duration over window length. Passing -ss and -t before -i makes them input options that seek and limit reading, so FFmpeg does not decode up to the middle. The plan records a 23 hour spoken word file where the sample predicted 49.8 percent in 0.4 seconds and the full encode delivered 50.0 percent in 172 seconds (not re-run for this book). The test sample_test_predicts_the_saving expects 40 to 60 percent on a synthetic file.

Building the Encode Command

args::encode_audio maps only the first audio track (-map 0:a:0). Cover art, stored as a video stream with the “attached picture” disposition, is copied with -map 0:v? for containers that hold it (the ffmpeg documentation explains that a trailing ? makes the map optional); Opus and samples get -vn. -map_metadata 0 and -map_chapters 0 copy tags and chapters. FLAC uses -compression_level 8. MP3 gets ID3 version 2.3 and a Xing/LAME header for gapless playback and accurate VBR duration; MP4 gets +faststart so a browser can play an R2 object before it fully downloads.

The plan says “a file whose chapters would be lost is uploaded unchanged unless the user allows it.” The code copies chapters and aac_m4b_keeps_chapters confirms they survive in M4B, but nothing compares chapter counts and no such setting exists. Whether chapters survive in MP3 depends on FFmpeg’s muxer; this book did not verify it.

Verifying the Output

verify_audio in crates/r2dock-media/src/verify.rs re-probes the output with Symphonia and requires it to open, be non-empty, hold the expected codec, and match the source duration within 1 second or 0.5 percent, whichever is larger (432 seconds for a full day, per the tolerance test), so a truncated output is caught. A failure deletes the output and the failure policy of Chapter 20 applies.

pipeline.rs then checks that nothing was dropped: exactly one audio track with the planned channels, confirmed by ffprobe when available. A copy that lost something is deleted and reported as unchanged with TracksNotKept, so the original is always uploaded regardless of the failure policy; a_copy_that_lost_something_uploads_the_original forces this with a lying fake ffprobe. Finally a real saving below the minimum gives ResultSavedTooLittle. Figure 18.1 puts the whole path in order.

Compare Quality

“Compare quality” in Settings (preview::compare in preview.rs) encodes the same 30 second middle window at each preset plus a FLAC reference, played through the media scheme of Chapter 24 (The Custom Media Preview Protocol). Labels come from the encoding actually produced (compare_quality_on_aac_is_labeled_aac).

Working on This Code

In crates/r2dock-media/src, classify.rs holds the speech rule, plan.rs the ladder and skip checks, ffmpeg/args.rs the arguments, and pipeline.rs the sequence from probe to verify. A new settings field in crates/r2dock-core/src/compression.rs needs a serde default so older preferences load.

Run cargo test -p r2dock-media for the decision tables and snapshots, and with FFmpeg installed cargo test -p r2dock-media --test ffmpeg and --test preserve, checking for skip messages. A ladder change should update a table test deliberately and record its measurement in the plan.

Never raise bitrate, sample rate, or channel count above the source. Never reduce channels without proof or permission, and keep the multichannel veto before the speech rule. Never compress a file whose extra tracks would be lost, treat a copy that lost something as unchanged, and never write the marker into MP4. Do not test ladder changes only on sine waves, which encode very differently from speech.
