26 React and Tauri IPC

Chapter 2 (Complete Software Architecture) introduced the split: a React interface in a system webview, a Rust core that owns everything else, and Tauri’s Inter-Process Communication (IPC) layer carrying JSON between them. This chapter goes underneath that picture: typed wrappers, errors as data, generated types, lossless event channels, and an upload that never shows the page a local path. Which commands the webview may call at all is the subject of Chapter 22 (Tauri Security Architecture).

Commands and the Single Wrapper Module

A Tauri command is a Rust function marked #[tauri::command] and called from JavaScript by name with invoke. The Tauri guide to calling Rust sets the contract: arguments travel as a JSON object “with camelCase keys” (so connection_id is sent as connectionId), parameters implement Deserialize, results implement Serialize, and a command returning Err rejects the promise with the serialized error.

R2Dock registers 56 commands, listed in tauri::generate_handler! in src-tauri/src/lib.rs, in the COMMANDS allowlist in src-tauri/build.rs, and as allow-<name> permissions in src-tauri/capabilities/main.json. Architecture decision record (ADR) 0003 accepts this duplication: “Command names and arguments are still listed by hand in commands.ts, build.rs, and the capability file.” A new command must appear in all four places, or it fails to compile, is refused at runtime, or is unreachable.

Components never call invoke themselves. The header of src/ipc/commands.ts states the rule: “The frontend calls Rust only through this module.” Each command has a one-line wrapper that fixes its name, argument names, and result type, for example bucketList = (connectionId) => invoke<BucketEntry[]>("bucket_list", { connectionId }). The type parameter on invoke is a promise to the compiler, not a runtime check; the safety comes from the result type being generated from the Rust struct the command returns.

StrictMode, which src/main.tsx wraps around <App />, shapes how the wrappers that subscribe are used. The React StrictMode documentation says that in development React runs an extra setup and cleanup cycle for every Effect. Any Effect that opens a subscription to Rust must clean it up or guard against running twice; R2Dock does both, as shown later.

Errors as Data

Commands return CmdResult<T>, an alias for Result<T, AppError> in src-tauri/src/commands/mod.rs. AppError lives in r2dock-core and is built to cross the boundary.

Source: crates/r2dock-core/src/app_error.rs, lines 37 to 53

#[derive(Debug, Clone, PartialEq, Eq, Serialize, TS)]
#[serde(rename_all = "camelCase")]
#[ts(export)]
pub struct AppError {
    pub code: ErrorCode,
    /// One plain sentence suitable for the UI.
    pub message: String,
    /// Optional technical detail (error code, request id). Never a secret.
    pub detail: Option<String>,
    pub retryable: bool,
    /// Bucket names, object keys, or file names that appear in `message` or
    /// `detail`. Never sent to the frontend; the activity log uses them to
    /// hide those names when the user has not allowed names in the log.
    #[serde(skip)]
    #[ts(skip)]
    pub names: Vec<String>,
}

The paired #[serde(skip)] and #[ts(skip)] on names keep that field off the wire and out of the generated type, so the frontend’s view of an error is exactly what it receives. Because a JavaScript rejection can be anything, commands.ts adds the runtime guard isAppError (an object with code and a string message) and errorMessage, which returns the AppError message, an Error’s message, or “Something went wrong. Try again.” ErrorView in src/features/connections/ErrorStates.tsx switches on code, never on message text, so Rust can reword messages freely. (src/lib/errors.ts also defines isCredentialError and isOfflineError, which nothing imports at this commit.)

Generated Types with ts-rs

PLAN.md section 7.1 left the choice between specta and ts-rs marked [Verify]. ADR 0003 records the answer for data transfer objects (DTOs), checked by continuous integration (CI): “Rust DTOs derive ts_rs::TS; cargo test writes TypeScript definitions to src/ipc/bindings/. CI fails if the generated files differ from the committed ones.” The ts-rs documentation explains the surprising part: #[ts(export)] “generates a test which writes the bindings for it to disk”. The output directory comes from TS_RS_EXPORT_DIR, set to src/ipc/bindings in .cargo/config.toml. The workspace enables the serde-compat feature, so ts-rs honors attributes such as rename_all and tag, and uuid-impl, so Uuid becomes string. ADR 0003 also exports 64-bit sizes as number “(values stay below 2^53)”, via #[ts(type = "number")] in src-tauri/src/dto.rs; that is about 9 petabytes, safe for sizes but an assumption to remember for any new 64-bit field.

Figure 26.1 shows the pipeline from a Rust struct to a type-checked call.

The CI step turns convenience into a guarantee: after cargo test --workspace regenerates every binding, the Linux job in .github/workflows/ci.yml runs git diff --exit-code -- src/ipc/bindings, so a DTO change without regenerated TypeScript fails the build. The folder holds 74 generated files at the audited commit. A tagged enum shows how faithfully shapes carry over.

Source: crates/r2dock-transfer/src/model.rs, lines 323 to 351

#[derive(Debug, Clone, PartialEq, Serialize, TS)]
#[serde(
    rename_all = "camelCase",
    rename_all_fields = "camelCase",
    tag = "type"
)]
#[ts(export)]
pub enum TransferEvent {
    /// Full state, sent when the frontend subscribes.
    Snapshot {
        jobs: Vec<JobSnapshot>,
    },
    Added {
        jobs: Vec<JobSnapshot>,
    },
    Updated {
        job: Box<JobSnapshot>,
    },
    Progress {
        updates: Vec<ProgressUpdate>,
    },
    Removed {
        ids: Vec<JobId>,
    },
    /// A connection's credentials were rejected; its jobs stopped.
    AuthFailed {
        connection_id: Uuid,
    },
}

The generated src/ipc/bindings/TransferEvent.ts is one long line; re-wrapped, it reads:

Source: src/ipc/bindings/TransferEvent.ts, line 5

export type TransferEvent =
  { "type": "snapshot", jobs: Array<JobSnapshot>, }
  | { "type": "added", jobs: Array<JobSnapshot>, }
  | { "type": "updated", job: JobSnapshot, }
  | { "type": "progress", updates: Array<ProgressUpdate>, }
  | { "type": "removed", ids: Array<string>, }
  | { "type": "authFailed", connectionId: string, };

tag = "type" became a discriminated union, Box vanished because boxing is invisible in JSON, and connection_id became connectionId through rename_all_fields. A switch (event.type) in the reducer of Chapter 28 (UI Performance and Large Queues) narrows each branch, so a renamed Rust variant becomes a TypeScript compile error instead of a silent undefined.

The gap ts-rs leaves is the command list itself: it generates value shapes, not command names or argument names, so a misspelled prefix in invoke("object_list", ...) still compiles. The ADR accepts this and keeps all such calls in one reviewed file. Tools such as tauri-specta can generate typed command functions, but the code does not use them, and the project records no reason beyond the ADR’s decision.

A Request Through Both Layers

useExplorerData in src/features/browser/useExplorerData.ts runs a TanStack Query infinite query keyed by qk.objects(connectionId, bucket, prefix) whose page function calls objectList(connectionId, bucket, prefix, pageParam), starting with null. Tauri deserializes the arguments into object_list in src-tauri/src/commands/browse.rs. Deserialization is the first validation: connection_id is typed Uuid, so a malformed id is rejected before the body runs, and null becomes Option::None. The command then validates bucket and prefix with bucket_arg and prefix_arg, opens an activity log record, and calls with_client, which resolves the connection to an R2Client whose credentials never leave Rust and records online status from the result. R2Client::list_page sends ListObjectsV2 with delimiter / and 1,000 keys per page (Chapter 8, The S3-Compatible Protocol).

The returned ListPage has prefix, folders, objects, and nextToken. getNextPageParam returns last.nextToken ?? undefined, and the TanStack Query infinite query guide documents that undefined means no further page. Rust keeps no per-view state: the frontend owns accumulated pages, sorting, filtering, and merging in-progress uploads (Chapter 27, Frontend State Management).

Channels: Streaming Transfer Events

A transfer queue may run for hours and produce thousands of changes; a promise resolves once, and polling wastes work. The guide to calling the frontend from Rust says “The event system is not designed for low latency or high throughput situations,” while “Channels are designed to be fast and deliver ordered data.” A channel is created in JavaScript and passed as a command argument; the @tauri-apps/api/core reference warns that messages arriving before onmessage is set are not replayed. R2Dock’s wrapper therefore sets the handler first.

Source: src/ipc/commands.ts, lines 130 to 134

export const transferSubscribe = (onEvent: (e: TransferEvent) => void) => {
  const channel = new Channel<TransferEvent>();
  channel.onmessage = onEvent;
  return invoke<void>("transfer_subscribe", { onEvent: channel });
};

On the Rust side, transfer_subscribe in src-tauri/src/commands/transfers.rs receives a Channel<TransferEvent>, installs a sink closure in the engine, and returns at once; the channel lives on inside the sink. Before forwarding each event, the sink records interesting Updated states in the activity log (record_job), lets the connection service learn online status from finished transfers (note_transfer), and counts completions for a background notification, which it spawns onto the runtime with the comment “Never block the event path on window queries.” It ends with let _ = on_event.send(event), ignoring failure because a vanished webview has nobody left to tell.

The engine side solves the classic race between taking a snapshot and subscribing.

Source: crates/r2dock-transfer/src/engine/mod.rs, lines 262 to 270

    /// Set (or replace) the event sink and send a full snapshot.
    pub fn subscribe(&self, sink: EventSink) {
        // Hold the delivery lock so no event can slip between the snapshot
        // and the new sink, or arrive before the snapshot.
        let _order = self.inner.delivery.lock();
        let jobs = self.snapshot();
        sink(TransferEvent::Snapshot { jobs });
        *self.inner.sink.write() = Some(sink);
    }

Every emission goes through Inner::emit, which takes the same delivery lock, so no event can fall into the gap or overtake the snapshot. A reloaded page subscribes again, its sink replaces the old one, and the first message is a fresh Snapshot that the reducer treats as “replace everything”.

Events come at two rates. State changes (Added, Updated, Removed) are emitted immediately. Byte progress is batched by progress_ticker, which every progress_interval (250 milliseconds by default in EngineConfig::new) gathers all active jobs’ counters into one Progress event, skipping unchanged ones. PLAN.md section 12.4 describes “at most every 250 ms per active job”; the code goes further with one combined event per tick for all jobs. Chapter 6 (The Transfer Scheduler) owns the engine side.

On the page, startTransferSubscription in src/features/transfers/subscription.ts subscribes once for the app’s lifetime from an Effect in src/app/App.tsx. A module-level started flag absorbs StrictMode’s second run; if the invoke fails the flag resets and a toast says “Transfer updates are not available.” There is no unsubscribe. The same idiom, a promise for the final result and a channel for progress, appears in deleteExecute and moveExecute (a Channel<OpProgress> with done and total) and compressionInstall (Channel<InstallProgress>). Copy it for any new long-running command.

An Upload from Click to Progress Bar

The upload path combines every mechanism and turns a security rule into an API shape. Figure 26.2 shows the sequence.

pickAndUpload in src/features/browser/upload.ts calls pick_upload_files. Rust opens the native dialog, registers the chosen paths in state.selections, and returns a Selection: an opaque id, a count, and up to three display names. The paths stay in Rust. PLAN.md section 7.1 gives the reason: this “prevents a compromised webview from uploading ~/.ssh by passing a path string.” No upload command accepts a path at all.

uploadSelection then calls upload_prepare with the selection id and target. Rust looks up the paths, walks folders inside spawn_blocking, computes keys, optionally estimates compression savings, counts existing destination keys, and stores a PreparedUpload under a new plan id. It returns an UploadPlan summary; as the comment on useUploadStore says, “Plans hold no secrets and no local paths.” If needs_review holds (folders, more than 20 files, conflicts, skipped items, a scan that hit its size limit, or a compression estimate), a dialog collects the conflict policy. upload_start then takes the plan with state.uploads.take(&plan_id), making it single use (“This upload expired. Choose the files again.”), turns files into JobSpec::Upload values, calls engine.enqueue, and returns only a u32 job count. Everything after that arrives over the channel opened at startup.

Drag and drop enters the same flow differently. The webview never receives dropped paths: src-tauri/src/dragdrop.rs handles window drag events in Rust, registers dropped paths with the same register_selection, and emits a Tauri event r2dock://drag carrying a DragEvent (enter, over, leave, or drop with a Selection). An event is fine here because drag notifications are few and small. The useDragDrop hook listens with listen and, on drop, calls uploadSelection. Its cleanup handles an asynchronous subscription under StrictMode.

Secrets and the Cost of the Boundary

The only time a secret crosses IPC is the Connect form submit. ConnectionInput in src-tauri/src/dto.rs is the only DTO with a secret field and derives Deserialize but not Serialize, so Rust cannot send it back; in edit mode the form sends secret: null to keep the stored one. ConnectionSummary returns only hints such as accessKeyHint, secretStorage, and hasApiToken. In React the secret lives in ConnectForm’s local useState, never in Zustand or the query cache, and is cleared after a successful save but kept after a failure so the user can retry; ConnectForm.test.tsx pins this down, including that error text never contains the secret. ConnectionInput still derives Debug with the secret as a plain String; nothing formats it today, but a redacting type would make a future leak impossible (Chapter 25, Threat Modeling and Remaining Risks).

Every call costs a JSON encode and decode, cheap at R2Dock’s sizes. File contents never cross IPC; transfers stream inside Rust and previews use the custom scheme of Chapter 24 (The Custom Media Preview Protocol). The failure modes are bounded. Arguments that do not deserialize reject with a non-AppError value, which errorMessage still handles. What the webview receives if a command panics is not shown by the code; the project rule is that command paths must not panic. A failed channel send leaves the engine running until the next snapshot. A command missing from the capability is refused before its handler runs, and a stale binding fails CI.

Working on This Code

To add a command, write a thin handler under src-tauri/src/commands/ (validate with bucket_arg, prefix_arg, or key_arg, call a service, return CmdResult<T>), register it in generate_handler!, add it to COMMANDS in src-tauri/build.rs and its allow- permission to src-tauri/capabilities/main.json with a reason in the pull request, and add a typed wrapper to src/ipc/commands.ts. New shapes go in src-tauri/src/dto.rs (or the owning crate) with Serialize, TS, rename_all = "camelCase", and #[ts(export)]; run cargo test -p r2dock and commit the regenerated bindings, never hand-edited. Long-running work returns its result through the promise and streams progress through a Channel<T> whose onmessage is set before invoke.

The invariants: no command returns a secret or accepts a local path; branch on AppError.code, not message text; 64-bit fields exported as number stay below 2^53. Frontend checks are npm test, npm run typecheck, and npm run lint. Mock IPC by mocking the whole commands module with vi.mock, as subscription.test.ts does.
