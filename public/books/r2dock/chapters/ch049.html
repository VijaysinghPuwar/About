Glossary

A

Active state. A job state that holds a job slot: Preparing, Running, Retrying, or Verifying, as defined by JobState::is_active.

Activity log. R2Dock’s daily CSV file of user actions and transfer outcomes, written by a dedicated thread with a bounded queue so that no caller waits on the disk.

AppError. R2Dock’s serializable error type that crosses the IPC boundary, carrying a code, a message, an optional detail, and a retryable flag.

AppState. The struct of shared services (connections, engine, registries, activity log, compression) that the Tauri application registers at startup and passes to commands.

Arc. An atomically reference-counted shared pointer from the Rust standard library, used to share one value between threads and tasks.

Atomic. An integer or flag updated indivisibly without a lock, with a memory ordering that defines what other threads observe.

B

Backend confirmation token. A single-use, expiring identifier returned by a preview command that names the exact work a later execute command may perform, used for deletes and moves.

Backpressure. A design in which a slow consumer makes its producer slow down, instead of buffering the surplus without limit or dropping it.

Bitrate. The number of bits used per second of media; R2Dock computes a file’s real bitrate as its size minus any cover art, times eight, divided by its duration.

C

Cancellation safety. Whether dropping an unfinished future loses data or a queue position; it matters for every branch of select!.

CancellationToken. A cloneable signal from tokio-util whose cancel wakes every task waiting on it.

Canonical equivalence. Unicode’s notion that different code point sequences, such as a precomposed letter and a base letter plus a combining mark, represent the same text.

Capability (Tauri). A configuration file that grants a set of permissions to named windows; R2Dock’s is src-tauri/capabilities/main.json.

Capability token (media token). An unguessable identifier whose possession alone grants access to one resource, in R2Dock one object for one hour through the preview protocol.

Channel (Tauri). An ordered, fast stream of messages from Rust to a JavaScript Channel object passed as a command argument; R2Dock uses one for transfer events.

Code signing. Attaching a cryptographic signature that identifies the publisher of a program and detects tampering; R2Dock’s releases are not yet signed.

Command (Tauri). A Rust function marked #[tauri::command] that the frontend calls by name with invoke; R2Dock has 56.

Common prefix. A ListObjectsV2 result that rolls up all keys sharing a prefix up to the next delimiter; R2Dock shows each as a folder.

Compaction. Folding a change log into a new snapshot with the next generation and truncating the log; the queue compacts when the log reaches 1 MiB and the snapshot’s size, after a failed snapshot, and at load.

Compressed copy. The verified encode in R2Dock’s work folder that replaces the original in an upload, tracked with a SHA-256 digest and checked before each upload attempt.

Conditional request. A request carrying a precondition, such as If-None-Match or x-amz-copy-source-if-match, that the service evaluates and rejects with 412 if it does not hold.

Conflict policy. The rule for an upload or download whose destination exists: Ask, Skip, Replace, or Keep both.

Connection generation. A counter that increases when a connection’s settings or credentials change, used to discard stale cache entries.

Content Security Policy (CSP). Browser-enforced rules listing which origins may supply scripts, images, styles, and connections to a page.

Content-MD5. A request header carrying the base64 MD5 of the body, which lets the server reject a body corrupted in transit.

Continuation token. An opaque token returned with a truncated ListObjectsV2 page and passed back to fetch the next page.

Copy on write (reducer). Copying the job map or order array at most once per batch of events, only when the batch first needs to write.

Copy, verify, delete. R2Dock’s move sequence: copy the inspected source version, confirm the destination copy and the unchanged source, and only then delete the source.

Core process. The Rust process of a Tauri application, the only component with full operating system access.

Counting semaphore. A counter of permits where acquiring takes one, waiting if none remain, and releasing returns one, so at most N holders exist at once.

Crash consistency. The property that any crash point leaves state from which recovery can reach a correct state.

Credential scope. The date/region/service/aws4_request string that binds a SigV4 signature to one day, region, and service; R2 uses the region auto.

CRF (constant rate factor). The constant-quality setting of x264 and SVT-AV1; a lower value means higher quality and larger files.

Custom domain (R2). A host name in the user’s Cloudflare zone connected to a bucket for public reads.

Custom URI scheme. An application-registered URL scheme, here r2dock-media, whose requests the webview routes to an in-process handler instead of the network.

D

Debounce. Delaying an action until events stop for a set time, such as R2Dock’s 800 millisecond listing refresh after completions.

DeleteObjects quiet mode. A multi-object delete response mode in which only failed keys are reported.

Drop guard. A value whose Drop implementation performs cleanup on every exit path, including early returns and cancellation.

E

Encoder gate. The condition in schedule_compression that starts a new encode only while running encodes, ready copies, and copy bytes stay below their limits.

Engine. The transfer engine in crates/r2dock-transfer: the job table, scheduler, progress ticker, journals, and the tasks that run uploads and downloads.

Enum. A Rust type whose value is one of several variants, each of which may carry data.

ETag. An opaque version identifier for an object; it equals the content MD5 only for single-part uploads without SSE-C.

F

Fault injection. Deliberately causing failures, such as lost responses, slow links, or stuck processes, to test recovery paths.

Finalization record. The finalized field of a download’s resume state (length, modification time, file identity), written synchronously before the partial is moved into place so a restart can recognize the moved file.

Fingerprint. A file’s length plus its modification time in nanoseconds, used to detect that a source file changed.

Folder marker. A zero-byte object whose key ends in /, created so an empty folder appears in listings; R2Dock hides it from its own listing.

Future. A Rust value representing an asynchronous computation that makes progress only when polled.

FuturesUnordered. A collection that polls many futures in one task and yields their results in completion order; each multipart job keeps its parts in one.

G

Generated bindings. The TypeScript files in src/ipc/bindings/, produced from Rust types by ts-rs and checked in CI with git diff --exit-code.

Generation number. A counter stored in the queue snapshot and on each log line; replay skips lines whose generation differs from the snapshot’s.

Ghost row. A temporary explorer row for an upload into the open folder that the listing does not show yet.

Group (transfer group). Jobs created from one folder or multi-file selection that share a GroupInfo and appear as one row; the scheduler balances slots between groups.

H

Head of line blocking. A queue’s first item cannot proceed and items behind it wait, although they could proceed on their own.

I

Idempotent operation. An operation whose repetition has the same effect as performing it once.

If-Match. An HTTP precondition that the target still has a given ETag; R2Dock uses it to pin a resumed download to one object version.

Ignored test. A Rust test marked #[ignore], run only with --ignored or --include-ignored.

Inter-Process Communication (IPC). The message path between the webview running React and the Rust core; in Tauri, JSON-serialized commands, events, and channels.

Interrupted. The state given to every job restored at startup; nothing restarts until the user resumes or discards it.

Invalidation. Marking cached queries stale so mounted ones refetch; resetQueries instead returns them to their initial state.

J

Job. One upload or download of exactly one file, described by a JobSpec and tracked by a JobSnapshot.

Job Object. A Windows mechanism that groups processes so they can be terminated together; R2Dock runs FFmpeg inside one.

Job slot. One of the configured number (default 3) of jobs allowed in an active state at once, computed by counting active jobs rather than held as an object.

JobCtx. The context handed to a running upload or download: client, run control, byte counter, part semaphore, limits, resume state, and hooks.

JobHooks. The trait through which upload and download code reports state, parts, renames, sizes, and checkpoints back to the engine.

Journal entry. One saved job (JournalEntry): its identifier, spec, group, resume state, creation time, and sequence number.

K

Keep both. The conflict policy that uploads or downloads under a numbered new name when the destination exists.

L

Logged journal. R2Dock’s queue persistence: a JSON snapshot (queue.json) plus an append-only JSON-lines change log (queue.log).

Lossless and lossy codec. A lossless codec (FLAC, ALAC) reproduces samples exactly; a lossy codec (MP3, AAC, Opus) discards information to save space and cannot be reversed.

M

Marker tag. The metadata R2DOCK_COMPRESSED=<preset> written into non-MP4 compressed outputs to prevent compressing them again.

Multipart ETag. The MD5 of the concatenated binary part MD5s, followed by a dash and the part count.

Multipart upload. Uploading an object as numbered parts that the service joins on completion; R2Dock uses it at or above the 100 MiB default threshold.

Mutex and RwLock. Locks giving exclusive access, or shared read and exclusive write access, through guards that unlock when dropped.

N

NeedsDecision. The job state for a transfer whose destination exists under the Ask policy, waiting for the user to choose.

NFC and NFD. Unicode normalization forms; NFD fully decomposes characters, NFC decomposes and then recomposes them.

No-clobber persist. Moving a temporary file to a name only if nothing exists there, with tempfile’s persist_noclobber.

Notarization. Apple’s service that scans a Developer ID signed app and issues a ticket so Gatekeeper accepts it.

Notify. A Tokio primitive that wakes a waiting task and stores one permit if nobody is waiting, so repeated notifications coalesce.

O

oneshot and mpsc channel. Tokio channels for a single value, and for many producers sending to one consumer.

O_NOFOLLOW. A Unix open flag that makes opening fail if the final path component is a symbolic link.

Opaque identifier. A random string that stands for data kept in Rust, such as a selection or a plan, so the webview never holds the data itself.

Optimistic update. Writing the expected result into a cache before the server confirms it, with rollback on error.

Opus. An open audio codec (RFC 6716) combining a speech layer and a music layer, from 6 to 510 kbit/s.

OwnedSemaphorePermit. Tokio’s permit returned by acquire_owned on an Arc<Semaphore>; it keeps its own reference to the semaphore and releases the permit when dropped.

Ownership. Rust’s rule that each value has one owner and is dropped when the owner goes out of scope.

P

Page cache. Operating system memory holding recently used file data; writes there survive a process crash but not a power loss.

Part permit. One of the global_parts (default 8) permits of the part_slots semaphore, required to send one multipart part request.

Partial file. The hidden .<name>.<tag>.r2dock-part file a download writes into before it is moved into place.

Path guard. R2Dock’s module, crates/r2dock-core/src/path_guard.rs, that maps untrusted object keys to safe local paths.

Path traversal. Making a program access files outside an intended folder by injecting .. segments or absolute paths.

Path-style addressing. Putting the bucket name in the URL path instead of the host name; R2Dock forces it.

Permission (Tauri). A named privilege that allows or denies specific commands; it takes effect only when a capability references it.

Plain journal. R2Dock’s journal.json, a single JSON snapshot of resumable state rewritten atomically on every save.

Poisoning. The state of a standard library mutex after a thread panicked while holding it; parking_lot locks do not poison.

Presigned URL. An S3 URL with a signature in its query string that grants temporary access without other credentials.

Process group. A Unix mechanism for signaling a process and its children together; R2Dock starts FFmpeg in its own group.

Property-based test. A test that checks a rule against many generated inputs and shrinks a failing input to a minimal case; R2Dock uses proptest.

Public base URL. A per-bucket URL entered by the user from which R2Dock builds public links.

Q

Query key. The array identifying a TanStack Query cache entry; R2Dock uses forms such as ["objects", connectionId, bucket, prefix].

R

r2.dev domain. A Cloudflare-managed public subdomain for a bucket, rate limited and intended for development.

Range request. An HTTP request with a Range header asking for part of a resource, answered with 206 and Content-Range.

Read model. A frontend projection of state owned elsewhere, such as the transfer store rebuilt from a snapshot and patched by events.

Ready copy. A compressed copy whose job is queued for upload or uploading; the encoder gate limits how many exist.

Registry. R2Dock’s expiring map from opaque random identifiers to selections, plans, or pending operations, with a 15 minute lifetime and 256 entries at most.

Request-boundary hook. A callback in a mock server that runs between applying a request and responding, letting a test change state at an exact moment.

Resume state. The ResumeState saved for a job: none, a multipart upload’s ID and finished parts, or a download’s partial file and ETag.

Retry storm. Many clients or jobs retrying at once against a failure that retries cannot fix.

RunControl. The per-run object holding a job’s stop reason (none, pause, cancel) and its cancel and stopping cancellation tokens.

Runtime. The Tokio executor and reactor that poll tasks on worker threads.

S

Secret Service. The freedesktop D-Bus interface for secret storage on Linux, implemented by GNOME Keyring and KWallet.

select!. A Tokio macro that waits on several futures, runs the branch of the first to complete, and drops the others.

Selection. An opaque identifier for local paths the user chose in a native picker or by drag and drop.

Server state. Data whose source of truth is outside the webview, such as R2 listings or Rust settings, cached in the frontend with TanStack Query.

Server-side copy. A copy performed inside the storage service; the client sends a request but no object bytes.

Session-only mode. R2Dock’s fallback when no credential store is available: secrets stay in process memory until the app quits.

SHA256SUMS.txt. A list of SHA-256 digests for release files, proving integrity but not authenticity.

Signature Version 4 (SigV4). The AWS request signing protocol, in which the client signs a canonical form of each request with a key derived from the secret, date, region, and service.

SmartScreen. Windows’ reputation-based warning for downloaded programs.

spawn_blocking. A Tokio function that runs a closure on the blocking thread pool, keeping blocking work off the async workers; it cannot be aborted once started.

Stalled stream protection. An AWS SDK feature that fails a body stream that moves no data for a grace period (60 seconds in R2Dock).

T

Task. A future spawned onto the Tokio runtime and scheduled independently.

Tauri event. A named broadcast with a JSON payload, not meant for high throughput; R2Dock uses one for drag and drop.

Terminal state. Completed, Cancelled, or Skipped, as defined by JobState::is_terminal; Failed is not in that set.

thiserror. A derive macro that generates std::error::Error and Display implementations for error types.

TOCTOU (time of check to time of use). A race in which what a program checked changes before the program acts on it.

Torn write. A write cut short by a crash, leaving an incomplete record at the end of a file.

Trait. A named set of methods that types can implement; R2Dock uses traits as seams between layers.

Trait object. A value of type dyn Trait whose concrete type is chosen at runtime and called through a vtable.

Transfer function (PQ, HLG). The mapping from stored values to brightness; PQ and HLG are the high dynamic range curves.

ts-rs. A Rust crate that generates TypeScript type definitions from Rust types when cargo test runs.

Typed confirmation. A safeguard requiring the user to type a phrase, such as a folder name, before a large or folder delete.

U

Upload ID. The identifier returned by CreateMultipartUpload that ties the parts and the final completion together.

V

Virtualization. Rendering only the visible items of a long list, plus overscan, inside a container sized to the full list.

VMAF. Video Multi-Method Assessment Fusion, a perceptual quality score comparing a distorted video with a reference.

W

Watchdog. A timer that kills FFmpeg after 120 seconds without any output line, reported as RunError::Stalled.

Webview process. The operating system webview (WebView2, WKWebView, or WebKitGTK) that renders the React interface.

Workspace (Cargo). A set of Cargo packages built together with one lockfile and shared settings.

Write-ahead logging (WAL). A database technique in which a change’s log record is made durable before the change is applied.
