2 Complete Software Architecture

This chapter maps R2Dock’s processes, layers, crates, Inter-Process Communication (IPC) paths, and operating system services. Later chapters zoom into each part.

Two Processes and a Trust Boundary

The Tauri process model documentation calls the Rust side the core process, “the only component with full access to the operating system”; the interface runs in a separate webview process (WebView2 on Windows, WKWebView on macOS, WebKitGTK on Linux). It recommends keeping secrets and business logic in the core.

docs/adr/0001-architecture.md puts all R2 traffic, credentials, file access, and transfers in Rust; React only renders and calls allowlisted typed commands. PLAN.md section 7 adds that commands stay thin, services live in crates without a Tauri dependency so they can be tested without a window, and only the secret store adapter and R2 client builder ever see a secret.

The webview renders untrusted strings from a remote bucket. If an attacker ran script there, the damage is limited to a fixed list of 56 commands, none of which returns a secret or accepts an arbitrary local path (Chapter 22, Tauri Security Architecture).

The Layers Inside the Application

Figure 2.1 shows the layers: a React screen calls a typed wrapper, Tauri checks the message against the capability allowlist, a command handler validates it and calls a service, and the service uses the workspace crates, which reach the operating system and network. Events flow back through a channel.

In src/, screens live in src/features/, and all calls into Rust go through src/ipc/commands.ts, whose header says “The frontend calls Rust only through this module” (Chapter 26, React and Tauri IPC).

The gate is configured by three files. src-tauri/tauri.conf.json sets the Content Security Policy (CSP) and disables withGlobalTauri. src-tauri/build.rs passes a COMMANDS array of 56 names to tauri_build::AppManifest::new().commands, and src-tauri/capabilities/main.json grants the main window each generated permission by name, such as allow-object-list. The Tauri capabilities documentation explains why: by default every registered command is callable from every window. A registered command missing from the capability file cannot be called. docs/adr/0003-ipc-types.md notes the cost: command names are listed by hand in commands.ts, build.rs, and the capability file.

The Command Layer and Application State

Handlers live in seven topic modules under src-tauri/src/commands/ and are registered with tauri::generate_handler! in src-tauri/src/lib.rs. The helper most browsing commands use shows the “validate, call a service, map errors” contract.

Source: src-tauri/src/commands/mod.rs, lines 20 to 30

/// Run an R2 call for a connection, tracking its online status.
pub async fn with_client<T, F, Fut>(
    state: &AppState,
    connection: Uuid,
    f: F
) -> CmdResult<T>
where
    F: FnOnce(R2Client) -> Fut,
    Fut: std::future::Future<Output = Result<T, R2Error>>,
{
    let client = state.connections.client(connection).await?;
    let result = f(client).await;
    state.connections.note_result(connection, &result);
    result.map_err(AppError::from)
}

CmdResult<T> is Result<T, AppError>; the generics and ? are explained in Chapter 4 (Rust Concepts Used in R2Dock). Architecturally, the command never builds a client or sees the secret. The connection service reads the secret from the credential store on a blocking thread, builds an AWS software development kit (SDK) client, caches it, and records whether the connection is reachable.

The services live in one struct, AppState, which setup in src-tauri/src/lib.rs builds once and registers with app.manage, so any command can take it as State<'_, AppState>.

Source: src-tauri/src/state.rs, lines 112 to 126

pub struct AppState {
    pub paths: Paths,
    pub settings: RwLock<SettingsFile>,
    pub connections: Arc<ConnectionService>,
    pub engine: Engine,
    pub selections: Registry<Vec<PathBuf>>,
    pub uploads: Registry<PreparedUpload>,
    pub deletes: Registry<PendingDelete>,
    pub moves: Registry<PendingMove>,
    pub media: MediaRegistry,
    pub credential_store_label: String,
    pub activity: Arc<crate::activity::ActivityLog>,
    pub compression: crate::compression::CompressionService,
    pub public_links: crate::public_links::PublicLinks,
}

settings sits behind a read-write lock, connections is the ConnectionService in src-tauri/src/connections.rs, engine comes from r2dock-transfer, and media issues preview tokens. The four Registry fields map opaque random identifiers to values that expire after 15 minutes, implementing a core security rule: local paths never come from the frontend. pick_upload_files opens a native dialog from Rust (src-tauri/src/dialogs.rs), stores the paths in state.selections, and returns a Selection with only an identifier, a count, and up to three display names. Drag and drop works the same way (src-tauri/src/dragdrop.rs), so a compromised webview can refer only to files the user chose. Deletes use the idea in reverse: delete_preview stores a PendingDelete under a token, and delete_execute accepts only that token, refusing expired or unknown ones (Chapter 11, Object Management and Consistency).

The Rust Crates and Their Dependencies

The root Cargo.toml declares seven workspace members: six crates under crates/ and the application crate in src-tauri/. Figure 2.2 shows the internal dependencies as the manifests declare them; a dashed arrow marks a test-only dependency.

r2dock-core holds pure logic (keys, path safety, part planning, settings) and the shared AppError; it depends on no workspace crate and not on Tokio. r2dock-secrets adapts the keyring crate per platform; its module comment warns that every call may block and must be wrapped in spawn_blocking. r2dock-r2 wraps the AWS SDK for S3 plus a read-only Cloudflare REST client, r2dock-media runs probing and FFmpeg, and r2dock-transfer is the engine: queue, scheduler, uploads, downloads, journal, and history.

The application crate, r2dock (library r2dock_lib), depends on all five plus Tauri and its plugins (dialog, notification, clipboard manager, opener, single instance). r2dock-testkit provides an in-process S3-compatible server and a mock Cloudflare API, only under [dev-dependencies] (docs/adr/0005-testing-against-local-s3.md). The graph is a strict layering with no cycles and Tauri only at the top, which is why most logic is tested with cargo test -p r2dock-transfer or cargo test -p r2dock-core without a window.

IPC Path One: Commands

The Tauri IPC concept page describes commands as using “a JSON-RPC like protocol under the hood”. The Calling Rust guide adds that arguments arrive with camelCase keys, that return values and errors must implement serde::Serialize, and that async commands run as separate tasks. Figure 2.3 follows one folder listing.

object_list in src-tauri/src/commands/browse.rs validates bucket and prefix with r2dock-core helpers, calls with_client, and records the activity. R2Client::list_page in crates/r2dock-r2/src/list.rs sends ListObjectsV2 with a / delimiter and rejects a truncated page without a continuation token or with a repeated token, which would otherwise loop forever.

Types on both sides come from one source: Rust types derive ts_rs::TS, and cargo test writes TypeScript definitions into src/ipc/bindings/ (set by TS_RS_EXPORT_DIR in .cargo/config.toml). The Linux continuous integration (CI) job fails if they differ from the committed files. The error type shows what crosses the boundary.

Source: crates/r2dock-core/src/app_error.rs, lines 37 to 53

#[derive(Debug, Clone, PartialEq, Eq, Serialize, TS)]
#[serde(rename_all = "camelCase")]
#[ts(export)]
pub struct AppError {
    pub code: ErrorCode,
    /// One plain sentence suitable for the UI.
    pub message: String,
    /// Optional technical detail (error code, request id). Never a secret.
    pub detail: Option<String>,
    pub retryable: bool,
    /// Bucket names, object keys, or file names that appear in `message` or
    /// `detail`. Never sent to the frontend; the activity log uses them to
    /// hide those names when the user has not allowed names in the log.
    #[serde(skip)]
    #[ts(skip)]
    pub names: Vec<String>,
}

The frontend gets a stable code, a displayable sentence, an optional detail such as an R2 request identifier, and a retryable flag. names is skipped by serde and ts-rs, and the test marked_names_never_cross_ipc asserts it is absent from the serialized form.

IPC Path Two: Channels and Events

For the stream of transfer updates, the Calling Rust guide recommends channels for ordered, high-throughput streaming, since event listeners can see events out of order. The transferSubscribe wrapper in src/ipc/commands.ts creates a Channel<TransferEvent>, sets its onmessage handler, and passes it to transfer_subscribe as the onEvent argument. Figure 2.4 shows the rest.

transfer_subscribe passes the channel to Engine::subscribe, which sends a full Snapshot first under a delivery lock, so no event can arrive before it or slip between snapshot and subscription. Then come Added, Updated, Removed, Progress, and AuthFailed events. A ticker batches progress for all jobs at most every 250 milliseconds (the default progress_interval in EngineConfig), and src/features/transfers/subscription.ts batches again for 50 milliseconds. Bulk deletes, moves, and the FFmpeg download also take a channel; the drag and drop bridge uses a plain event, r2dock://drag.

IPC Path Three: The Media Protocol

A presigned R2 URL in the webview would be a credential-equivalent link. Instead, run registers a URI scheme, r2dock-media: media_token maps an opaque token to a bucket and key, and the handler in src-tauri/src/media.rs fetches with range support, size caps, and two static semaphores. The CSP allows this scheme for images and media and nothing remote (Chapter 24, The Custom Media Preview Protocol).

Operating System Services and Lifecycle

At startup setup writes, reads, and deletes a probe credential; on failure the app uses session-only memory storage, never a plaintext file (docs/adr/0002-credential-store.md). Dialogs, notifications, clipboard, and link opening go through plugins called from Rust, and open_external refuses anything but https:// URLs. Downloads always pass through the path guard (Chapter 23, Filesystem Security). FFmpeg runs in its own process group or Windows Job Object (Chapter 17). In the background, the engine runs a scheduler task and a progress ticker, its two journals each run a writer task, and the activity log runs an operating system thread named r2dock-activity (Chapter 5, Tokio and Asynchronous Execution).

run installs the plugins, protocol, and command list, exiting with status 1 instead of panicking if that fails. setup loads settings and connections, probes the credential store, starts the engine and activity log, starts a background sweep of compressed copies left by a crash (Chapter 15), and registers AppState. On RunEvent::Exit, engine.flush() writes resumable state and the queue to disk, and the activity log shuts down within two seconds (Chapter 14, Journals and Persistent Queues).

Working on This Code

To add a command, write the handler under src-tauri/src/commands/, register it in tauri::generate_handler! in src-tauri/src/lib.rs, add its name to COMMANDS in src-tauri/build.rs, add allow-<name> to src-tauri/capabilities/main.json, and add a wrapper in src/ipc/commands.ts. Forgetting one list shows up as a runtime permission error, not a compile error. A new data shape derives TS with #[ts(export)]; run cargo test --workspace and commit the generated binding, because CI compares it.

Keep handlers thin and put logic in a workspace crate. No command may return a secret or accept a local path string, destructive bulk operations need a backend token from a preview call, and remote content is never rendered as HTML. Run cargo test -p r2dock (connection and registry tests), cargo test -p r2dock-core, and npm test.
